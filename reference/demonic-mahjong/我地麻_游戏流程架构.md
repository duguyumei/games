# 我地麻 游戏流程架构分析

> 数据来源：`work/` 下 Il2CppDumper 产物（`dump.cs` 128 万行类结构 + `stringliteral.json` 中文串）。
> 本文不依赖旧分析文档，全部结论直接取自 dump 证据；类名/字段名照抄代码，推断处标注。
> 商业闭源游戏，零代码零资产入库，仅设计笔记。

## 0. 全局流程总览

```
主菜单/大厅（角色、天赋、收藏、代币商店、工作台……）
   │  选难度(难度=DifficultyPayload)、选角色队伍(teamList)、选遗物(_preRelicList)
   ▼
肉鸽地图（关 Level → 小节 Section → 层 Layer，节点有向路径）
   │  节点类型 NodeType：SmallMonster/SmallBoss/BigBoss/FinalBoss/
   │                    Regular(常规战斗)/Event(事件)/Blank(空)/Posthouse(驿站)/None
   ▼
战斗节点 → 对弈初始化（见 §3）→ 麻将对弈（回合循环，见 §4）
   │  PlayerPipeline.RoundEndState：None/Draw/PlayerWin/AIWin
   ▼
结算 → 奖励（BattleRewardsRecord）→ 回地图 → 下一节点 → …… → FinalBoss → 局终
```

驱动这一层的核心类：

| 类 | 职责 | 证据 |
|---|---|---|
| `MapDataManager` | 关/节/层指针、`RandomSeed`、`HasUncompletedGame`、`LevelHistoryData` 走过路径史 | dump 147358 |
| `MapGeneratorBase` | 生成节点路径、修正节点类型、限制事件节点数量（字符串"#地图生成器# …… 修正路径中的事件节点的数量 要求不大于 {0}"） | 字符串 |
| `MapNodeCtrl` | 节点点击/移动演出（ToNextNodeEffect 等） | dump 21062 |
| `GameManager` | 全局调度，持 `PlayMaJiangData`（对弈快照）与 `InfoInMaJiangGame`（中断锚） | dump 160570 |

## 1. 存档体系

### 1.1 文件布局

| 文件 | 内容 | 证据 |
|---|---|---|
| `settings.json` | 设置档 `GameSaver`：音量/语言/帧率/分辨率/自动理牌/商店快买/听牌自动卖祭品等 | dump 161628，字段全 `[JsonProperty]` |
| `Game.json` | 账号级数据（`AccountGameData`、公告、`CharacterIndependent`） | dump 162483 |
| `Slot{0..2}.json` | **3 个存档槽**，每槽一个 `Saver` 主档 | `GameManager.SaverSlotInfo.HelperGetSlotSavePath/FileName` |

### 1.2 主档 `Saver`（MaJiang.GM，`RuntimeVersion = 9`）

一个类装完整局进度，字段按职责分组（`[JsonProperty]` 逐一命名）：

**肉鸽进行时（地图状态机）**
`MapData`、`_mapHasUncompletedGame`、`_mapCurGameRandomSeed`、`_mapCurLevelNo/_mapCurSectionNo/_mapCurLayerNo`、`_mapHistoryPath`、`curEnterNodeIdStack`（节点栈）、`_mapCurBattleLevel/_mapCurBattleNode/_mapIsFinalBattle/FinalBattleNodeData`、事件池与节点池快照（`_mapCurRandomEventPool/_mapCurNormalNodePool/_mapDlcCh3EventPoolMerged`）、战斗 AI 黑名单、灵俑/遗物/祭品权重偏移（`_mapLingYongWeightOffset/_mapYiWuWeightOffset/_mapJiPinWeightOffset`）。

**商店状态**：`_mapShopRefreshPrice/_mapShopRefreshIncrementalPrice/_mapCurRefreshCount/_mapShopBuyCount`——刷新涨价进度跨节点存档。

**对弈中断锚（唯一与战斗相关的存档）**：`GameManager.InfoInMaJiangGame { levelId, roundEndState, character_AddedBonus, isSkipBattle }`——**只记打到哪个关、回合终态、待发奖励，不记牌局**。

**局内资源**：`_hp/_hpMax/_accHpLost/_difficultyHpLost`、`_soul/_soulMax/_soulRestore`、`_coin`＋四个乘区（`_outGameCoinsMulti/_inGameCoinsMulti/_spendCoinsMulti/_shopPriceMulti`）。

**槽位**：`_offeringSlot`（祭品槽）、`_xiaoChouSlot`（灵俑槽）、`_xiaoChouRepositorySlot`（灵俑仓库槽）＋槽满待删记录。

**收藏（跨局永久）**：`_hadXiaoChouList`（已有灵俑）、`_hadRelicList`、`_hadOfferingList`、`_characterCollectionDataList`、`_unlockedRelicList/_currentUnlockedRelicList`、封禁表（`_banLingYong/_banNames/_selectBanLingYongList`）。

**队伍/角色**：`teamList: List<CharacterSaveData>`、`_lastUsedCharacterID`、`_preRelicList`（出门携带遗物）。

**宝牌工作台**：`_workbenchPaiMianBindList: List<PaiMianBindSaveData>`——每牌种一条 `{ PaiMian, DeltaBaseScore, BaoId, LingId }`，见 §2.3。

**麻将偏好与基础数值**：`_playerBaseScore`、`_huPaiSlotsCount`、`_swapPaiRoundTotal/_swapPaiTurnTotal/_initSwapPaiTotal`（换牌配额三件套）、`_selectedFans/_fanZhongToCount/_commonlyUsedFanZhong`（番种选择与使用统计）、`_isAudioSort/_isHuaSeSort`（理牌开关）。

**天赋/难度/杂项**：`_talentSaveDataList`、`_difficultySaveDataList/_curDifficulty/_lastSelectedDifficulty`、当铺（`PawnshopRelicSaveDatas`）、珍珠奶茶（`_bubbleTeaBought`）、`_isSeedMode`（种子模式）、十几条新手引导旗标（`xxxGuide`）。

**统计与成就**：`_statisticsMaxTotalScore/_statisticsMaxSingleScore`（Decimal）、`_maxSumFan`、`_statisticsJiFenCount/_statisticsCleanseCount/_statisticsHaoYunCount`、`_achievementSaveDataList/_characterKillSaveDataList/_fanAchievementSaveData`。

**时间戳**：`_lastSaveTimestamp`＋DateTime 缓存（防抖节流用）。

### 1.3 存档机制要点

- **坏档三防线**：主档损坏→读备份档（"主存档损坏，尝试使用备份存档"）；反序列化失败→**不自动新建覆盖**（"暂不自动新建替换存档"）；版本号解析失败同理。版本迁移单独一条失败路径（"版本迁移反序列化失败"），`RuntimeVersion=9` 说明经历 9 轮结构演进。
- **队列＋防抖＋超时强存**：`GameSaverUtil` 有 `_debouncingCount`、存档队列（"存在队列中的存档({0})，再次存档"）、"保存存档等待超时，强制进行本次存档操作"。
- **Steam 云**：开关存设置档（`SteamCloudToggle2`），云/本地存档合并确认走弹窗（"用户确认/取消刷新Steam云绑定"）。
- 局外代币商店等小额状态走独立 `SimpleDataInt` 类（`GvTokenShopBought/GvTokenShopBuyCount`），不塞主档。

### 1.4 全局调参表 `GameConfig`（ScriptableObject）

数值全集中在此：`hp/hpMax`、`soul/soulMax/soulRestore(+Param)`、`shopRefreshPrice/IncrementalPrice`、`swapPaiRoundTotal/swapPaiTurnTotal/initSwapPaiTotal`、`huPaiSlotsCount(+SoftLimit/HardLimit)`、`sellMultiplier/buyBackMultiplier`、`baseScore/coin`、`lingYongSlotNum/NumLimit/RepositorySlotNum/NumLimit`、`offeringSlotNum/NumLimit`、`discardContainerLength`（打出区长度上限）。

## 2. 玩家存什么 vs 战斗存什么

### 2.1 分层原则

| 层 | 载体 | 寿命 |
|---|---|---|
| 局外玩家态 | `Saver`（§1.2） | 永久（Slot 文件） |
| 进场快照 | `GameManager.PlayMaJiangData` | 一场对弈 |
| 局内现场 | `PlayerPipeline` / `AIBase` 及其容器 | 一场对弈（内存） |
| 对弈中断锚 | `GameManager.InfoInMaJiangGame` | 回地图前 |

**牌局不落盘**：Saver 全文没有手牌/牌墙/打出区字段——对弈中途退出，重进即回到该战斗节点重开（`_mapHasUncompletedGame` 标记"有未完成局"）。这是激进但大幅简化存档的决定。

### 2.2 进场快照 `GameManager.PlayMaJiangData`

```
Level(id, levelType, bossBaseScore, bossIndependent)   ← 关卡配置
AIBase                                                 ← 对手 prefab（§3.2）
targetScore(Decimal) / randomSeed / DifficultyPayload
XiaoChouSaveData + CurrentXiaoChouPayloads             ← 玩家灵俑（数据+永久成长）
FakeXiaoChouSaveData + CurrentFakeXiaoChouPayloads     ← 敌方假灵俑（=boss技能）
Relics / OfferingSaveData / CharacterPayloads + CurrentCharacterSaveData
RandomLingYongIndex ×4                                 ← 敌方随机技能池已摇索引
Merge*List                                             ← 灵俑/遗物/祭品/宝牌/角色/成就合并池
HideFanZhongIdList                                     ← 本关禁用番种
```

即：**对弈=关卡配置 + 敌人 prefab + 种子 + 玩家构筑快照**，全部值拷贝进场，局内修改不回写（除宝牌绑定，见下）。

### 2.3 唯一的"局内→局外"回写：宝牌工作台

`PlayerPaiMianBind`（dump 85700+）维护 `Dictionary<PaiMian,(宝牌,牌灵)>`＋三层分数账（`ForeverScore/TempScore/inRoundScoreDelta`）＋永久/临时绑定记录，`SaveBaoLingBindAndScore()` 把局内新绑定即时写回 `Saver._workbenchPaiMianBindList`。对弈中获得的宝牌因此跨局保值。

## 3. 一场对弈怎么初始化

### 3.1 敌人是什么：`AIBase` prefab（配置式，零代码）

| 字段组 | 内容 |
|---|---|
| 身份 | `characterID`（`CharacterID` 名册约 40 位：贪吃/贪财/不让碰僵尸、自闭/怨念/凶恶女鬼、牛头、马面、牛头马面、黑/白/黑白无常、谛听、孟婆、十殿阎罗（秦广王/阎罗王/泰山王/都市王…）、察查/罚恶/赏善/阴律司、地藏王菩萨(+2)、鬼新娘四姐妹（魖傀魇魅）、日游/夜游神、罗刹、曼荼罗/龙蜒草/荼蘼/水晶兰/彼岸花、+4 个新手版） |
| 数值 | `targetScore`（击败线）、`baseScore`、`independent`（独立倍率）、`initSlotCount`（和牌槽数）、`SwapPaiLeftCount`（换牌配额） |
| AI | `greedyConfig: GreedyConfig`（见 §3.3） |
| 技能 | `_skillPayloads: XiaoChouPaiPayload[]`——**技能就是灵俑**；`randomXiaoChouPool ×4` 随机技能池（`PlayMaJiangData.RandomLingYongIndex×4` 决定本场抽中哪个） |
| 牌库 | `_initPaiMianPool: SaintsArray<PaiMianPayload>[]`——按牌种数组显式配置敌方牌库 |
| 宝牌 | 敌方也有 `_paiMianPayloadToBaoPaiPrefab/_paiLingPrefab/_deltaScore`——**敌人宝牌绑定与玩家同构** |

### 3.2 进场序列（字符串证据逐步对应）

1. 创建对手：`"#AI# 创建Boss "`。
2. 灵俑实例化：`PlayerXiaoChouPaiContainer.Init` 按 payload 的 `prefabReference` 逐个 Addressables 实例化（"#AI# 创建灵俑 {0}/{1}"），随后 `OnXiaoChouInitApply`（"初始化完成"）跑初始化生效类效果；`"#玩家# OnMaJiangRoundStart，添加临时灵俑将不记录记分"`——**临时灵俑与正式灵俑分账**。
3. 宝牌绑定：`DoBaoLingBindAndEffect` 按 `PlayerPaiMianBind` 给手牌挂宝牌/牌灵（"#Pipeline# 新增玩家宝牌绑定 {0}: {1}"）。
4. 初始抓牌＋宝牌生效：`"#AI# 初始抓牌完成，宝牌牌灵初始附加完成"` → `"开始生效各个宝牌牌灵"`（`IOnBaoLingAttach`）。
5. 遗物/角色技能/祭品容器 Init（`OnRelicInitApply`）。
6. 首次换牌窗口（祭品 `UsageTiming=FirstSwap` 在此可用）。

### 3.3 敌人 AI：`GreedyConfig` 纯权重，无搜索

一张 ScriptableObject 权重表：搭子权重（`diff1/diff2Weight`＝邻差权重，`same2/same3/same4Weight`＝对/刻/杠）、花色权重（万/筒/索/风/三元各一）、**每张牌单独权重**（`_1W.._9W/dongW/nanW/xiW/beiW/zhongW/faW/baiW` 共 34 个）、行为权重（`AIChiW/AIPengW/AIMingGangW/AIAnGangW`）、听牌节奏（`needDelayTing + delayMin/delayMax`）、脚本化例外（`jiaGang`、`onlyOnePaiCanTing(+Num)`、`onlyOnePaiCantChiPengGang`、`forceTingAfterSwap`、`aiswapType/aiHuType` 枚举模式）。日志显示 AI 用权重组合做换牌决策（"#AI# StartSwapWeight 组合/权重耗时/候选数"，有 Job 并行加速）。

## 4. 对弈局内：`PlayerPipeline` 是回合状态机＋事件派发中枢

### 4.1 容器清单（战斗存哪些＝这些容器的现场态）

玩家侧（`PlayerPipeline : BasePipeline`）：

| 容器 | 内容 |
|---|---|
| `PlayerHandPaiMianContainer` | 手牌 |
| `PlayerSwapPaiMianContainer` + `PlayerSwapPaiLeftCount` | 换牌区＋换牌配额 |
| `DiscardContainer`（Player/AI 各一） | 打出区（计分区，长度上限 `GameConfig.discardContainerLength`） |
| `XianShiContainer`（明牌显示容器） | 副露：`PaiXingType = Ke/Shun/MingGang/AnGang` |
| `HuPaiSlots` | 和牌槽（`Length=4` 常量，`GetLeftCount/GetTotalCount`，`DynamicChangeSlotsCountDelta` 可加减） |
| `PlayerXiaoChouPaiContainer` | 灵俑（`SlotCount/EmptySlotCount`） |
| `OfferingContainer` | 祭品 |
| `PlayerRelicContainer` | 遗物 |
| `CharacterSkillContainer` | 角色技能 |
| `PlayerSoul` / `PlayerHp` | 魂力（技能资源）/ 血量 |
| `BuffList` | 尸毒、蓄力、好运/厄运、独立倍率临时袋 |
| `PlayerPaiMianBind` | 宝牌/牌灵绑定（§2.3） |

对侧 `AIManager + AIBase` 同构一套（AI 有自己的灵俑=假灵俑、打出区、和牌槽、宝牌绑定）。**敌我在协议层完全同构，差异只在配置。**

### 4.2 回合流（方法名即状态机）

```
OnMaJiangRoundStart（回合开始）
  → OnBeforeFetchStart / OnFetchHand（抓牌，含排序 OnFetchHandSort）
  → OnBeforeSwapStart / OnSwapStart（换牌：手牌↔换牌区，受配额）
  → OnPlaying / OnSliding（打出→滑入打出区，打出区组牌型）
  → OnBeforeChiPengMingGang / OnRunChiPengMingGang / OnOneChiPengMingGang（对方牌的吃碰杠窗口）
  → OnAnGang / OnJiaGang / OnOtherSideJiaGang
  → OnDiscard / OnPaiDiscardSetChanged
  → OnTing / OnOtherSideTing / OnProcessTingResult（听牌，含 HuResult 拆分手牌）
  → OnAboutToHuMySide/OtherSide → OnHu（和牌，UniTask 异步演出）
  → OnJiFen / GetJiFenPreview（计分/预览）
  → OnMaJiangRoundEnd → RoundEndState{None,Draw,PlayerWin,AIWin}
```

### 4.3 计分模型（支撑全系统的经济）

- **打出区组扑克牌型**：自动计分器 `AutoJiFen` 识别 同花顺/同花/五连/四连/四条/五条/同花四连/同花四条/同花五条/葫芦/同花葫芦/两对/两条/三条（字符串全部列出，且有"高番数优先/上次手动计分优先"两套择优策略）——**弃牌即出牌，打出区是计分板**。
- **番种（FanZhong）**：传统麻将役（天和/地和/杠上开花/海底捞月/不求人/全求人/明杠系列/古役：百万石·真百万石·神仙索·花天月地·连开花……），`FanZhongPayload` 数据化，可被灵俑新增（"#灵俑# 为 {0}/{1} 添加番种 {2}"）。
- **和牌槽限次**：和牌是可重复的大分动作但烧槽（`HuPaiSlots`），灵俑可 `PreventDefaultHuPaiSlotReduce` 豁免（纯字牌计分不烧槽即此通道）。
- **三乘区**：底分（BaseScore）×番（Fan）×独立倍率（Independent），全程 `Decimal` 精确结算＋`randomSeed` 全程种子。

## 5. 灵俑（小丑牌）怎么生效

### 5.1 数据：`XiaoChouPaiPayload`（ScriptableObject，`XiaoChou` 枚举 524 项）

- **条件族**（引擎筛"这张牌/这次事件满不满足"）：`huaSe/number/numberType/isZi/isFeng/jian/count/count2/pattern/fanZhong(+List)/paiXingType(Ke/Shun/MingGang/AnGang)/compareType/requiredCount/RoundArr/UsedLimit/isExceptBaoPai/isRandomNumber`。
- **效果族**（四资源通道＋衍生）：`addBaseScore(+2)/addBaseMagnification(+2)/baseMultiIndependent/accMultiIndependent/addFan/addCoin(+1)/addSoul/addHp/addHpMax/addSwap/huPaiSlotsCount/percent(+Limit)/multiple/paiMianScore/decline/addChou`。
- **表现**：`prefabReference/modelReference/iconReference`（一卡一个 prefab＋3D 模型）、`dynamicDescriptionTerms` 动态卡面文本。
- **杂项**：`rarity`（Rarity：Normal/Rare/Epic/Legendary/Artifact/Cursed/Mysterious）、`skillLevel`、`isPlayerSkill`、`relicIds`、`gameEvent`、`offeringInfo`、boss 专用（`zhuFuGangCount/bossJiFenPaiKu/zhuFuPlayingCount/lianHuaPlayingCount(2)`）。

### 5.2 实现：一卡一类一文件

461 个 `: XiaoChouPaiDisplay` 子类，每个灵俑一个类＋一个 prefab，类里只实现自己关心的 `IOn*` 接口方法。例（dump 115322 紧邻容器定义）：

```csharp
public class PlayingCountPatternAddScoreDisplay : XiaoChouPaiDisplay {
    public void OnPlaying(OnPlayingOrSlidingInput input, OnPlayingOrSlidingOutput output) { }
}
```

### 5.3 派发：管线迭代＋Input/Output DTO

`PlayerPipeline` 在每个时点遍历灵俑容器，对每个 display 调接口；参数走 `MaJiang.PlayMaJiang.InOut` 命名空间（**125 个类**）的 `On*Input / On*Output` DTO——Input 只读现场，Output 是可变结果袋由管线回收合并。例：`OnJiFenOutput { DeltaTotalScore, AccIndependent, AddCoin, AddHuSlotCount, PreventDefaultHuPaiSlotReduce, NeedApplyBaoLingDisplays, TempIndependentPayloads, DelayAnimations }`——一次计分里所有灵俑的效果、宝牌刷新指令、演出动画排队全从 Output 袋子里出来。

事件接口约 90 个 `IOn*`（我方/对方成对）：摸牌（Fetch 前后/最后一张/换牌区）、换牌（SwapStart 前后/对方）、打出（Playing/Sliding/Discard/打出区集合变化）、吃碰杠（Before/Run/One/对方/AnGang/JiaGang）、听牌（Ting/对方/结果处理/演出结束）、和牌（Before/AboutTo/OnHu/Finished/统计板）、计分（JiFen/Preview/Finished/对方）、回合（Start/End/Init）、经济（AddCoin/SpendCoin/GetRelic/LoseRelic/Bought）、祭品（Using/CancelUse/Remove）、灵俑自身（XiaoChouChanged/InitApply/LoseAnyXiaoChou）、系统（UseSkill/BuffValueChanged/EYun 厄运/HaoYun 好运/ZhongYun 中运）。

### 5.4 三条复用线（内容协议统一的关键）

1. **boss 技能＝假灵俑**：`FakeXiaoChouSaveData/CurrentFakeXiaoChouPayloads` + 102 个 `: XiaoChouPaiFakeDisplay` 子类——敌方技能与玩家灵俑同一套接口/DTO，"结算灵俑"驱动宝牌激活（"#宝灵# 结算灵俑 激活 绿宝牌"）。
2. **角色技能＝灵俑**：`CharacterSkillContainer`，payload 带 `isPlayerSkill`。
3. **遗物/祭品同协议**：遗物挂 `IOnGetRelic/IOnLoseRelic`；祭品（OfferingPayload）字段即效果声明（`UsageTiming ∈ {吃碰阶段, 首次换牌, 换牌, 吃碰+换牌}`、`useType/handSelectType`、可直接内嵌 `baoPaiPayload/paiLingPayload`＝"祭品就是一张宝牌"）。

### 5.5 成长与孵化

- **永久成长**：`XiaoChouSaveData { id, roundCount, permanentAddFan, permanentAddBaseScore, accPermanentMultiIndependent, addUpTimes×4, mark }`——灵俑随对局次数累积永久数值（进场时注入 PlayMaJiangData）。
- **孵化**：`CanHatchAttribute/ReviveAttribute` 标记可孵化/可复活的灵俑；"灵俑蛋中蛋"、临时灵俑（`AddTempXiaoChou`，不记录分）、假灵俑给对方（"给对方添加假灵俑"）。

## 6. 商店与道具

- **地图商店节点**：`ShopPanel`（货架 goodsRoot＋详情 DetailContainer＋刷新 RefreshButton＋购买 ButtonWithPrice＋已购置灰）。商品统一 `IItemInfo` 接口——**灵俑/遗物/祭品/角色/宝牌同货架**（`CurShopGoods`）。

## 7. 地图与敌人生成细节

- 结构三层：关（Level）→小节（Section）→层（Layer）。`LayerConfig { layerNo, nodeType, nodeNum }`，`LayerType ∈ {Fixed, Random, FixedEvent}`；`RandomConfig { nodeNumOfLayers, nodeNumOfSection, nodeProbability{regularNode, eventNode}, eventNodeOfLineMax, canRepeatEventNode/RegularNode }`。
- 生成器保证：事件节点数上限、同线事件不超限、节点类型修正（字符串证据）。
- **事件节点＝小节点树**：`GameEvent` ScriptableObject + 第二个 `NodeType` 枚举——`Dialog/Optional/Text/Title/Description/Bubble/AddBaseScore/AddFan/AddIndependent/AddHp/AddHun/AddLowToken/SetBaseScore/SetFan/SetIndependent…`，事件内选项直接给数值/资源，子事件可嵌套（"开启一个子事件"）。
- **随机池持久化**：`GlobalDataCtrlEventNodePool/RegularNodePool`（`SaveDataRandomItem` 列表）＋ Saver 池快照——已触发事件不重复（除非 canRepeat）。
- **敌人挑选**：战斗节点 → `AIBase` prefab（`isInRandomPool` 标记可否随机出）＋ `Level` 数值（bossBaseScore/bossIndependent）＋ 难度 `DifficultyPayload`；`GlobalDataCtrlBattleAIBlackPool`＋Saver 黑名单防重复出怪；`_battleBossAIRecordList` 记录本局已遇 boss。

## 8. 架构总结（可直接对照我们工程的观察）

1. **分层**：`Saver`（持久档）→ `PlayMaJiangData`（进场值拷贝快照）→ `Pipeline ×2`（局内派发）→ `容器`（现场态）→ `Payload(SO 数据) + Display(一卡一类逻辑) + prefab/VFX(表现)`。数据/逻辑/表现三件套，内容件全 ScriptableObject 化。
2. **内容协议大一统**：玩家灵俑＝boss 技能＝角色技能＝遗物效果＝祭品效果＝宝牌结算，全走 `IOn*` 事件总线＋`On*Input/Output` DTO；商店货架统一 `IItemInfo`。新增内容不改引擎，只加类＋SO＋prefab。
3. **敌人＝玩家同协议**：AI 侧容器与玩家镜像，差异全在配置（`AIBase` 权重表/技能池/牌库/宝牌绑定）；AI 无搜索，纯 `GreedyConfig` 权重（连每张牌一个权重）。
4. **存档激进简化**：牌局不落盘只存节点锚；宝牌绑定是唯一局内→局外回写通道。
5. **确定性**：全程 `randomSeed`＋`Decimal` 精确结算（种子模式 `_isSeedMode` 面向复现/分享）。
6. **调参集中**：`GameConfig`（全局）＋`AIBase/GreedyConfig`（敌人）＋`Level/DifficultyPayload`（关卡）三张表管全部数值，payload 字段即内容语法。

## 9. 图鉴/收藏系统（Illustration，后续补挖）

**入口与结构**：主菜单右上「图鉴」按钮 → `IllustrationPanelCtr`（顶部 Tabs 组＋当前子面板切换＋**全局搜索**——`SearchController` 实时过滤、搜索态隐藏常规内容器）。子面板基类 `IllustrationSubPanelCtr`（各页自带搜索器＋左侧二级导航＋`allItems`）。子页清单：**灵俑**（LingYongPanelCtr）、**遗物**（RelicPanelCtr）、**祭品**（OfferingPanelCtr）、**番种**（FanXingPanelCtr，配 FanItemCtr/FanPopPanelCtr/FanXingManager）、**成就**（AchievementPanelCtr）＋**Boss 图鉴**（BossPanelCtr＋boss 详情页）；宝牌/牌灵条目（BaoLingItem）并入相关页并参与搜索。

**发现制收藏（核心模型）**：条目默认隐藏——`isDiscovered` 标记、`_unDiscoveredTerm` 本地化"未发现"文案、各页持 `_discoveredLingYong/_discoveredOffering/_discoveredRelic` 发现清单；发现来源＝对局中获得/遇到（"#宝灵解锁# 新增发现宝牌""#存储已发现的番型#"）。Saver 持久化收藏：`_hadXiaoChouList/_hadRelicList/_hadOfferingList/_unlockedRelicList/_characterCollectionDataList`。

**解锁通道（发现 ≠ 解锁）**：未解锁条目可花**修为**购买解锁（"【修为解锁】{0} 失败 当前{1}不足"——图鉴兼解锁商店）；成就发解锁（"成就 {0}[{1}] 解锁灵俑 {2}"）；兑换码发解锁（灵俑/角色）；`XiaoChouPaiNeedUnLockedList` SO 维护待解锁清单。

**浏览辅助**：稀有度分组容器（普通/稀有/史诗/传说，`_containers[]＋_itemsLists[]`）；"总表(含未解锁)/总表(已解锁)"双视图；**收藏完成度**"[ArchiveCollect] 收藏比例 => {0}/{1} = {2}%"；详情弹层 `ShowDetailPanel(payload,…, isDiscovered, isGroupUnlock, item)`（含 3D 模型加载）；灵俑页还带封禁管理（BanLingYongCtr）与代币面板。

**对我们的启示**：图鉴不是静态说明书，是**发现驱动的局外收藏闭环**（玩到→点亮→修为解锁→进池），完成度百分比给搜集目标感。
