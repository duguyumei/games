# UI 流程

> 状态：初稿
> 前置：[游戏概述](./00-游戏概述.md)、[架构](../implementation/架构.md)
> 平台：PC 键鼠优先，移动端适配留后期

本文定义屏幕清单、跳转关系与战斗界面布局。目的是让实现有明确的界面清单，且确定每个界面需要哪些数据。

## 1. 屏幕清单

```text
主菜单
  ├─ 开始探索 → 准备界面 → 探索地图
  ├─ 局外改造（真气重塑、局外升级）
  ├─ 图鉴（功法、内功、敌人）
  └─ 设置

探索地图
  ├─ 节点：战斗 → 战斗界面
  ├─ 节点：搜索 → 战利品界面
  ├─ 节点：商店 / 事件 / 休息（待设计）
  └─ 撤离 → 结算界面 → 主菜单

战斗界面
  └─ 胜利 / 失败 → 结算 → 回到探索地图
```

九个屏幕，其中**战斗界面是唯一复杂的**。其余都是列表 + 按钮。

## 2. 跳转关系

```text
主菜单 ──开始──→ 准备（选地图、选构筑）
                    │
                    ↓
              探索地图 ←──────────┐
                    │             │
        ┌───────────┼─────────┐   │
        ↓           ↓         ↓   │
      战斗        搜索      事件   │
        │           │         │   │
        └───────────┴─────────┴───┘
                    │
              撤离 / 战败
                    ↓
                 结算 → 主菜单
```

战斗失败与撤离成功都回主菜单，区别只在结算界面显示的收获。

## 3. 战斗界面布局

信息密度是本作的核心难点：玩家需要同时看到双方四个牌区、双方功法配置、双方状态层数。

```text
┌────────────────────────────────────────────────────────┐
│ 敌方  生命 72/100   罡气 5  岩障 3  格挡 1             │  ← 敌方状态条
│ 凝气 18  驭气 2  散气 5                                │  ← 敌方牌区计数
│ ┌──────┐ ┌──────┐ ┌──────┐                            │
│ │敌功法│ │敌功法│ │敌功法│  ← 敌方本组计划（公开）      │
│ └──────┘ └──────┘ └──────┘                            │
├────────────────────────────────────────────────────────┤
│                   第 3 回合 · 行动组 2                  │  ← 回合指示
├────────────────────────────────────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                   │
│ │ 功法 │ │ 功法 │ │ 功法 │ │ 功法 │  ← 我方功法槽      │
│ │ 对子 │ │ 高牌 │ │ 三连 │ │ 顺子 │    （牌型要求）    │
│ │ [空] │ │ 金7  │ │ [空] │ │ [空] │    （已分配真气）  │
│ └──────┘ └──────┘ └──────┘ └──────┘                   │
├────────────────────────────────────────────────────────┤
│  行气（5/8）                                            │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐                   │
│  │金 7│ │木 8│ │水 5│ │火 9│ │土 6│  ← 可拖拽          │
│  │气+2│ │    │ │封脉│ │毒3 │ │    │    （状态标记）    │
│  └────┘ └────┘ └────┘ └────┘ └────┘                   │
├────────────────────────────────────────────────────────┤
│ 凝气 13   驭气 1   散气 6      [结束行动组]             │
│ 我方  生命 65/80   化劲 4  灼热 2                       │
```

### 3.1 分区职责

| 区域 | 显示什么 | 交互 |
|---|---|---|
| 敌方状态条 | 生命、五种防御层数 | 悬停看详情 |
| 敌方牌区计数 | 凝气 / 驭气 / 散气的**数量**，不显示具体真气 | 点击展开（若规则允许） |
| 敌方计划 | 本行动组要发动的功法（公开） | 悬停看效果 |
| 回合指示 | 第 N 回合、第 M 行动组、先手方 | 无 |
| 我方功法槽 | 牌型要求、已分配真气、效果摘要 | 拖放目标；点击预览 |
| 行气区 | 全部行气真气，含状态标记 | 拖拽到功法槽；点击选中 |
| 我方牌区计数 | 凝气 / 驭气 / 散气数量 | 点击展开 |
| 我方状态条 | 生命、五种防御层数 | 悬停看详情 |

### 3.2 敌方信息的公开程度

[敌方与信息](./05-敌方与信息.md) 已确定：敌方计划固定且公开。因此敌方功法在行动组开始时就显示，玩家可以据此决定分配。

敌方**行气的具体内容**是否公开，文档未定 —— 见 §7 待决。

## 4. 真气卡牌的信息层级

一张真气要显示：属性、内力、状态、重塑。空间有限，分三层。

```text
第一层（始终可见）
  属性色 + 内力数字        金 7
  
第二层（有则显示的角标）
  气力       +2 / -1       右上
  毒量       毒 3          右下
  封脉/冻结  图标          左上
  重塑标记   小点 ×N       左下

第三层（悬停展开）
  存有的内力 = 基础 + 重塑明细
  提供的内力 = 存有 + 气力（或冻结时为 1）
  全部状态记录及来源
  全部重塑及来源
```

**存有的内力与提供的内力必须区分显示。** [真气系统](./08-真气系统.md) 定义了两者：面板显示与毒发门槛用存有的，功法实际读取用提供的。冻结时提供的恒为 1，这个落差玩家必须看得见。

## 5. 核心交互：分配真气给功法

这是玩家在战斗中做得最多的操作，必须最顺。

```text
方式 A（拖拽）  按住真气 → 拖到功法槽 → 松手
方式 B（点选）  点真气（可多选）→ 点功法槽
方式 C（快捷）  点功法槽 → 自动选中满足牌型的真气 → 确认
```

**三种都要支持。** A 直观，B 适合多选，C 适合已经想清楚的老玩家。移动端只保留 B。

### 5.1 分配时的实时反馈

分配过程中必须实时显示：

- **牌型是否已满足** —— 功法槽边框变色
- **本次预计输出** —— 功法槽显示预览数值
- **消耗后行气剩余** —— 行气区计数变化
- **是否还能发动其他功法** —— 其他功法槽置灰

预览数值走 `BaseAction.execute_preview()`，拦截器在预览模式下不产生副作用（见 [真气拦截器](../implementation/真气拦截器.md) §8）。

### 5.2 无法行动的提示

[核心战斗](./01-核心战斗.md) 定义：剩余行气凑不出任何已配置功法的牌型时，该方本回合不再发动功法，**没有保底措施**。

因此界面必须**提前**让玩家看到这个状态，而不是让玩家试完才发现。功法槽在牌型无法满足时置灰，全部置灰即「无法行动」，此时「结束行动组」按钮变为「结束回合」。

## 6. 实现顺序

对应 [架构](../implementation/架构.md) §8 的第 7 步，UI 自身也分步：

```text
1. 行气区：显示 5 张真气（纯色块 + 数字，无美术）
2. 点击一张 → 调流程层的运转方法 → 真气消失，驭气计数 +1
3. 功法槽：显示牌型要求，拖放接收真气
4. 牌型判定的实时反馈（边框变色）
5. 预览数值
6. 敌方区域 + 回合指示
7. 状态角标、悬停详情
8. 换上水墨美术
```

第 2 步跑通就验证了「表现层只发意图、流程层执行动作」这条约束可行。

## 7. 待决

- **敌方行气是否公开。** 影响敌方区域的布局 —— 若公开需要完整的牌区显示，若只公开计数则一行文字够。[敌方与信息](./05-敌方与信息.md) §4 提到「对敌方真气的干预边界」，但没说可见性。
- **驭气区是否需要独立显示。** 驭气是「已分配给某功法、等待读取」的真气，视觉上可以并入功法槽内部（显示在槽里），也可以单独一区。倾向并入功法槽。
- **散气与凝气是否需要可展开。** 玩家想知道凝气里还剩什么才能规划后续回合，但展开 18 张真气占屏幕。可能用「按属性统计」代替完整列表。
- **行动组的推进是自动还是手动。** 若自动，玩家分配完就结算；若手动，需要「确认」按钮。倾向手动 —— 分配过程中可以反复调整。
- **动画时长。** 卡牌游戏的手感很依赖这个，但只能实测调。
