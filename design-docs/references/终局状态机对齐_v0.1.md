# 终局状态机对齐 v0.1（2026-11-15）

> 目标：把「遭遇胜利 → 弃手/洗回 → 攻击视图收尾 → 升级/胜利」的**底层时序与职责**
> 对齐原版。本文只记录结构与证据，不把表现层时长当逻辑门。
> 证据等级：✅ ISIL/资产直读；🔬 lldb 运行时；⚠️ csall 仅定位/待复核；❓ 未闭合。

## 一、原版结构（已证）

### 1. 两条轨

| 轨 | 载体 | 内容 | 是否阻塞洗牌 |
|---|---|---|---|
| 命令轨 | `CommandRunner`（IEnumerator 串行） | 卡牌/牌堆飞行、DiscardHandCommand、DiscardComboPile、洗牌 AddDiscardToDrawPile | 洗牌排在前面的清理命令之后，但不攻击视图 |
| 视图轨 | `GameView.IsAnyViewUpdating`（RegisterUpdatingView） | AnimatedWeapon / WeaponCollision / 粒子 / 碎牌 / 宝箱等 | **不阻塞洗牌**；只在转场前统一等 |

- 攻击武器 `AnimatedWeapon.StartWeaponAttack` 是 UniTask 协程，登记/注销 `RegisterUpdatingView`，
  **不是 CommandRunner 命令**；死亡判定在动画中段的 `OnDamagePointReached`。
- 洗牌命令走 CommandRunner，与攻击视图并行。

### 2. EncounterDefeatedState.ExecuteTask（ISIL 直读）

```text
await player.OnEncounterDefeated()                 // :125 第一拍，数据收尾先跑
  m_EncounterEnding → RemoveTemporaryCardsFromDeck
  anyDiscarded = hand>0 || fcc>0 || combo>0
  DiscardHand(false,false)                         // :251 无条件
  DiscardComboPile()                               // :254 无条件
  if anyDiscarded: Delay(1000ms)                   // :282→:299 只垫拍
  TryAddDiscardPileToDeck()                        // :415 无条件；弃堆空 no-op
dungeonModel.OnEncounterDefeated + 成就              // :236/:249
await WaitWhile(CommandRunner.IsProcessing || GameView.IsAnyViewUpdating)  // :272
await Delay(100ms)                                 // :383
转场
```

### 3. 关键语义

- `anyDiscarded`（hand/fcc/combo）**只决定 1000ms 垫拍**，不是洗回门；
- `TryAddDiscardPileToDeck` 无条件：弃堆里有牌就洗回；第一关 0/0/0/1 也洗；
- 洗牌数据/命令在死亡后立即启动，攻击视图继续；
- `WaitWhile(IsProcessing || IsAnyViewUpdating)` 在收尾之后、转场之前，服务场景重建；
- 用户实机目击：攻击特效仍在播时，牌已进弃堆并完成洗牌 ✅。

### 4. 未闭合

- `EncounterResetState.EnterStateTask` 也有一份 `SyncView → player.OnEncounterDefeated`；
  与 `EncounterDefeatedState` 的调用是二选一、旧路径还是有守卫，状态转场边为 stub，
  **❓ 未钉死**。本移植先按「每场遭遇只执行一次终局结算」实现，避免双调；
- 直刺具体 weapon 配置 ⚠️ 未逐卡验，但族类在登记集合内；
- 洗牌弧度：原版有弧度（用户目击 + `DOLocalJump`），我方暂直线，后议。

## 二、我方旧结构（问题）

```text
_check_finale（命中拍）
→ _finish_encounter_after_playout
   while _cardq / _any_view_updating / _played_anim_pending:
      await frame            ← 先等整段攻击回放（1.18s）
→ +100ms
→ discard_hand_finale / add_discard_pile_to_deck
→ _try_finish_win
```

问题：

1. 把「转场前的视图等待」提前到了「洗牌前」；
2. 洗牌不能与攻击特效并行；
3. 第一关敌人已死仍空等回放，表现为卡顿/空拍；
4. 与 d__280「OnEncounterDefeated 第一拍」相反。

## 三、目标结构（本次起）

```text
_check_finale（命中拍）
→ _start_terminal_settlement（只启动一次）
   → discard_hand_finale：hand/played→discard（无条件）
   → anyDiscarded? await 1000ms
   → add_discard_pile_to_deck：无条件洗回，洗牌命令入 _cardq
   → _finale_cleanup_done = true

攻击回放/死亡 FX 继续并行；
XP 珠/条/升级窗按原流程；
_on_ended（回放结束）→ _win_pending
→ _try_finish_win：
   xp_flights==0
   reward_ui==null（升级窗先关）
   finale_cleanup_done
   _cardq 空（洗牌动画真正完成）
   → 100ms
   → 胜利浮层
```

## 五、不变量

1. 数据收尾不等攻击视图；
2. 攻击视图不阻塞洗牌；
3. 洗牌只等自己的命令/末卡动画；
4. 胜利浮层等：XP 完、升级窗关、终局结算完、洗牌命令完、100ms；
5. `anyDiscarded` 只控制 1s 垫拍，不是洗回门；
6. `check_piles` 总量守恒；第一关弃堆 1 张也会洗回；
7. 结案日志清退前保留 `[终局账]`/`[洗牌视图]` 取证。

`EncounterResetState` 双调核对（2026-11-15 收口）：

- 正常胜利只有一条链：敌全灭 → `EncounterDefeatedEvent` → `SetStateEncounterDefeated`
  → `ExecuteTask :125 player.OnEncounterDefeated` **一次**；`ExecuteTask` 自身不转场，
  尾部只拨 `_isInCombat` 后收线。
- `EncounterResetState` 是另一条**手动重置**路径：`ResetEncounterButton`（场景 `m_IsActive: 0`
  默认禁用）→ `GameView.Button_ResetEncounter` → `RaiseEncounterResetEvent` →
  `SetStateEncounterReset` → `SyncView → :197 player.OnEncounterDefeated`（第二份调用）。
- 两条路径由不同全局事件驱动，正常游玩互斥；bp12 运行时 `TryAddDiscardPileToDeck`
  教程关共 4 中（开局 3＋胜利 1），若正常胜利双调应有第 5 枪，未出现。
- 结论：**正常胜利单调；双调只存在于禁用态调试重置**。我方每场一次正确，不复刻调试路径。
