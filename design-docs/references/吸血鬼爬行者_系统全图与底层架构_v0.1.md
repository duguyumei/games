## 二、分层与依赖方向

```
L5 呈现：HUD 视图｜Modal(41)｜浮窗｜DeckBox｜暂停设置          ←订阅模型事件
L4 元游戏：进度｜装备位｜圣物｜秘法｜FCC｜商店｜铁匠｜解锁｜成就｜教程
L3 地牢：层生成(15)｜地图数据｜房间模板｜运行时模型｜地牢事件｜可破坏
L2 战斗：GameStateMachine(18态)｜GameModel｜遭遇三层｜敌人｜武器弹体(88)｜索敌
L1 卡牌架构（六件套）：数据｜实例｜容器｜视图族｜编排｜效果
L0 底座：状态机框架｜单例｜SO数据库｜变量资产｜View登记簿｜CommandRunner｜存档｜随机｜本地化｜输入｜运动工具
```

- 依赖方向单向向下：L4 内容调 L2 战斗调 L1 卡牌调 L0 底座；L5 呈现只订阅不指挥。
- **横切三件**：存档（L0，任何 ISaveableComponent 域可挂）、Globals 全局事件总线（跨域解耦：EncounterDefeatedEvent/MoveNextFloorEvent 等）、RngStream（任何随机点分轨）。
- **底层判定标准**（被依赖广度）：L0＝全员依赖；L1＝被 L2/L4/L5 依赖；L2/L3 互相只在流程层握手（状态机事件）；L4/L5 无被依赖。

## 三、底层卡牌架构（L1 六件套）——本游戏的核心资产

### 3.1 六件套总览

| 件 | 类 | 结构要点（锚） |
|---|---|---|
| ① 数据件 | CardConfig（SO）＋CardType/CardGroup＋数据库 | 纯配置零状态；**效果四钩子数组内嵌**（onPlay/onDraw/onDiscard/onEndTurn，Odin SerializedBytes）；等级上限/费用类型/进化素材/宝石槽全在配置 |
| ② 实例件 | CardModel（MonoBehaviour，**GO 池化**） | `GetOrCreateCard`（PlayerModel:7537，_cardPool 栈）造/还池；持 _cardConfig/_cardView/费用修改栈×4/_isFreeToPlay/宝石/类型；**卡等级不在卡上**（在 PlayerModel.CardGroupStatus 账本） |
| ③ 容器件 | CardPileModel（唯一堆容器）＋7 薄包装 | TryAdd/TryGrab/Insert/Remove/Peek/Shuffle/Swap/SetCardOrder＋**OnCardAdded/OnCardRemoved 事件直连 _view**；包装件＝**组合不继承**（Hand/Draw/Discard/Destroy/Combo/Fcc/Throwing 各自持引用加语义） |
| ④ 视图件 | CardPileView(abstract)＋9 子类＋槽位布局族＋CardView | View 基类 SyncView 对账；**CardView.SetCardConfig 一次绑定＋之后只刷文本**（sprite 直换终身不重建卡面）；手牌＝CardSlotHolder 槽位制＋CardLayoutGroup 扇形代数 |
| ⑤ 编排件 | PlayerModel(209)＋PlayerView(23) | 上帝对象：卡池/回合/抽打弃/资源/连击/FCC/等级账本/存档钩子；PlayerView＝视觉命令宿主（DrawCardsCommand/DiscardHandCommand） |
| ⑥ 效果实 | CardEffect(abstract)＋87 子类＋CardCostType 族 | **Execute→OnExecuted 全同步**；四生命周期钩子；DisplayProjection/ResetProjection 悬停投影；宝石运行时注入（triggerType 0-5 路由） |

**多组件同物体（资产级实锤）**：Card_Hand.prefab 挂 98 个 MonoBehaviour，字段指纹同现——`_cardConfig/_cardGemsModel`（CardModel）、`_costText/_visualRoot/_transformMover/_tooltipPrefab`（CardView）、`IsDraggable/_currentCardSlot`（InteractableCard）、`_isPlayerTurn`（PlayableCard）。＝卡 GO＝数据模型＋视图＋交互＋运动原语一体（Unity 组件制用法；我方差异登记 #5 的子节点组件制即此映射）。

### 3.2 数据流：一次出牌的全链（全锚）

```
CardConfig.onPlayEffect
→ PlayerModel.TryPlayCard(:13054)：扣费/连击判定/入 Combo 堆（CardPileModel.TryAddCardToTop→事件→ComboPileView）
→ CardEffectsModel.OnPlayCard(:110) → CardEffect.Execute(:210) → OnExecuted          ←逻辑轨·全同步
→ DamageEffect：GenerateDamageParams → WeaponTargeting.CalculateEnemiesToHit/ProcessColumns
   → EnemyModel.ResolveDamage(:995) 落账/判死（当帧）                                  ←逻辑轨
→ DamageEffect.FireWeapons(:8721)/FireMultipleWeapons：逐把生成 Weapon（发射间隔=DelayMultiplierEquation×rand）
   → WeaponCollision 逐段命中/DoAllRemainingDamage；AnimatedWeapon=clip 时长；Projectile=物理涌现时长  ←表现轨·UniTask
→ 视图命令（CardAddedViewCommand 等 IEnumerator）入 CommandRunner 串行               ←表现轨·命令队列
→ 回合闸：WaitWhile(CommandRunner.IsProcessing ‖ GameView.IsAnyViewUpdating)
```

### 3.3 通信四总线（模型→视图/跨域解耦的全部通道）

1. **C# 事件一对一**：CardPileModel.CardAdded→_view（堆模型直连堆视图）；EnemyModel.Died 等。
2. **变量观察者资产**：值住 FloatAsset/BoolAsset，多处订阅（IsPlayerTurn 驱动 PlayableCard/按钮；SimpleStat 数值条）。
3. **Globals 全局事件总线**：跨域广播（EncounterDefeatedEvent→GameStateMachine/PlayerModel/DungeonModel 各自订阅）。
4. **状态机事件**：StateExecuted/StateEntered/StateExited（流程驱动，RegisterTransitions 23 订阅）。

### 3.4 执行双轨

- **逻辑轨＝全同步**：效果执行、伤害落账、判死、资源增减当帧完成（伤害管线档＋差异登记 #40 的依据源）。
- **表现轨＝排队＋登记闸**：IEnumerator 视图命令入 CommandRunner 保序；UniTask 协程管长演出（武器/弹体）；回合推进只等 `IsProcessing‖IsAnyViewUpdating` 双条件。

## 四、主流性判定

> 业内参照两档：〔仓内已证〕STS2（Godot 4.5 反编译在库）、尸姬（Unity 反编译在库）；〔通识〕Unity 生态公开做法（含 GDC 公开分享），未逐源验证。

| # | 原版做法 | 业内参照 | 判定 |
|---|---|---|---|
| 1 | SO 配置＋AssetDatabase 注册表（数据/逻辑分离） | Unity 官方 SO 架构模式，Unity 卡牌通用〔通识〕 | **主流·教科书式** |
| 2 | 卡实例=MonoBehaviour+对象池+模型视图同物体 | Unity 中型项目常态；超大卡牌（炉石级）用纯 C# 模型+绑定层〔通识：GDC〕 | **务实主流**（省绑定层，代价=模型黏引擎） |
| 3 | 单容器类 CardPileModel＋薄包装组合 | 「组合优于继承」教科书用法 | **主流·干净** |
| 4 | 事件驱动模型→视图（观察者四总线） | MVP/MVVM 变体，回合制卡牌标配〔通识〕 | **主流** |
| 5 | CommandRunner 命令队列序列化表现 | 卡牌/回合制动画保序标准件（任务队列模式）〔通识：GDC 炉石公开分享〕 | **主流** |
| 6 | 逻辑同步＋表现异步双轨（deterministic core + cosmetic queue） | 回合制竞技/卡牌通行〔通识〕 | **主流** |
| 7 | 泛型 GoF 状态机框架（框架级自持 5 类） | 流程控制标准件 | **主流** |
| 8 | **PlayerModel 209 法上帝对象** | 反架构洁癖教科书，但交付现实常见（同类聚合在 STS AbstractPlayer 亦见）〔通识〕 | **务实非主流**（全作最大架构债） |
| 9 | Odin Serializer 存嵌套效果数组 | Unity 常用第三方序列化件 | **主流工具选择** |
| 10 | UniTask＋IEnumerator 双异步并存 | Unity 现行主流渐进迁移态 | **主流** |
| 11 | 键鼠+手柄双输入制、手柄选牌状态机族 | 主机跨平台标配 | **主流**（我方 #15 缓后合规） |
| 12 | 拖拽＝自研轮询（非 UGUI 标准拖拽事件完整制） | STS2 同为自研轮询〔仓内已证〕——手柄动机同源 | **业内同构** |

**总判定**：底层＝「Unity 生态主流件的规范组合」，无 ECS、无自研轮子级非常规设计；两处务实偏差（模型视图同物体、PlayerModel 上帝对象）均为交付现实常见取舍。**对复刻的含义**：这套架构可直接按结构 1:1 落 GDScript（我方 11 批计划即按此分层排序：批1-4=L1 前四件、批5=效果件、批3=编排件）；唯一需要 GDScript 映射裁量的＝「模型视图同物体」（我方已按 #5/#7 登记拆两层）与「上帝对象是否照搬聚合度」（建议照搬方法集、按文件分件，见批3）。
