# 手牌悬停命中区与迟滞调研 v0.1

> 2026-11-03 立档。起因：VC 战斗手牌「放大后鼠标移到卡上半截会缩回」报障，及随后对「套壳是否业内做法」的质疑。本档回答三问：这个问题的学名与普遍性、业内的三派解法、我方代码对应哪派何时补哪派。
> 结论先行：**「稳定命中区（壳）」是业内讨论中的常见解之一，但不是统一标准；单用壳必然留下「弹起物探出命中区」的洞，完整方案＝壳＋迟滞（轮询/进出阈值分离）**。「套壳＝业内统一」的说法（2026-11-03 会话中口误）作废，以本档为准。

## 1. 问题定义（学名与普遍性）

悬停驱动的 UI 元素在 hover 时**移动/放大/弹出**，导致「鼠标还在视觉元素上（或正朝它移动），进/出事件却判定离开」→ 元素收回/狂闪。三个圈子公开讨论多年：

| 圈子 | 经典案例 | 症状 |
|---|---|---|
| Web 前端 | **亚马逊巨型下拉菜单问题**（2013 被拆解） | 鼠标斜向移向弹出的子菜单，途中穿过兄弟项，菜单被关掉 |
| Unity | `OnPointerExit` 不可靠（Reddit 常年吐槽）；卡牌悬停在相邻卡间快速切换（2024 官方论坛帖，与本案同病：楼主缩放卡**根节点**，命中盒随缩放移动） | 退出事件误触发/快移时根本不触发（卡卡在放大态） |
| Godot | 手牌设计求助帖（forum.godotengine.org/t/62716 等） | 同族：`mouse_exited` 在控件移动/缩放时语义失真 |
| 我方仓库 | VC 手牌（QiVcScreen，2026-11-03） | 卡弹起 ×1.5 后上半截探出壳矩形 152px，鼠标移入探出区触发「离开壳」→ 焦点丢、卡缩回 |

## 2. 业内三派解法

| 派别 | 做法 | 适用 | 代表出处 |
|---|---|---|---|
| ① 稳定命中区（壳/proxy hitbox） | **交互区（射线目标/碰撞体）固定不动，动画只做子节点的视觉**（缩放/抬起/倾斜全在内层） | 一切「卡在布局槽位上做视觉动画」的场景；命中区稳定还带来左右切卡零抽动 | Unity 各帖标准答案之一（「Keep the raycast target a fixed, non-scaling hitbox — scale a child visual」） |
| ③ 三角形意图预测（safe triangle） | 按光标**速度矢量**与弹出物构成的三角形判断「是否正朝它移动」，朝它则不关 | 弹出物**离锚点很远**（斜向子菜单、大幅位移浮层） | 亚马逊下拉（Ben Kamens 拆解）、Framer「cursor trajectory / safe triangle」 |

**派别组合的成熟用法**：①＋② 打底（命中区稳定＋探出区保持），③ 只在「弹出物远距位移」时加。MIT Tech Review 对三派的评注：③ 优于纯宽限期计时（② 的弱形态）——宽限期只是容忍误操作，③ 是预测意图。

## 3. 我方代码对应（2026-11-03 落地态）

- **① 壳**：`QiVcScreen._rebuild_hand`——壳 Control（`HAND_W × HAND_H+HAND_LIFT`，STOP）管一切事件；内层＝SubViewport 贴图（IGNORE，纯视觉，倾斜/弹起/光效全在内层）
- **② 迟滞**：`_hand_lerp_tick` 焦点保持判据——**卸掉 mouse_exited**，每帧判「鼠标 ∈ 壳矩形 ∪ 弹起后卡面矩形（各 grow 2px）」才保焦点，两矩形皆离才收；进入仍走 mouse_entered（StS2 制：设用事件、收用轮询）
- **③ 未用**：当前弹出物与壳重叠（并集即够）；将来做「斜向浮窗/远距弹出」时按亚马逊三角形补

## 4. 判定表（新交互件选型）

| 场景 | 用哪派 |
|---|---|
| 槽位上的卡/按钮做放大、抬起、倾斜 | ①打底＋②补探出区 |
| 弹出物贴着锚点（tooltip 上浮、卡弹起） | ①＋② 的「壳 ∪ 弹出物矩形」并集判定（本案） |
| 弹出物离锚点远（斜向菜单、侧拉面板） | 再加③（光标轨迹三角形） |
| 拖拽跟手件 | ①（命中区原地不动、视觉跟手——本仓拖放制同源） |
