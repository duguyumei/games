## 一、类幸存者本源（VS 系）的做法

- **经验＝世界实体，非击杀直接到账**：gem 掉地上，进磁吸半径才吸向角色，**接触角色当场入账**；经验跨线**当场暂停弹升级选择**。VS 系无「飞向 HUD」环节（条在屏顶、拾取在角色身上），但「跨线即弹」与本项目「涨满立即弹窗」同构。
- **设计意图**（Klein）：掉落物逼玩家近身击杀现场，制造「冒险拾取 vs 安全掉队」取舍——该类型里唯一近似走位技巧的时刻；判型标准＝「有没有可投资的拾取范围属性（pickup range stat）」。
- **三条工程/体验配套**：①屏上宝石过多时**自动合并成高级宝石**（gem merging，性能＋整洁）；②远处宝石向玩家缓慢漂移＋到期消失（奖励不丢、屏幕不糊）；③拾取音效**音调逐颗递升**（多巴胺核心）。
- **警告**（Klein＋反篇 GDC）：特效过载会让玩家主动关掉自己的攻击特效；反馈要克制、可见性优先。

## 二、「飞向 HUD」形态（F2P 手游圈，与本项目形态同构）

- 模式名＝**fly-to-HUD / coin-fly**：收集点爆散 → 物件飞向计数器 → 落地计数器弹跳＋数字递增。三大引擎皆有标准实现与商品件。
- Game Economist Consulting 四原则：①货币必须**流进钱包 UI 位**（「钱包数字不会凭空增加」——因果闭环）；②奖励难以忽略；③动画量可夸张于实际值；④强音效。冠军 Brawl Stars：**动画显示的单位数与实际加入完全一致，条在单位到达时才跳**。
- **到账时序共识**（多来源汇总）：主流架构＝底层状态立即更新保正确、表现层落地才计数；纯落地制（状态等动画）同样成立。**红线只有一条：数字不能在物件未到时先跳**（因果闭环不破）。

## 三、表现层方法论（juice）

GDC《Juice It or Lose It》：逻辑零改动、纯表现层迭代——拾取物脉动/到期前闪烁、收集时粒子爆、**+N 数字弹出**、挤压拉伸、hit-stop、音效递升。本项目对应件＝出生弹跳、拖尾、到账爆点、条闪、飘字、升级冲击环（全代码可实现）。

## 四、本项目映射结论

1. **已实装链路（2026-11-05 经验特效轮）＝业内共识侧**：击杀→敌位放珠→贝塞尔飞向经验条→**珠到账才入账**（`QiVcBattle.settle_one_xp`）→涨满**立即**战斗内弹三选一→升级关完才弹胜利横幅。与 Brawl Stars 式「到达才跳」因果闭环一致。
2. **后续可抄三件**：①到账**音调递升**（音效轮；VS 标配）；②**+N 飘字＋条闪**（juice 标准件，纯代码）；③**gem merging 多敌合一大珠**（波次战敌多时启用；单场敌少暂不需要）。
3. **美术资源结论**：业内此类飞 HUD 物件清一色**单张小精灵图＋程序运动**（无序列帧）——委托单＝1 张 64×64 透明底玉珠 PNG（可另配 32×32 软圆点/128×128 光斑，多用途），其余表现全代码。
