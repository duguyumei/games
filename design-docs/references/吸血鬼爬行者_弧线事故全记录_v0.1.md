### 环 3：垂直轴符号翻转（翻「中间低」案的关键）

**文件**：`~/Documents/vc_decomp/IsilDump/UnityEngine.UI/UnityEngine/UI/LayoutGroup.txt:2044-2152`
（**游戏自带的 UnityEngine.UI**，`SetChildAlongAxisWithScale`）：

axis==0 分支（:2141-2149，无翻转，普通语义）：
```
2145 mulss xmm0, [rbp-40h]        ; pivot.x × width
2146 mulss xmm0, [rbp-1Ch]        ; × scaleFactor
2147 addss xmm0, [rbp-50h]        ; ★ + pos
      → x = pos + pivot.x × width   （左缘定位，x 向右）
```

axis==1 分支（:2121-2140，★翻转）：
```
2131 xorps xmm2, [0x502B9C0]      ; ★ −pos（符号位掩码取负）
2133 movss xmm1, [0x502B964]      ; 1.0
2134 subss xmm1, xmm0             ; ★ 1.0 − pivot.y
2135 mulss xmm1, [rbp-40h]        ; × height
2136 mulss xmm1, [rbp-1Ch]        ; × scaleFactor
2137 subss xmm2, xmm1             ; ★ y = −pos − (1−pivot.y)×h×scale
```

**推导**：槽 pivot=(0.5,0.5)、h=100：
- 边缘卡（curve=0）：pos=start → y = −start − 50
- 中间卡（curve=1）：pos=start−32 → y = −(start−32) − 50 = **−start − 50 + 32 → 比 egdes 高 32**

**∩ 形，中间高 32 画布单位（上屏 ≈36px）。判正。**

## 三、问题是怎么出现的（根因四条，按暴露顺序）

1. **二手结论未复核**：「死代码」判源是 survey 摘记，我直接引用没回汇编一手核对——
   实参 false 记成 true、Invalid jump target 当成 early return，两处都在同一跳转上。
2. **循环论证**：拿「用户否掉我的烂弧实现」当「原版无弧」的证据——测的是自己的 bug，
   不是原版的行为。
3. **引擎语义凭记忆**：uGUI 垂直轴「从顶向下量＋取负」的公式没查游戏自带 DLL，
   用了想当然的「y-up 底边」语义——**同一个库内水平轴和垂直轴符号约定不同**，记忆只覆盖了前者。
   （与 DOTween Ease 枚举案同族：引擎/库的事实必须实测自游戏自己的二进制。）
4. **无常识前置**：卡牌手牌扇形＝中间高两端低是品类通例，反常识结论直接实装了——
   常识是推导错误最早的报警器，这次响了我却没听。

## 四、防复发红线（以后「反编译读结论」必过）

1. **跳转必达**：反编译器噪声（Invalid jump target／throw obj／NoteDecompilerIssue）≠ 行为结论
   ——跳转目标地址必须解析到方法入口再下判。
2. **实参必核**：survey/二手记录里的调用实参，引用前回汇编核一遍（本事故实参一个 bool 翻转整案）。
3. **引擎语义必实测**：Unity/Godot/DOTween 等**库的行为**，从游戏自带的 DLL/dump 实测，
   不凭训练记忆（本事故＋Ease 枚举案两案同族）。
4. **常识前置＋否定结论双证**：落码前先问「这在同类游戏里正常吗」；不正常→停下问用户；
   「原版没有 X」类否定结论必须双证（调用链死＋运行特征死）才准下判；
   用户否掉我实现的 X ≠ 原版没有 X。
