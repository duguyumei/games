## 二、单位槽实测（关键）

- 蓝本单位槽 **170×450**（3D 立绘单位，含）：Head 头像 85×114／Name 160×50／品级条 148×50／Boss 徽 145×50／分隔线 164×2／**属性面板 234×163**（两列 110×40 ×8 项＋宽血条 207×50）。
- **我方裁定偏离**：我方单位＝**卡牌**（敌与器灵都是卡，翻面看详情），故槽位采卡牌制——**180×230（卡牌工厂制裁定，全场唯一）**＋右侧 30px 状态图标列；不采蓝本 170×450（那是 3D 立绘制，不适用）。7×180＋6×间距＝铺满约 1620，居中。
- **卡牌 vs 手牌（本轮裁定澄清）**：卡牌＝场上单位（敌方＋器灵）；手牌＝器灵招式（打出用）。两者都走 QiCardStyle 工厂、都 180×230，但内容结构不同：单位卡＝立绘区＋耐久条＋（敌）属性/（我）剩余攻击次数；手牌卡＝费用＋招式效果。

## 三、意图与状态显示（蓝本机制，已核对代码）

- 意图徽章 E_ActionTip：锚单位 TipPos 常驻，图标＋**实时预结算数值**＋段数；悬停→箭头连线＋完整句浮窗（E_ActionUITip）。
- 状态图标 R_BBuff：挂单位 MyBuffs 容器、**带层数角标**、数值变动即刷新（ReflashBuffTip）；悬停→词条详情窗。意图/状态/Buff＝同一套「小图标＋悬停说明」。
- **我方已按此实装**（敌方卡右侧竖排图标列＋QiTooltip 悬停）。

## 四、弃牌机制完整规格（已彻底核实；我方照此实现）

### 4.1 UI 件实测
- **GiveUpTip**：全屏容器 1920×1080（锚左上），**默认隐藏**；两态＝本体（拖卡即显）＋child(1) 高亮态（悬停弃牌区才亮）。
- **GiveUpCardCheck**：3D 碰撞体，local(15.8, 2.1, −1.3)·scale(1.08×1.00×1.58)＝**战场右缘外的扁宽判定区**（tag=GiveUpCheck）。
- Abandon 200×60／AbandonAll 160×30：右下角两钮（anchor 右下 −200,60／−50,50），弃牌堆查看族。

### 4.2 主动弃牌（手动·拖拽）操作流
1. 拖起手牌 → GiveUpTip 点亮（右侧提示区出现，拖动期间常显）；
2. 卡悬停弃牌区（每帧物理射线 tag 命中）→ 引导线动画＋高亮态亮；
3. 松手在区内 → **弃置（不扣能量）**入弃牌记录；区外 → 正常打出判定（且要求不在弃区，防误触）。

### 4.3 被动弃牌（自动）
- 回合结束仅自动弃 Forget（打出即逝/抽到即自动弃）与 AddCost（增费诅咒）类特殊牌；普通手牌**跨回合保留**。

### 4.4 我方实现口径（Godot 原生映射）
拖卡 `NOTIFICATION_DRAG_BEGIN` → 弃区显示；弃区 `_can_drop_data` 命中 → 高亮；`_drop_data` → 弃置不扣能量；回合结束自动弃同标签牌。弃区位置＝手牌带右端上方的竖条（对应蓝本右缘碰撞体，具体形位随战斗屏联调）。

### 4.5 勘误与教训
前稿「蓝本无拖边弃牌」结论作废——**判定在 3D 物理层（tag 碰撞体），不在 UI 层**；只查 UI 坐标就断言「不存在」是方法错误。通则：下「某机制不存在」结论前，必须把输入链路两条（UI RaycastAll＋Physics Raycast/tag）全查完。
