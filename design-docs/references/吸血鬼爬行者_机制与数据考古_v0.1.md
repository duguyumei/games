# 吸血鬼爬行者 机制与数据考古（v0.1）

> 2026-10-31 立档。对象＝《吸血鬼爬行者》(Vampire Crawlers: The Turbo Wildcard from Vampire Survivors, Poncle × Nosebleed, 2026-04-21)。三路来源，可信度递减：
> ①**一手数据层**：`SurvivatonsAndMore/VampireCrawlersFiles`——把游戏 `Data/` 目录原样上传的 JSON（版本 1.5.x）。本文所有数值若无特别说明均出自此，字段名逐条注明可复核。
> ②**一手代码结构**：开源 BepInEx mod 源码（BetterCards / BetterAutoPlay / Advisor），游戏本体是 **IL2CPP**，拿不到可读 C#，但 mod 的 Harmony 目标与反射字段暴露了真实类结构（§6）。
> ③**二手攻略站**：`vampirescoffin.com`（中文，SEO 站，来源标注为 GameSpot / PC Gamer / Pro Game Guides / Reddit，复核日期 2026-07-10）——只作中文术语与机制解释参考，与 ① 冲突时以 ① 为准（§0.3 有实测冲突样例）。
>
> **入仓边界**：本档只提炼机制与数值锚。游戏原始 JSON、贴图、本地化文本一律不入仓（同「美术三步制」口径）。

## 0. 结论总览

### 0.1 它是什么

第一人称网格地牢探索 ＋ 卡牌构筑，**不是** Slay the Spire 式的路线选择型 roguelike：地牢是**走出来的**（有墙、有光源、有宝箱、每层找铲子挖下层），战斗是回合制卡牌。

### 0.2 一句话骨架

> **一次出牌序列的排序约束**（法力升序）**把「前面几张牌」变成「最后一张牌的倍率燃料」**——这是它全部深度的来源，也是它跟本项目最同构的一点。

| 轴 | 它的做法 | 出处 |
|---|---|---|
| 连击 | 按法力**严格递增**出牌，每接一张倍率 +1；倍率直接乘进伤害 | 遗物 `RelicConfig_PancakeOfPower`（Combo Stack）描述 ＋ `DamageEffect.GetDamageDescriptionValue(player, card, mult, true, inCombo)`（mod 反射调用） |
| 连击的归属 | **不是天生规则**，是开局教学给的遗物赋予 | 同上 |
| 卡池稀缺 | 靠**宝石孔**（GemSlotCount / MaxGemSlotsAllowed / 每种卡的 `_excludeGemTags`）与**进化条件**（配对 ＋ 空孔）双重约束 | `CardDatabase` 字段 |
| 容量 | 起始卡组 **5 张**（1 角色卡 ＋ 4 功法），27 套 | `AllDecks` |
| 局外 | 村庄：旅店（买角色）／铁匠铺（加孔）／占卜师（秘法）／商店（20 项永久强化） | `PowerUpDatabase` / `RelicDatabase` |

### 0.3 二手站的一处实测冲突（说明为什么要以一手数据为准）

攻略站称「角色卡有『打出效果』与『颜色触发』两段数值」（安东尼奥＝打出 +3 护甲／红卡触发 +10% 伤害）。但一手 `CardDatabase` 里 `FCC_Antonio` 的 `statModifiers` 为 `{}`、`shortDescription` 为 `{}` —— **角色效果不在卡表里**，在运行时配置（`GameCardConfig` 一族）中。结论：角色效果数值**本档不采信二手值**，只采信「角色＝一张 0 费卡 ＋ 一个颜色触发」这个结构。

## 1. 游玩循环

```
村庄（整备：角色／秘法／强化／买卡包）
  └→ 世界地图（选地牢，31 个地牢 × 难度评级）
      └→ 地牢（第一人称网格，多层）
            ├ 走动遇敌 → 回合制卡牌战
            ├ 打碎光源 → 掉金币／拾取卡
            ├ 宝箱 → 宝石／进化触发
            └ 每层找铲子 → 挖通下层 → 末层 Boss
                └→ 打完可继续留下挑战「腥红死神」(RedDeath, HP 1,000,000)
  └→ 回村：金币买永久强化、达成条件解锁新角色／卡／宝石／地牢
```

- 地牢表 `AllDungeons`：31 条，字段含 `GenerationConfig`／`_difficultyRating`／`BonusCoins`／BGM 组——**地牢是数据驱动生成的**（另有 `DungeonGenConfig` 373KB 的生成规则）。
- 敌人 `EnemyDatabase`：140 条，其中 `IsBoss=1` 共 60 条。最高血量档：`EnderEliteP1` 225,000 / `EnderEliteP2` 115,000 / `TrinacriaElite` 100,000。
- 死亡与重开：`runModeConfig` ＋ `gameOverScreenConfig`；无「路线分支地图」概念。

## 2. 战斗骨架

### 2.1 回合与资源

| 项 | 值 | 字段 |
|---|---|---|
| 初始生命 | 50 | `PlayerConfig.baseHealth` |
| 初始法力 | 2 | `baseMana` |
| 每回合基础发牌 | 3 | `baseDealCount` |
| 手牌上限 | 可由商店 Handsize 提升（2500 金 ×2 档，+1/档） | `PowerUpDatabase.Powerups` |
| 法力上限 | 1,000,000（等于无上限，靠牌组自限） | `maxMana` |
| 复活上限 | 3 | `maxRevival` |

属性轴（`PlayerConfig` 全套，均为 0 起）：`might`（伤害）／`area`（范围）／`amount`（弹数）／`duration`（持续）／`growth`（经验）／`greed`（金币）／`luck`／`recovery`／`armor`／`magnet`／`revival`／`curse`／`charm`／`scavenge`。每个都有 `max*` 与 `*Decay`（衰减，默认 0）。

### 2.2 连击（Combo）——唯一的核心机制

- **触发**：打出法力**严格大于**上一张的卡。同费不连（mod 里 `GetNextHigherMana` 用的是 `mana > currentMana`，非 `>=`）。
- **倍率**：连击层数即倍率，第 n 张牌吃 ×n。**一层一层累加，不是指数**（`DamageEffect.GetDamageDescriptionValue(..., mult, ...)` 以 `mult` 直接缩放）。
- **谁能吃到倍率**：卡上一个布尔 `ReceivesComboMultiplier`。184 张里 16 张为 0（＝不吃倍率）：全部 9 张 `CardType_Void`（金币／拾取类）＋ 部分 Debuff 与工具牌。
- **免费卡**：`FreeToPlay` 布尔独立于费用——0 费 ≠ 免费卡。免费由宝石／效果在运行时赋予（设计上：免费卡是「不花法力也能延长链条」的专用件）。
- **保留**：`_hasRetain`，全库仅 1 张（`Card_AngeloSpietato`，一张「在手则出牌自伤」的 Debuff）——保留在本作是**稀有的负面载体**，不是常规资源。
- **UI 上的连击语言**（`cardTextConfig`）：费用与描述在连击态切 **Orange Glow 材质**，不可支付切 **Grey 材质**，debuff 切 **Red Glow**——**用材质辉光而不是数字/图标表达状态**，这是它卡面信息密度的关键手法。

### 2.3 卡型与颜色

`cardType` 六类，与攻略站说的四色对应：

| 类型 | 数量 | 颜色语义 | 费用分布 |
|---|---|---|---|
| `CardType_Attack` | 64 | 红（攻击） | 0:17 / 1:11 / 2:15 / 3:11 / 4:8 / 5:2 |
| `CardType_Special` | 50 | 黄（特殊：抽牌／强化／金币） | 0:21 / 1:12 / 2:14 / 3:3 |
| `CardType_Mana` | 13 | 紫（回蓝／降费） | 0:5 / 1:3 / 2:1 / 3:1 / 4:2 / 5:1 |
| `CardType_Defense` | 12 | 蓝（护甲） | 0:2 / 1:4 / 2:3 / 3:1 / 4:1 / 6:1 |
| `CardType_Void` | 9 | —（金币／拾取，全 0 费，全不吃倍率） | 0:9 |
| `CardType_Debuff` | 6 | —（在手即生效的负面） | 0:3 / 1:1 / 5:2 |
| `CardType_Character` | 30 | —（角色卡，0～1 费） | 见下 |

**颜色不是 UI 分类，是触发键**：角色卡（`FCC_*`）在「打出对应颜色的卡」时触发效果。这就是为什么同一张武器卡在不同队伍里价值不同。

### 2.4 费用曲线（全卡 184，含测试卡）

| 费 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 张数 | 66 | 51 | 33 | 17 | 11 | 5 | 1 |
| 占比 | 35.9% | 27.7% | 17.9% | 9.2% | 6.0% | 2.7% | 0.5% |

**这是整套设计的支点**：**63.6% 的卡在 0～1 费**——低费不是「弱牌」，是链条的**起手燃料**。高费（4+）只占 9.2%，是链条终点。任何一张 2 费「桥梁」缺失，整条链就断在 1→3。

| 项 | 值 | 字段 |

### 2.7 卡裂（Card Crack）——消耗型压力

`cardCrackConfig`：`timesPlayedToStartCracking=2`、`chanceToBreak=1` → **打出第 3 次必碎**（碎裂后离组）。配套动画：抖动 0.2s ＋ 屏幕震动（Amplitude 1／25Hz／0.1s）。这给「关键牌反复用」加了时间成本，是它的另一种容量稀缺。

### 2.8 敌人侧

- 字段族：`BaseHealth`／`Xp`／`EnemyDifficulty`／`KnockbackResistance`／`DisarmResistance`／`InstakillResist`／`_maxHit`／`_maxArmor`／`_woundChance`／`_dungeonTags`／`_enemyTypeTags`／`PossibleChestTiers`。
- 即：**击退／缴械／秒杀三条抗性轴 ＋ 命中上限 ＋ 护甲上限 ＋ 致伤概率**。多层抗性用来防「单一解场牌通吃」。
- 意图（intent）有独立配置 `enemyIntentConfig`（图标锚 enemy 头顶、`z=-0.6`、`scale=1.05`）——**敌人意图是显式的**，玩家可预读。
- `overkillConfig`：只对 Boss 生效（`onlyOverkillBosses=1`），溢出伤害转金币，伤害上限 5000（Ultra Overkill 档 500,000／金币上限 5000）——一个「打完还继续打」的经济彩蛋，靠遗物解锁。

## 3. 数值锚（可拿去做我方曲线的对照）

| 项 | 它的值 | 备注 |
|---|---|---|
| 起始卡组 | 5 张（27 套，其中 25 套正好 5 张） | `AllDecks`：1 角色 ＋ 4 功法，如 Antonio＝`FCC_Antonio, Whip, Whip, Armor, Spinach` |
| 经验曲线 | base 5；每 5 级段递增 +2（0-5 级每级 +10，45-50 级每级 +28） | `PlayerLevelConfig` |
| 升级三选一 | 可选 skip（换经验）／reroll／banish，三者各由商店强化给次数 | `PowerUpDatabase`：Skip 250×5(+2)、Reroll 250×5(+2)、Banish 300×5(+2) |
| 商店 20 项定价 | 250～4000 | 见 §4.2 |
| 一箱金币 | 100-150／150-300／300-500（按箱档） | `treasureChestConfig.coinsMinMax` |

**一条对我方直接有用的比例**：它的 `Might`（伤害）每档 +20%、5 档 ＝ +100%；`MaxHealth` 每档 +10%、5 档 ＝ +50%；`Armor` **每档 +1 点固定值**、3 档。也就是说——**百分比堆伤害、固定值堆护甲**。固定值护甲在低数值段极强（起手 0 护甲、敌人一击十几点），这是它护甲牌只有 12 张却关键的原因。

## 4. 局外层

### 4.1 遗物 25 件（`RelicDatabase`）

按功能分四组，**注意其中「开系统」类才是真正的进度锁**：

| 组 | 遗物 |
|---|---|
| 开系统（关键） | **Combo Stack**（赋予连击规则）／Gem Hammer（解锁镶宝石）／Stardust Anvil（解锁铁匠铺）／Lapidary Loupe（解锁珠宝台）／Polentír（解锁占卜师秘法帐篷）／Grim Grimoire（暂停菜单显示已发现的进化与合成）／Rusty Key（旅店）／Deck Box（牌组盒） |
| 信息 | Guiding Light（小地图标可破坏光源）／Milky Way Map（小地图显示敌人）／Yellow Sign（暂停全图）／Rilevatore（显示武器将如何影响目标）／Possessed Sneakers（自动导航到 Boss）／Sorceress' Tears（地图加速键） |
| 经济／爽点 | Overkill（对已死 Boss 续打掉金币）／Ultimate Ultra Overkill（解除 Overkill 上限）／Ovenkilt（任何遭遇都能 Overkill）／Bomba Infernale（已清过的地牢首层瞬清）／Rage Virus（大幅增伤＋自动出牌） |
| 变体规则 | Brave Story（升级选项随机化）／Darkasso（加入 Darkana 事件）／Arcana Finder（地牢加秘法箱）／Randomizer（起始卡组与掉落全随机）／Crawlers Tutorial |

### 4.3 秘法 12 条（二手来源，仅记机制意图）

链环（倍率跨回合保留）／法力虹吸（单回合获 15+ 法力 → 永久法力成长）／敏锐头脑（未用法力留存到下回合）／Wild 强化（打碎光源掉的卡计入）等。**共同点：全都在改「链条的连续性」**——保留倍率、保留法力、扩大免费卡来源。二手数据，未核一手。

## 5. UI 与手牌系统（全部取自 `GlobalConfig` 一手字段）

这是它做得最扎实的一层，也是本项目可直接对位的部分。**它的做法＝把「手感」全部外置成配置数值**，而不是散在代码里。

### 5.1 手牌

| 项 | 值 | 字段 |
|---|---|---|
| 卡间距 | 14 px | `handPileConfig.cardSpacing` |
| 自动重排延迟 | 0.5 s | `defaultCardReorderDelayTime` |
| 长按切排序方式 | 0.3 s | `cardSortConfig.holdDurationToChangeSortMethod` |

### 5.2 悬停（最重要的一组）

| 项 | 值 |
|---|---|
| 放大 | **×1.5**（`hoverCardConfig.scaleTo`），0.05 s |
| 抬升 | +38 px（`hoverHeightOffset`） |
| 倾斜 | 跟手 0.7 幅度／静止时自动 4° 摆动 |
| 可打出时 | ×1.2 曲线脉冲（`hoveringPlayablePositionScaleMultiplier`） |
| 不可打出时 | 只放大 ×1.05，抬升 +15，**抖动 5 幅度／0.3 s／15 振动** |

> 对照我方现行制：手牌悬停「弹内层卡面 ×1.25、外层壳不动」。它用 **×1.5 ＋ 38px 抬升 ＋ 倾斜**，且把「不可打出」做成一套独立的**小幅＋抖动**语言——这套「可打／不可打」双态在悬停层就分开，比我方只有弹起要清楚。**可借点：不可打出态的抖动反馈。**

### 5.3 抽／弃／移动

| 动作 | 数值 |
|---|---|
| 抽牌 | 从 `(-55, 180, -90)` 度翻转进来，0.2 s，抽完等 0.2 s |
| 弃牌 | 转到 `(55, 180, 90)`、缩到 0.2、移速 250、减速 0.5，弃完等 0.15 s |
| 卡移动 | 移速 500、减速 10；回手跳跃高 500（0.25 s 升 / 0.05 s 顶停 / 0.4 s 落） |
| 补牌堆 | 0.3 s／次，间隔 0.05，跳幅 -50～200 |

**读法**：抽牌走「翻转」、弃牌走「旋转＋缩小」、回手走「抛物线跳跃」——**三种动作三种空间语义**，玩家不用看字就知道卡去哪了。我方目前缺「回手／弃牌」的方向性动作。

### 5.4 连击堆（ComboPile）——它最有戏的一层

| 项 | 值 |
|---|---|
| 卡举起 | ×2 缩放，0.5 s |
| 砸下 | 0.1 s，急停缓动（ease 26） |
| 粒子 | 10 → 100,000，每层 +100 |
| 屏幕震动 | 0.1 幅度／30 Hz／0.1 s |
| 火焰 | 连击堆火焰 + 卡面火焰（`enableComboPileFlame` / `enableCardFlames`） |
| 阴影回位 | 0.3 s |

**这是「倍率」的物理表达**：每接一张，牌被举起两倍再砸下，粒子与震动按层数线性增长——**数值增长 ＝ 屏幕暴力增长**，不需要数字跳字。对我方「威力轴」的呈现是直接可借的范式。

### 5.5 卡面结构与角标

mod 反射出的真实层级（`BetterCards`）：

- `CardView` 子节点：`Front`（正面根）／`CardHighlight`（原生高亮）／`_costText`（左上费用 TMP）
- 另有 `CardSelectionCardView`（升级三选一用的选择态卡），带 `_manaCostText`
- 卡面配置：`CardView._appliedCardConfig`（即 `CardConfig`），费用走 `CardConfig.GetManaCost()`，免费判定走 `CardModel.IsCardFreeToPlay()`

**角标做法（可直接借的工程手法）**：mod 要在卡上加徽记，做法是——把自己造的 `RectTransform` **挂成 `_costText` 的兄弟节点**，镜像 X 到右上角。理由（源码注释原话）：费用文本**永远**在左上，用它当锚点就能自动继承「UI canvas / worldspace canvas / sprite worldspace」三种坐标系，不用判断卡是 2D 还是 3D 摆放。另加 `CanvasGroup(interactable=false, blocksRaycasts=false)` 保证不吃点击，并把 `Image.raycastTarget=false`。

> 这对我方 `QiCardStyle` 的「左上能量点／右上留空」是同一类问题：**右上留空位如果要放角标（升一/升二、锁定、NEW），锚点应挂能量点的兄弟并镜像**，而不是另算一套坐标。

## 7. 对本项目的判断

### 7.1 可借（按优先级）

1. **费用阶梯＝把「排序」变成资源**。我方现在的短板是「横向 combo 为零」。它的解法不是加配对卡，而是**给序列本身定规则**：前面打的牌给后面打的牌供能。这跟我方「A+B 效果大于各自之和」是同族，但实现成本低得多——不需要两张卡互相认识，只需要一个全局顺序规则。
2. **连击的物理表达**（举起 ×2 → 砸下 → 粒子/震动按层数增长）。我方威力轴目前靠数字与徽记，缺这套「不看数就知道叠了几层」的语言。
3. **不可打出态的抖动**（5 幅度／0.3 s／15 振动）——比纯灰化更明确。
4. **角标锚点挂能量点兄弟、镜像到右上**（§5.5），直接可用在工厂卡面的右上留空位。
5. **三条件进化的阀门**（配方＋空孔＋触发点）：我方若做「两卡合成」，孔位这道额外成本可以防「凑齐就必出」。

### 7.2 不可借（与我方定位冲突）

- **肉鸽局外成长**（村庄／20 项永久强化／遗物解锁系统）——本项目定位是卡牌构筑，不是 roguelike deckbuilder（用户 2026-10-30 裁定）。
- **第一人称地牢探索**——两屏布局已定死。
- **TurboTurn 实时排队出牌**——它的卖点是「不等动画」，我方是回合制卡牌战，接这套等于换引擎语义。
- **卡裂（打出 3 次必碎）**——那是为「反复用同一张」设的软上限；我方容量稀缺走的是卡组容量，不需要第二套消耗制。

### 7.3 待裁（未定，勿擅自落地）

- 是否引入「法力／威力升序」类顺序约束作为 combo 的骨架（这是本档最重要的一条待裁）。
- 是否引入「颜色触发」（器灵对应某色功法）——它靠颜色把角色与牌组绑定，我方器灵与功法已经是绑定关系，颜色可能是冗余轴。
- 连续击层数是否给「保留到下回合」的例外（对应它的链环秘法）。
