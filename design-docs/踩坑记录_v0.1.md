# 踩坑记录 v0.1（2026-11-05）

## 1. 按钮“不居中”反复错
- 现象：按钮文字在护手槽里总是偏下，调位置也修不好。
- 根因：**文字是在按钮矩形里居中的**。按钮矩形（44px 高）比护手**镂空**（约 35px 高）大，
  文字按矩形中心排，就落在镂空中心下方；只改矩形位置（top/bottom 一起平移）不解决，
  因为矩形比洞高，无论怎么移都不对齐。
- 正确做法：**按钮矩形 = 可见镂空本身**（本例 267–406 × 827–857），文字自然落在洞心。
- 教训：嵌槽的控件要按“**洞**”定尺寸，不是按“**外框/带**”定尺寸。

## 2. 场景 .tscn 改动后解析失败
- 现象：Godot 起不来 / 卡住，日志报 `Parse error [Resource file ...tscn:NNN]`。
- 根因：①`ExtResource("xx")` 用了未声明的 id；②节点块之间缺空行。
- 教训：手改 tscn 后必查——每个 `ExtResource` 有对应 `[ext_resource]`、每个 `[node]` 前有空行。

## 3. 资源改了游戏里没变
- 根因：贴图走 `.import` 时，覆盖 PNG 不会自动重导入。
- 做法：改图后跑一次 `godot --headless --import`；或走运行时 `Image.load_from_file`。

## 4. “牌堆被切”误判
- 根因：用旧配置（堆高 92、数字在下）的结论推断新状态，没复测。
- 教训：位置/裁切类结论必须**看当前截图或量像素**，不能凭历史配置推断。

## 5. 改 tscn 字体不生效
- 现象：把卡堆数字的 `theme_override_font_sizes/font_size` 从 22 改到 68/110，截图完全没变。
- 根因：**运行时代码又覆盖了一遍**——`QiVcCabinet.gd` 里 `QISTYLE.font(c, 22, true)` 给 DrawCount/DiscardCount 统一设字，tscn 的值被盖掉。
- 教训：改样式不生效时，先搜同名节点在代码里的 `QISTYLE.font/text_color` 覆盖点；**tscn 与代码两处都要改**，或把代码改成读 tscn。

## 6. 手改 tscn 的重复属性
- 现象：块里出现两组 `layout_mode/offset_*`，解析或取值异常。
- 根因：正则只替换了块头一部分，旧块尾巴留在后面，后写的重复键生效。
- 教训：改节点一律**整块替换**（从 `[node` 到下一个 `[node`），改完 grep 一遍重复键。

## 7. 气珠轨道与吸入（2026-11-06，一整轮返工换来的）

### 7.1 「闪一下」的三种真因（都踩过）
- **层级掉档**：飞行粒子挂在屏幕根（z 0）下设 91 → 绝对 91；并入后挂到轨道（z 66）下设 2 → 绝对 68。并入那一帧整颗往下掉 23 层。
  - 教训：**跨父节点交接时，按「绝对层级」对齐**，不要按子节点 z 值对齐。
- **透明度清零**：飞行段透明度走 `sin(t·π)`，终帧正好为 0；并入后有一段「落位」期跳过了透明度更新，于是 0 一直挂着 → 看起来是「飞进去然后消失」。
  - 教训：接管期也要每帧维护可见属性，别只维护位置。
- **拖尾滞留**：到站后拖尾还保留 0.12 秒（点已不再更新，是一条定住的亮线）。
  - 教训：拖尾透明度要在行程末尾就收到 0。

### 7.2 「吸附感 / 停顿感」的真因
- 末段**径向**插进环 → 速度方向指圆心，而轨道是切线，差 90°，并入必然改向。
- 修法：**捕获螺旋**（一个函数，不是拼接）
  `f(θ) = 1 + (f0−1)(1−u)²`，`f` 是相对轨道半径的倍数
  - `f ≥ 1` 恒在环外；`f'(u=1)=0` → 接点切线＝轨道切线（C1，无折角）
  - θ 单调递增 → 全程顺时针（用 `wrapf(..., 0, TAU)` 保证，别用 `-PI..PI`）
  - `θ > θ₁` 直接取 `f=1`，自然等于环绕轨道本身（末半圈完全重合）
- 速度也要对齐：飞行时长按**路径长度自适应**（`dur = len/760`），末端速度＝轨道线速度（`SPIN × 70px`），用三次多项式 `p(u)` 锁两端速度。

### 7.3 跨度太短的「钩子」
- 半径从 4.6 倍收到 1 倍，若只给 30° 角度行程，曲率半径会掉到 **3px**（肉眼就是折角）。
- 教训：**跨度 < 120° 就加整圈**（`span += 2π`），把收缩摊到更长角度；120° 时曲率半径约 30px，200° 约 39px。

### 7.4 不重叠
- 「按角度排序后重排槽位」会因 0/2π 接缝错位而横穿（看起来逆行/重叠）→ 改为**邻居间距松弛**：`spd = V_NORMAL − (gap_behind − gap_ahead)·GAIN`。
  - 符号别写反：后面空得多要**减速**等人（写成加速会正反馈聚堆，实测 `2.44,2.44,2.44`）。
- 只许减速（`V_MAX = V_NORMAL`）时收敛较慢；把「最慢」抬太高会显得卡住。
- 最后一道保险：每帧把速度钳到 `(gap_ahead − MIN_GAP)/delta` 以内。

### 7.5 其他
- `for k in 1..12:` 不是合法区间，GDScript 要用 `range(1, 13)`。
- 飞行终点**不要加随机抖动**，否则并入时会有一两像素的位移。
- 速度变化本身也要平滑（`lerp(prev, target, delta*5)`），否则「速度突变」看着像「位置跳」。

## 2026-11-08 · 方向性错误（用户点名：「你老是有方向性的错误」）

- **现象**：浮窗跟随卡面倾斜时，横向对、**纵向反了**。指针往上滑，浮窗反而往上跑；按 3D 语义它该往下收（上边框后退＝远离观者）。同一轮之前还有一次更大错：把 `tip`（归一化 ±0.5）当像素位移用，`tip × 半宽` 算出 95px，实际 shader 只位移 **7~8px**——量级错 12 倍。
- **根因**：凭直觉写"跟随/位移"，没有先把公式写出来代入极值验方向与量级。
- **医嘱（后续所有位移/跟随类改动）**：
  1. 先写出位移公式（有 shader 就从 shader 反解），**代入极值算出数值**，再动手；
  2. 先问一句「变大还是变小、向内还是向外」——**近大远小**是唯一基准：指针移到某侧＝该侧靠近观者＝该侧边框**变大/外扩**，对侧后退＝**变小/内收**；
  3. 纵向基准：指针往上＝上边框后退＝顶边**下收**；指针往下＝顶边**上抬**。横向按同一逻辑验一遍再写；
  4. 量级先对：7px 的位移用 95px 去跟，怎么调方向都是错的。


## 2026-11-08 · 一个 `#` 毁掉整条链路（Shader 编译失败引发的一连串"假 bug"）

- **现象（用户视角，看起来是四件互不相关的事）**：
  1. 卡牌跟着鼠标**倾斜的动效没了**；
  2. 指针在卡内**靠近边缘**时，悬停态被取消、卡缩回、浮窗消失；
  3. 卡牌**左上角一直发亮发白**（金框变成一条米白亮线）；
  4. 放大看有锯齿。
- **真实根因（一条）**：为修锯齿往 `card_tilt_glint.gdshader` 加注释时用了 `#`（GLSL 只认 `//`）：
  ```
  SHADER ERROR: Tokenizer: Unknown character '#'  (card_tilt_glint.gdshader:17)
  ERROR: Shader compilation failed.
  ```
  shader 整个不编译 → 卡面退回**无 shader** 渲染（不再透视变形、边缘直出）。
  于是：倾斜消失；而命中判定 `_card_face_corners` **仍在按 shader 的斜切公式补位移**——视觉是正的、判定是斜的，两套几何对不上，指针一到边缘就被判"出去了"；顶部那条"白亮线"其实是**无 shader 时贴图边缘直出**。
- **为什么排查了十几轮才找到**：跑图时只 `grep SCRIPT ERROR`，**没 grep `SHADER ERROR`**。这两类错误分开报，脚本层全绿、shader 层早就红了。
- **医嘱（后续所有改动）**：
  1. **跑图过滤必须同时含 `SHADER ERROR`**：`grep -E "SCRIPT ERROR|SHADER ERROR|compilation failed"`；
  2. 任何"视觉突然不对 + 交互跟着不对"同时出现时，**先查 shader 编译**，再怀疑逻辑——一个 shader 挂了会产生一堆看起来无关的症状；
  3. GLSL 注释只用 `//`，**禁止 `#`**；
  4. `textureSize(TEXTURE, 0)` 在 canvas_item 里可能返回 0——不要用它算像素尺度，改用固定 UV 常数或从 GDScript 传 `uniform`；
  5. 给材质设参数前**核对 uniform 名字**（本项目同时存在 `strength`（tcg_glint）与 `glint_strength`（card_tilt_glint）——名字写错不会报错，只会"改了没反应"，白查很久）；
  6. **不要把 shader 材质挂到带子节点的容器上**（`Panel` 里套 Label），会让整块重绘、alpha 被改写；要发光就挂叶子层。

### 当前遗留（明确挂账）
- **金色光效仍处于关闭状态**：`tcg_glint.gdshader` 的 `strength` 默认值与 `card_tilt_glint.gdshader` 的 `glint_strength` 都已置 0（用户当前要的是"先看基础形态"）。
- 恢复时必须一并做：①**参数名按各自 shader 写对**；②加**限幅** `clamp(amt, 0.0, 0.42)`（此前无上限，R/G 通道顶到 255 变成"发白"）；③改完**先确认 shader 编译通过**再看效果。

## 2026-11-08 · 多把飞剑「先到的停住等后到的」

- **现象**：连环刺打出 5 把刀，敌人已被打死、余下两把无目标飞向右侧；第一把到了**停在原地不动**，等第二把到了才**一起消失**。
- **根因**：`QiCombatFx.scabbard_strike` 用**一个统一时钟**驱动全部刀的位移，而"淡出＋释放"挂在 `clock.tween_callback`（整段结束才跑一次）。先到的刀位置停了，但销毁要等全段走完。
- **修法**：给每把刀挂**自己的**定时器——按它的出发时刻＋飞行距离算出到位时间 `arrive_i`，到点直接 `queue_free()`（用户令：不做淡化）。统一时钟只负责位移。
- **通用规则（已升级为 AGENTS 硬规·多发单位生命周期制）**：多把刀／多支箭／多段命中，**每个单位自己的生命周期自己管**；禁止用总时钟的结束回调统一销毁；空放单位同样到位即消失。
