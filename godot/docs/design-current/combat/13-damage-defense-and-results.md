# 伤害、防御与对战结果

> 本文件是当前 v0.30 模块化权威设计源的一部分。原文规则段落仅在此处维护；
> 其他模块只能通过链接引用，不得复制或重新解释。原章节编号保留用于迁移核对。

## 9. 对战结果

牌型基准值不是分数，也不是本次行动自动造成的伤害。出牌只计算牌型基准值与功法值；只有功法、内功或毒状态明确写出造成伤害时，才执行伤害结算。它们可以读取牌型基准值或功法值，并产生：

- 伤害或额外伤害；
- 防御；
- 抽取、弃掉、锁定、夺取或回收真气；
- 其他明确写出的战斗效果。

高牌的基础功法可以写成“造成等于本次功法值的伤害，并获得等于本次功法值的防御”，但这只是该门功法的效果，不是高牌或所有牌型的默认规则。

敌人的攻击也应由它当前组成的普通牌型和已装备效果产生，不能退回固定的“攻击值／防御值”两个数字。

防御是功法或内功的效果，不是独立的牌型，也不是某种真气属性的公共效果。

防御可以跨回合并在多次出牌中累积。受到伤害时，先从防御中扣除；伤害超过当前防御的部分才扣生命。若伤害没有耗尽防御，剩余防御继续保留。

每个完整回合的全部行动结算完成后，双方先各自保留当前防御的 50%，并统一向下取整：`defense = floor(defense × 0.5)`。因此 1 点防御变为 0，3 点变为 1，5 点变为 2。该衰减每方每个完整回合只执行一次，不能按玩家与敌人的单独行动重复执行。随后才结算延迟效果、状态、山觉醒以及其他“回合结束时”效果；这些效果在本次回合结束阶段新获得的防御不参与刚刚完成的衰减。例如原有 20 点防御、随后由山觉醒获得 8 点防御时，最终为 `floor(20 × 0.5) + 8 = 18`，不是 14。战斗结束时防御清空。

50% 是没有其他效果介入时的默认**防御保留比例**，不是写死在具体功法、内功或物品 ID 上的内容分支。未来内功、物品或其他明确效果可以写出“回合结束时额外保留 X% 防御”或“防御不会因回合结束而衰减”：额外保留比例在默认 50% 上相加，最终限制在 0%～100%，全部比例合并后只向下取整一次；“不会衰减”将最终保留比例设为 100%。效果默认只影响其持有方，除非正文明确写出影响双方或敌方。具体内容必须通过统一的防御衰减规则接口修改保留比例，不得绕过公共回合时点直接按内容 ID 改写防御。

当前不设置全局防御上限；默认保留比例与具体内容修正仍需在后续试玩中继续校验数值，但上述结算时点与取整方式作为公共规则保持一致。

普通伤害的持续规则顺序固定为：基础伤害 → 现有状态百分比 → 攻击方 `outgoing_damage_query` → 受击方 `incoming_damage_query` → `floor/max(0)` → 防御与生命承伤 → `damage_resolved`。预览可以纯查询预计值，但每条实际伤害记录只在写入前按最新状态重新查询一次。同步伤害的 shadow 既不查询动态伤害被动，也不发送事件；只有 `flush_synchronized_damage()` 的真实写入逐条完成后才发送 `damage_resolved`。真实伤害继续绕过普通伤害百分比、防御与上述两个普通伤害查询，实际写入后仍发送带 `true_damage` 标志的结果事件。

所有正式防御增加统一执行：请求值 → `defense_gain_query` → `max(0)` → 写入防御 → `defense_gained`。请求为 0 或有效增加为 0 时不发送事件。回合结束保留率统一执行：基础 50 → `defense_retention_percent_query` → 限制到 0%～100% → `floor(defense × percent / 100)`；完全不衰减由 Handler 返回有效值 100 表达，中央流程不得按内容 ID 分支。伤害、防御或保留率查询失败必须发生在对应写入前：不造成伤害、不增加防御，或保留原防御不衰减。

### 反震

反震是角色当前持有的一个百分比状态，不使用层数。效果写出“获得 50% 反震”时，直接令当前反震比例变为 50%；以后获得 40% 反震时，当前比例改为 40%，不与旧值相加，也不取最高值。

当敌方效果实际使我方防御减少 `D` 点时，在本次防御减少完成后，对敌方造成：

```text
反震伤害 = floor(D × 当前反震比例)
```

每次防御减少分别读取当时最新比例。例如第一次减少 10 点防御且当前反震为 50%，造成 5 点反震伤害；随后反震被改为 40%，第二次减少 10 点防御时造成 4 点。只读取实际减少的防御，不读取被防御挡住前的攻击值，也不读取生命损失。反震造成普通伤害，但不能触发任一方的反震，避免递归。

反震比例默认在战斗结束时清除；具体内容可以明确写出更早的覆盖或结束时点。旧“反击／借力”不再是公共受击资源，历史内容若需要迁移，应改写为反震或直接的延迟伤害效果。
