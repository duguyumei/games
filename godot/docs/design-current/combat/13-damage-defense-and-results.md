# 伤害、防御与对战结果

> 本文件是当前 v0.30 模块化权威设计源的一部分。原文规则段落仅在此处维护；
> 其他模块只能通过链接引用，不得复制或重新解释。原章节编号保留用于迁移核对。

## 9. 对战结果

牌型基准值不是分数，也不是本次行动自动造成的伤害。出牌只计算牌型基准值与功法值；只有功法、内功或毒状态明确写出造成伤害时，才执行伤害结算。它们可以读取牌型基准值或功法值，并产生：

- 伤害或额外伤害；
- 防御；
- 抽取、弃掉、锁定、夺取或回收真气；
- 其他明确写出的战斗效果。

高牌的基础功法可以写成“造成等于本次功法值的伤害，并获得等于本次功法值的防御”，但这只是该门功法的效果，不是高牌或所有牌型的默认规则。

敌人的攻击也应由它当前组成的普通牌型和已装备效果产生，不能退回固定的“攻击值／防御值”两个数字。

防御是功法或内功的效果，不是独立的牌型，也不是某种真气属性的公共效果。

防御可以跨回合并在多次出牌中累积。受到伤害时，先从防御中扣除；伤害超过当前防御的部分才扣生命。若伤害没有耗尽防御，剩余防御继续保留。

每个完整回合的全部行动结算完成后，双方先各自保留当前防御的 50%，并统一向下取整：`defense = floor(defense × 0.5)`。因此 1 点防御变为 0，3 点变为 1，5 点变为 2。该衰减每方每个完整回合只执行一次，不能按玩家与敌人的单独行动重复执行。随后才结算延迟效果、状态、山觉醒以及其他“回合结束时”效果；这些效果在本次回合结束阶段新获得的防御不参与刚刚完成的衰减。例如原有 20 点防御、随后由山觉醒获得 8 点防御时，最终为 `floor(20 × 0.5) + 8 = 18`，不是 14。战斗结束时防御清空。

50% 是没有其他效果介入时的默认**防御保留比例**，不是写死在具体功法、内功或物品 ID 上的内容分支。未来内功、物品或其他明确效果可以写出“回合结束时额外保留 X% 防御”或“防御不会因回合结束而衰减”：额外保留比例在默认 50% 上相加，最终限制在 0%～100%，全部比例合并后只向下取整一次；“不会衰减”将最终保留比例设为 100%。效果默认只影响其持有方，除非正文明确写出影响双方或敌方。具体内容必须通过统一的防御衰减规则接口修改保留比例，不得绕过公共回合时点直接按内容 ID 改写防御。

当前不设置全局防御上限；默认保留比例与具体内容修正仍需在后续试玩中继续校验数值，但上述结算时点与取整方式作为公共规则保持一致。

普通伤害的持续规则顺序固定为：基础伤害 → 现有状态百分比 → 攻击方 `outgoing_damage_query` → 受击方 `incoming_damage_query` → `floor/max(0)` → 合格直接攻击依次查询卸力来源 → 格挡来源 → 计算防御实际吸收量与预计生命损失 → `pre_life_loss_query` → 一次提交防御与生命 → `damage_resolved` → 反震及后续响应。预览可以纯查询预计值，但每条实际伤害记录只在写入前按最新状态重新查询一次。同步伤害的 shadow 只读取攻击取消公开投影，不查询动态伤害被动或生命干预，也不消费来源或发送事件；只有 `flush_synchronized_damage()` 的真实写入按稳定伤害段顺序完成。真伤继续绕过普通伤害百分比、防御与上述两个普通伤害查询，但属于直接攻击段的真伤仍在扣除生命前接受同一卸力／格挡解析；未被取消的真伤与普通、毒、反震伤害共用生命写入前查询，并在写入后发送带 `true_damage` 标志的结果事件。

通用 `damage` 操作具有 `blockable` 字段，默认 `true`。`blockable=false` 同时跳过卸力与格挡查询，
不跳过伤害增减、防御吸收、反震或其他伤害事件，也不建立专用伤害端口。格挡来源条件使用
统一 `ConditionSpec`；角色对象不得为每种新条件增加字符串分支。

毒伤是由毒状态或明确写出“毒伤”的效果造成的独立伤害类型。毒伤完成自身固定值与百分比修正后，默认先由普通防御吸收，超过当前防御的部分才减少生命；但毒伤不等同于普通伤害或真伤，不读取普通伤害增减查询，也不能被卸力或格挡取消。毒伤实际减少防御时正常产生`damage_absorption`防御减少事实，但明确不能触发反震。内容不能用“普通伤害”或“真伤”代替“毒伤”。

毒伤的固定值与百分比修正使用独立公共流程，不借用普通伤害查询：设单个毒伤段基础值为 `B`，先汇总该段合格来源的固定修正 `F`，得到 `max(0, B+F)`；再汇总百分比修正 `R`，得到 `floor(max(0, B+F) × (100+R) / 100)`；随后以该最终毒伤值作为默认可被防御吸收的上限，经`poison_defense_intervention_query`允许来源缩减该上限，再一次提交防御与生命变化。默认不限制固定值、百分比或来源数量。带有限次数的来源按冻结的毒伤段稳定顺序逐段消费。

同时触发多张毒牌时，每张牌仍是独立毒伤段。系统必须先对每段分别应用固定与百分比修正，再合计为同步生命写入；不能先合并基础毒量后只应用一次修正。因此“每次毒伤 +1”在三张毒牌同时触发时会生效三次，而不是只令合计值 +1。毒伤修正来源至少公开固定值、百分比、影响阵营、剩余次数、到期时点与稳定来源令牌；中央毒流程不得按提供来源的功法或内功 ID 分支。

所有正式防御增加统一执行：请求值 → `defense_gain_query` → `max(0)` → 写入防御 → `defense_gained`。请求为 0 或有效增加为 0 时不发送事件。回合结束保留率统一执行：基础 50 → `defense_retention_percent_query` → 限制到 0%～100% → `floor(defense × percent / 100)`；完全不衰减由 Handler 返回有效值 100 表达，中央流程不得按内容 ID 分支。伤害、防御或保留率查询失败必须发生在对应写入前：不造成伤害、不增加防御，或保留原防御不衰减。

所有防御减少统一经过公共端口，并明确携带 `cause`；至少包含
`damage_absorption`、`direct_effect`、`cost`、`decay` 与 `reset`。端口先冻结目标与请求量，
按 `amount` 或 `all` 计算实际减少值，再写入并发送一次 `defense_reduced`。`remove`、`set`、
`clear`、`consume`、自然衰减与战斗重置都只改变防御并发送对应事件，不直接触发反震。
效果可以捕获实际减少量，但 Handler 不得直接写角色 `defense` 字段。

### 生命写入前干预

`pre_life_loss_query`是防御实际吸收已经计算完成、生命尚未写入时的唯一来源中立查询。它的
`base_value`等于本段`proposed_life_loss`，请求同时公开伤害段/行动窗口令牌、来源身份、`cause`、
伤害类型、直接攻击/反震/同步标志、请求与最终伤害、防御前值/实际吸收/后值、生命前值和致命标志。
多个来源按既有Invocation顺序读取并改写`current_value`，最终值只能位于
`0..proposed_life_loss`；越界或Handler失败会令该段在防御、生命、事件和日志写入前失败。

- 普通伤害与毒伤都只查询击穿防御后的溢出生命损失；真伤不减少防御；反震明确带
  `reflection_damage=true`、`direct_attack=false`。四者使用同一查询和提交函数。
- `cause=cost`的燃命、支付生命等代价明确跳过干预。战斗初始化、存档恢复、最大生命变化截断、设置或
  清空防御不是生命损失，也不进入查询。
- 生命损失被减为0时，防御实际吸收仍提交并可触发反震；这不是格挡，不发送`damage_blocked`，仍发送
  `damage_resolved`且`life_lost=0`、`life_loss_canceled=true`。
- `damage_resolved`同时公开干预前损失、阻止量、实际损失、取消标志、breakdown、source/request
  fingerprint、伤害段令牌、cause及防御/生命前后事实。统计、邀战、毒/反震结果、条件与ValueSpec只
  使用干预后的实际`life_lost`。
- 查询是纯读，不支付真气或层数。未来代价型保护以`damage_segment_token`将支付事务原子绑定到查询
  结果，不得在Handler内消费来源。

同步伤害flush使用既有BattleSide状态快照、committed-event事务状态与publication transaction，并
同时保存触发队列/结构化日志及行动统计。任一后段查询或其反震失败时，整次flush恢复生命、防御、
被动状态、receipt、execution history、事件序号、待发布通知与日志，返回结构化失败；调用方不得忽略。
同步毒来源也只在flush提交前的同一事务内清除。不存在长期并存的数组flush协议。

### 攻击取消：卸力与格挡

`BattleSurvivalEffectService.resolve_attack_cancellation`是正式战斗唯一攻击取消入口。内部继续复用
`BattleSide.block_sources`字段以兼容既有快照，但每条记录以`cancel_kind=deflection|block`区分类型，
共用`source_token`、`established_order`、目标行动窗口、`waiting_for_action`、到期和恢复协议；卸力另冻结
`threshold=N`。公开DTO分别给出格挡列表与卸力列表，不能把卸力阈值显示成格挡次数。

卸力N只处理`blockable=true`的敌方直接普通／真伤段。设攻击完成自身全部增减后的最终值为A：多个卸力
严格按`established_order`／Invocation顺序检查，不按N排序；每个被检查来源无论成功或击穿都消费。
若A≤N，立即取消整个攻击段并保留后续来源；若A>N，提交击穿结果并继续检查下一个卸力。全部卸力被
击穿后才进入格挡条件。毒伤、反震、自毒、燃命、生命代价及其他非敌方直接攻击既不查询也不消费卸力。

格挡是取消一个敌方直接攻击段的公共效果，不属于特定属性。设一个合格攻击段完成自身伤害增减、尚未进入防御或生命结算时的伤害为 A；满足来源条件的格挡令该攻击段伤害变为 0。

- 格挡可以取消普通伤害或真伤，但不能取消毒伤、反震、自毒、燃命或其他不属于敌方直接攻击段的生命变化。
- 卸力或格挡成功都不减少防御、不减少生命、不触发`pre_life_loss_query`与反震，也不产生
  `damage_resolved`。每次卸力消费提交`deflection_resolved`，以`succeeded/pierced`区分成功和击穿；
  真正取消时另提交一次`attack_canceled(cancel_kind=deflection|block)`。
- 格挡成功继续发送既有`damage_blocked`兼容事件，并同时发送`attack_canceled(block)`；卸力成功只发送
  `deflection_resolved(succeeded=true)`与`attack_canceled(deflection)`，不得伪装成`damage_blocked`。
- 格挡来源只有实际成功时才消耗；条件不满足时保留至自身到期。一个攻击段最多消耗一个来源，多个来源按已经冻结的公共效果顺序查询。
- 正文只写“获得 1 次格挡”而没有另写持续时间时，该来源持续至敌方当前出牌轮次结束；建立时敌方没有正在结算的出牌轮次，则持续至敌方下一出牌轮次结束。
- 每个来源自行定义条件。山系常见条件为 A 不高于持有者当前防御；无条件格挡则不读取防御。
- 格挡查询、消费和成功事件必须由通用端口处理，中央伤害流程不得识别提供格挡的功法、内功或物品 ID。

`deflection_resolved`与`attack_canceled`公开攻击值、伤害类型、伤害段／行动／执行令牌、来源令牌和来源
身份；前者另公开冻结阈值、消费、成功与击穿。来源消费、source changed、兼容／canonical取消事件及最终
伤害处于同一既有伤害事务。任一Handler或同步flush失败时恢复来源、防御、生命、历史、receipt、日志和
触发队列。预览、AI和同步shadow只读投影；只有真实写入／flush可以消费并提交事件。

### 反震

反震对外表现为角色当前持有的一个百分比状态，不使用层数，也不把多个比例相加或取最高值。每个具有持续时间的反震效果在内部建立独立来源；最新建立或最新明确改写的仍有效来源决定当前比例。新来源暂时覆盖旧来源，覆盖不会删除仍在计时的旧来源；当前来源到期或移除时，恢复下一项仍有效的最新来源。

例如第一完整回合建立持续三个完整回合的 50% 反震，第二完整回合又建立只持续该回合的 100% 反震，则三个回合显示为 50% → 100% → 50%，而不是相加、取最高值或在第二项到期后清零。后来获得 40% 反震仍会暂时把当前比例改为 40%，即使被覆盖来源的比例更高。

当敌方普通／真伤攻击段以 `cause=damage_absorption` 实际吸收我方 `D` 点防御时，在本次伤害写入完成后，对敌方造成：

```text
反震伤害 = floor(D × 当前反震比例)
```

每个伤害段分别读取当时当前有效比例。例如第一次伤害吸收 10 点防御且当前反震为 50%，造成 5 点反震伤害；随后当前比例被改为 40%，第二个伤害段吸收 10 点防御时造成 4 点。只读取该伤害段实际吸收的防御，不读取被防御挡住前的攻击值，也不读取生命损失。毒伤即使实际减少防御也明确不触发反震；卸力或格挡成功都没有防御损失，同样不触发反震。直接削防、支付、清空、设置、消费、自然衰减与重置即使来源属于敌方，也不触发反震。反震默认造成普通伤害，但不能触发任一方的反震，避免递归。

### 毒伤段冻结与提交

毒伤修正分为纯查询和幂等提交。`preview`／`freeze_poison_modifier` 只冻结本段适用来源、
固定值、百分比与稳定 receipt，不消耗有限次数；只有该毒伤段成功提交后，才按 receipt
消费 `remaining_hits`。失败、预览、等待选择恢复和同 token 重放不得重复消费。

单张毒触发与同步毒爆共用同一段级管线：冻结毒牌 → 冻结毒伤修正 → 防御吸收上限介入 →
伤害提交 → 按 receipt 消费修正 → 清除毒 → 发送 `poison_trigger_completed`。
同步毒爆只负责同步冻结与同时写入，不复制毒清除或事件结果结构。

`poison_trigger_completed` 是统一 committed 事件，公开该段进入防御吸收前的最终毒伤值、
实际生命损失、来源牌与稳定事件 token。自动条件因此可以同时累积“毒伤次数”和“毒伤总额”，
由任一配置阈值触发并只消费对应批次。

“反震伤害改为真伤”是与比例来源分离的限时修改：它在有效期间作用于当时当前比例产生的全部反震，因此临时覆盖基础比例的 100% 或 150% 反震也会转为真伤。多个同类真伤修改不叠加。

写作“持续三个完整回合”时，建立效果的当前完整回合计为第一个，之后两个完整回合分别为第二、第三个；额外行动不减少持续回合。每个完整回合结束时先完成该回合仍应生效的防御衰减、延迟效果与其他回合结束结算，再减少来源剩余回合并重新选择当前来源。所有反震比例来源与伤害类型修改在战斗结束时清除。旧“反击／借力”不再是公共受击资源，历史内容若需要迁移，应改写为反震或直接的延迟伤害效果。

### 反震响应与邀战

每次实际反震完成后发送结构化 `reflection_resolved` 公共事件，至少包含攻击者、反震持有者、实际防御损失 `D`、当时有效比例、请求伤害、实际生命损失、普通／真伤类型、反震来源令牌和行动令牌。借震生势、震裂、余震、迎浪、震返等效果只能监听此事件，并通过来源令牌和 `max_triggers` 自行消费；中央伤害流程不识别功法 ID。

邀战是独立的行动窗口记录，冻结阈值`Q`、当前累计值`X`、来源令牌、挑战者、目标、目标行动窗口及达标／未达标效果。若敌方当前行动已锁定则绑定当前窗口，否则等待敌方下一次实际行动；主组与全部协同组属于同一窗口，后来取得的额外行动建立新窗口。`X`累计窗口内明确归因于该敌方的实际防御损失与生命损失；格挡、自毒、燃命、主动清空防御和自然衰减不计入。窗口结束时以`X≥Q`判断达标，否则按`Q-X`提供未达标差额；随后发送结构化`challenge_resolved`事件。无合法敌方行动时继续等待，战斗结束不补结算。
