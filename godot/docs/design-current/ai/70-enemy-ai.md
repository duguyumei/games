# 敌方 AI 与远程协议

> 本文件是当前 v0.30 模块化权威设计源的一部分。原文规则段落仅在此处维护；
> 其他模块只能通过链接引用，不得复制或重新解释。原章节编号保留用于迁移核对。

#### 敌方 AI 并行决策、公开信息与会话记录

敌我共享牌区、牌型、功法、内功、异状、行动资格与结算规则，但使用不同的行动生成方式。玩家通过界面选择行动；敌方可以使用本地确定性策略或可选的远程人工智能策略。两种敌方策略都只能从本地规则核生成的合法候选中选择一项，最终统一转换为战斗行动提案；远程回答不能直接修改牌区、生命、防御、功法序列、随机数或其他战斗状态。本地策略始终作为离线、超时、格式错误和非法回答的保底。

每次任一方获得一次新的完整出手机会时都建立新的行动窗口；连击产生的额外行动同样建立新窗口。行动窗口开始后，若敌方拥有行动机会，敌方 AI 立即接收该窗口开始时的公开信息和合法候选并开始思考，玩家同时可以自由选择、取消和修改自己的真气，也可以使用当前规则允许且只影响我方的消耗品，但在敌方产生有效行动提案或本地策略完成接管前不能确认出牌。玩家界面的选牌草稿不进入待出区、不改变战斗状态，也不会发送给敌方 AI。

敌方先完成时立即锁定其行动，不因玩家之后修改选牌或使用只影响我方的消耗品而重新决策。每个窗口先在本地枚举全部合法出牌组合，再把即时效果、真气状态、重塑、印记、异状、内功、功法序列和剩余手牌的一步未来价值投影为战略画像；经过关键候选硬保护、严格帕累托淘汰、战略方向代表选择和 MMR 去相似后，只保留 1～5 个候选。完整集合只存在于本地画像和压缩阶段，不进入远程请求或玩家快照；第一版不做 MCTS、完整状态克隆或跨回合搜索。

玩家从窗口建立起可以看到冻结顺序的全部“可能意图”，包括强攻、防守、蓄势、换气、运功、控制等公开方向和预计伤害、防御、打出数量、补牌数量、预计同气收益与少量公开标签。公开项不含 `candidate_id`、敌方卡牌实例、隐藏计数、AI 评分或选中标记。AI 完成内部选择后界面只从“思考中”变为“已准备”或“本地接管”，可能意图的内容和顺序不变；锁定张数、实际牌型、功法、伤害、防御和状态效果只在双方确认并进入正式揭示／结算边界后公开。如果压缩后只有一个合法方向，玩家可以自然推断，但系统仍不额外标记其已被选择。

当前战斗消耗品只影响我方牌组、手牌、心得、功法获取或其他我方状态。玩家在敌方思考期间使用这类消耗品时，不取消、不重发当前请求；该使用事件、公开构筑变化和实际结果写入完整本地历史，并在敌方下一次实际获得行动机会、准备发送下一条请求时作为历史增量发送。以后若新增能够改变敌方手牌、功法序列、行动资格或令其已选候选失效的消耗品，必须另行明确失效与重新决策规则，不能自动沿用本条。

敌方没有行动机会的窗口不调用远程接口，但窗口、玩家出牌、连击、单方行动、消耗品、状态与结算结果仍按顺序记录在本地会话历史中。敌方下一次获得行动机会时，所有尚未发送的公开事件作为 `history_delta` 一并发送。因此玩家单方连击不会产生一次无意义的远程请求，但敌方之后仍能得知该连击中玩家公开打出的真气、牌型、功法和结算结果。

敌方 AI 可以读取玩家当前生命、防御、同气槽当前值与有效最大值、当前有效反震及公开剩余持续时间、公开格挡来源、有效邀战的 X/Q 与到期窗口、公开层数与异状、各牌区数量、完整本局牌组构成及重塑、全部功法配置与等级、全部精确牌型序列及当前位置、内功配置与等级、已公开的消耗品和此前公开历史。被反震来源暂时覆盖的旧比例只有在其来源本身属于公开状态时才公开，但不能因投影隐藏而改变本地规则核的恢复结果。敌方不能读取玩家当前手牌的具体内容、玩家抽牌堆顺序、玩家当前选牌草稿、尚未公开的随机结果，以及随机效果命中隐藏手牌时的具体真气身份。已经打出、弃入公开牌区或通过规则明确揭示的真气可以按实例记录；敌方可以根据公开构筑和历史自行推测隐藏信息。

正式功法的即时与未来价值统一由语义标签投影 Provider 估值。`damage`、`defense`、`true_damage`、`draw`、`discard`、`recover`、`deck_control`、`anomaly_apply`、`delayed_defense`、`momentum`、`reflection`、`block`、`temporary_card`、`economic_gain`、`same_qi_payoff`、`extra_card_commitment`、`retrigger_sensitive`、`enemy_disruption` 与 `challenge` 只表达通用行为，不允许在 AI 中按功法 ID 分支。随机收益使用通用期望值，预览、候选枚举和状态哈希不得推进正式随机源。

一次战斗尝试对应一个本地 AI 会话。完整脱敏请求、模型原始回答、格式校验、纠错重试、超时、本地接管、最终行动、耗时与用量都必须持久化，供审计和回放使用；凭据和请求认证头不得写入战斗存档或日志。战斗中退出后不恢复中间牌区、回合或 AI 对话，而是从战斗开头建立一次新的战斗尝试与新的 AI 会话；旧会话作为只读审计记录保留，不能接入新尝试。服务端会话 ID 和提示词缓存只在当前战斗尝试中作为可选适配能力。发送给 AI 的工作历史默认每 5 个完整回合压缩一次；压缩只替换当前尝试后续请求使用的早期工作历史，不删除本地完整记录。没有触发远程请求的窗口所积累的事件同样参与下一次压缩和发送。

远程响应必须通过协议版本、决策 ID、窗口状态、返回格式、候选 ID 和本地合法性校验。失败时可以在同一会话中发送简短结构化错误并要求重答；超过设置的重试次数、超时、断网、主动取消或仍不合法时，立即交由本地 Utility 从本窗口同一批 1～5 个压缩候选中选择，不能回到完整候选集合。远程 AI 和本地策略对外都只返回同一种行动提案，不建立两套战斗规则。

压缩参数使用统一默认值：`candidate_limit=5`、六个 `direction_weights=1.0`、`diversity_penalty=0.35`、`future_value_discount=0.5`。候选上限只允许 1～5；内容加载时拒绝越界配置，运行适配器对程序化输入明确钳制。真气状态和被动未来价值通过 `ai_action_value_query`、`ai_card_play_value_query`、`ai_card_retention_value_query` 纯查询贡献数值与 `source_breakdown`；默认值为零，查询不得移动卡牌、推进 RNG 或修改计数器。AI 中央模块不得按功法、内功、真气状态、印记、异状或敌人 ID 写评分分支。

AI 信息协议现统一为 v3：`AiBattleContext`、`AiDecisionObservation`、`AiHistoryEvent`、请求、响应、提示词和会话审计均拒绝旧 v1/v2，不写迁移层。`BattleSnapshot` 的玩家字段契约未变化，因此仍保持现有版本。战斗上下文由唯一规则版本常量提供 `rules_version`，同时声明 `content_version=2`、`ai_protocol_version=3`、`prompt_version=3`；本场实际引用的功法、内功、物品、消耗品与真气状态会投影名称、玩家说明和辅助语义标签，再经递归键排序的规范 JSON 计算 SHA-256 `content_fingerprint`。未引用内容、Handler、脚本路径和完整内部 DSL 不发送。

每窗口观察由唯一状态投影器建立。敌人看到自身生命、防御、连势、同气槽当前值与有效最大值、有效手牌上限、预计正常补牌、功法直接值、当前反震与公开来源、格挡次数与条件摘要、邀战 X/Q 与到期窗口、自身手牌实例、公开弃牌和暂移实例、序列位置、行动状态、状态和被动进度，但也看不到自身抽牌顺序。玩家侧只公开同类数值、手牌与牌区数量、公开弃牌、序列、行动状态、公开状态和公开被动进度；当前手牌实例、抽牌顺序、选牌草稿、隐藏手牌异状、未揭示随机结果和私有计数不进入观察。

玩家公开威胁使用确定性区间 `{minimum, expected, maximum, confidence, basis}`。第一版 `minimum=0`；`expected` 取最近至多四次公开伤害的稳健中位值，若无历史则取公开构筑保守上界的四分之一；`maximum` 由公开牌组最高基础真气值与公开手牌数量上限形成。它不读取玩家当前手牌或选牌，也不复制玩家合法候选枚举。F6B 的 `avoids_immediate_death` 使用该 `expected`，不再使用永久 `-1`。

`state_hash` 为规范化后的完整观察（排除自身哈希）、冻结顺序的 1～5 个公开候选、规则版本、内容指纹和公开被动来源指纹的 SHA-256。生命、防御、敌方手牌状态、功法位置、公开状态、被动进度或候选画像变化都会改变哈希；Dictionary 插入顺序不会。AI 返回后仍必须经过已有本地合法性复核。

公开历史只接受白名单事件：行动窗口、出牌、功法、协同、同气变化、连击、伤害、格挡成功、反震来源变化、邀战建立／推进／结算、防御、防御衰减、抽弃牌、暂移／返回、卡牌状态、被动触发／计数、序列、消耗品、行动、回合和战斗完成。玩家抽牌只记录数量，隐藏随机目标只记录数量，私有事件完全丢弃。每次正式行动还附带 AI 可见状态前后差量；预览和候选枚举不产生日志。五回合摘要保留最新公开状态、各类确定性频率和累计差量，以及最近四次正式行动的顺序尾部；本地完整 `public_events` 永不删除。

默认远程服务商确认为 DeepSeek。游戏采用其 OpenAI 兼容的 Chat Completions REST 接口，默认 `base_url` 为 `https://api.deepseek.com`、路径为 `/chat/completions`；Godot 客户端直接发送 HTTPS 请求，不依赖 Python、Node 或厂商 SDK。通用 Provider 必须允许玩家覆盖 `base_url`、路径、API Key、模型、思考开关、推理强度、超时和附加请求字段，因此其他 OpenAI 兼容服务可以复用同一接口。Anthropic 兼容端点不作为默认实现，后续只有确有需要时才增加独立协议适配器。

默认模型为 `deepseek-v4-flash`，用于频繁的普通行动窗口，默认开启 thinking 并使用中等推理强度；`deepseek-v4-pro` 作为玩家可选的高质量模型，默认开启 thinking 并使用高推理强度，可用于 Boss、高难度或愿意承担更高延迟与费用的配置。模型字符串始终允许玩家手动填写，不把可用模型硬编码成封闭枚举。

远程 AI 设置第一版通过本机配置文件 `user://ai/ai_settings.cfg` 提供，不要求先制作设置页面。程序首次以图形模式启动时自动生成默认配置，远程 AI 默认关闭；玩家可以直接在配置文件中填写 API Key、将 `enabled` 改为 `true`，并修改兼容端点、模型及会话参数。API Key 允许以明文保存在该本机配置文件中，但不得进入战斗存档、RunSnapshot、脱敏 AI 会话、结构化日志、公开设置快照或请求审计记录；环境变量 `DEEPSEEK_API_KEY` 可以在配置文件 Key 为空时作为运行时替代来源。

每次战斗尝试的脱敏 AI 会话默认自动保存到 `user://ai/conversations/`，内容包括公开战斗上下文、完整公开事件、压缩摘要、请求、原始回答，以及 `validation_succeeded/failed`、`decision_accepted/retried/timed_out/cancelled`、`fallback_selected` 和 `window_failed` 审计。该文件只用于审计、费用检查和回放，不是存档，也不提供进程重启后的对话续接。重新进入同一战斗时必须建立新的战斗尝试 ID、AI 会话和服务端短会话，不能覆盖或续写旧尝试。

完整 F6B 候选诊断进入另一份本地私有轨迹 `user://ai/traces/`。每个窗口保存公开候选到诊断候选的映射、原观察指纹、完整压缩管线、远程或本地 Utility 选择、预估与正式结算差量；战斗结束再汇总胜负、回合、远程成功／接管／校验／超时、token、响应时间、错过斩杀和错过保命。私有轨迹不进入远程请求、`BattleSnapshot`、玩家意图、正式存档或战斗恢复，写入失败也不能令战斗失败。conversation 可以审计“发送了什么”；trace 用于本机平衡分析“完整候选为何被压缩和选择”。两者都递归脱敏认证信息。

离线只读入口 `res://tools/run_ai_trace_report.gd` 汇总战斗数、窗口数、三阶段平均候选数、方向出现／选择、远程成功、本地接管、格式错误、超时、耗时、token、错过斩杀／保命、预估误差和分敌人结果；空目录输出“无数据”，损坏文件单独报告并继续。工具不联网、不修改轨迹，也不自动修改权重。后续权重调整必须同时检查结构化候选诊断、批量轨迹报告和试玩结果；战斗胜率只是结果指标之一，不能单独作为调权依据。

通用战斗提示词保持稳定、短小并适合服务端前缀缓存。它明确说明候选已经由本地规则核压缩，允许依据公开构筑、公开历史和公开状态做概率推测，但禁止把隐藏手牌、抽牌顺序或未冻结随机结果当作事实，也禁止从候选 ID、数组顺序或字段缺省猜优先级。返回使用 schema v3；`reason_code` 固定为 `lethal`、`survival`、`assault`、`prepare`、`cycle`、`control`、`passive_trigger`、`sequence_progress`、`resource_preservation` 或 `uncertainty_management`。缺省会规范化为 `unspecified` 并记为协议质量问题；非空非法值触发纠错重试。`confidence` 只用于诊断，不影响战斗规则。
