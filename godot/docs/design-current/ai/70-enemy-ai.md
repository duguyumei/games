# 敌方 AI 与远程协议

#### 敌方 AI 并行决策、公开信息与会话记录

敌我共享牌区、牌型、功法、内功、异状、行动资格与结算规则，但使用不同的行动生成方式。玩家通过界面选择行动；敌方可以使用本地确定性策略或可选的远程人工智能策略。两种敌方策略都只能从本地规则核生成的合法候选中选择一项，最终统一转换为战斗行动提案；远程回答不能直接修改牌区、生命、防御、功法序列、随机数或其他战斗状态。本地策略始终作为离线、超时、格式错误和非法回答的保底。

每次任一方获得一次新的完整出手机会时都建立新的行动窗口；连击产生的额外行动同样建立新窗口。行动窗口开始后，若敌方拥有行动机会，敌方 AI 立即接收该窗口开始时的公开信息和合法候选并开始思考，玩家同时可以自由选择、取消和修改自己的真气，也可以使用当前规则允许且只影响我方的消耗品，但在敌方产生有效行动提案或本地策略完成接管前不能确认出牌。玩家界面的选牌草稿不进入待出区、不改变战斗状态，也不会发送给敌方 AI。

敌方先完成时立即锁定其行动，不因玩家之后修改选牌或使用只影响我方的消耗品而重新决策。界面可以按难度展示敌方预计伤害、防御和其他公开意图，也可以在高难度只显示“思考完毕”；预计信息由本地预览核根据已选候选生成，具有随机性的结果只显示范围、数量或类别，不公开尚未结算的随机目标和随机数结果。玩家只有在敌方思考完成后才能最终确认出牌，确认后双方行动才进入待出区并由共享规则核结算。

当前战斗消耗品只影响我方牌组、手牌、心得、功法获取或其他我方状态。玩家在敌方思考期间使用这类消耗品时，不取消、不重发当前请求；该使用事件、公开构筑变化和实际结果写入完整本地历史，并在敌方下一次实际获得行动机会、准备发送下一条请求时作为历史增量发送。以后若新增能够改变敌方手牌、功法序列、行动资格或令其已选候选失效的消耗品，必须另行明确失效与重新决策规则，不能自动沿用本条。

敌方没有行动机会的窗口不调用远程接口，但窗口、玩家出牌、连击、单方行动、消耗品、状态与结算结果仍按顺序记录在本地会话历史中。敌方下一次获得行动机会时，所有尚未发送的公开事件作为 `history_delta` 一并发送。因此玩家单方连击不会产生一次无意义的远程请求，但敌方之后仍能得知该连击中玩家公开打出的真气、牌型、功法和结算结果。

敌方 AI 可以读取玩家当前生命、防御、公开层数与异状、各牌区数量、完整本局牌组构成及重塑、全部功法配置与等级、全部精确牌型序列及当前位置、内功配置与等级、已公开的消耗品和此前公开历史。敌方不能读取玩家当前手牌的具体内容、玩家抽牌堆顺序、玩家当前选牌草稿、尚未公开的随机结果，以及随机效果命中隐藏手牌时的具体真气身份。已经打出、弃入公开牌区或通过规则明确揭示的真气可以按实例记录；敌方可以根据公开构筑和历史自行推测隐藏信息。

一次战斗尝试对应一个本地 AI 会话。完整脱敏请求、模型原始回答、格式校验、纠错重试、超时、本地接管、最终行动、耗时与用量都必须持久化，供审计和回放使用；凭据和请求认证头不得写入战斗存档或日志。战斗中退出后不恢复中间牌区、回合或 AI 对话，而是从战斗开头建立一次新的战斗尝试与新的 AI 会话；旧会话作为只读审计记录保留，不能接入新尝试。服务端会话 ID 和提示词缓存只在当前战斗尝试中作为可选适配能力。发送给 AI 的工作历史默认每 5 个完整回合压缩一次；压缩只替换当前尝试后续请求使用的早期工作历史，不删除本地完整记录。没有触发远程请求的窗口所积累的事件同样参与下一次压缩和发送。

远程响应必须通过协议版本、决策 ID、窗口状态、返回格式、候选 ID 和本地合法性校验。失败时可以在同一会话中发送简短结构化错误并要求重答；超过设置的重试次数、超时、断网、主动取消或仍不合法时，立即交由本地策略选择。远程 AI 和本地策略对外都只返回同一种行动提案，不建立两套战斗规则。

默认远程服务商确认为 DeepSeek。游戏采用其 OpenAI 兼容的 Chat Completions REST 接口，默认 `base_url` 为 `https://api.deepseek.com`、路径为 `/chat/completions`；Godot 客户端直接发送 HTTPS 请求，不依赖 Python、Node 或厂商 SDK。通用 Provider 必须允许玩家覆盖 `base_url`、路径、API Key、模型、思考开关、推理强度、超时和附加请求字段，因此其他 OpenAI 兼容服务可以复用同一接口。Anthropic 兼容端点不作为默认实现，后续只有确有需要时才增加独立协议适配器。

默认模型为 `deepseek-v4-flash`，用于频繁的普通行动窗口，默认开启 thinking 并使用中等推理强度；`deepseek-v4-pro` 作为玩家可选的高质量模型，默认开启 thinking 并使用高推理强度，可用于 Boss、高难度或愿意承担更高延迟与费用的配置。模型字符串始终允许玩家手动填写，不把可用模型硬编码成封闭枚举。

远程 AI 设置第一版通过本机配置文件 `user://ai/ai_settings.cfg` 提供，不要求先制作设置页面。程序首次以图形模式启动时自动生成默认配置，远程 AI 默认关闭；玩家可以直接在配置文件中填写 API Key、将 `enabled` 改为 `true`，并修改兼容端点、模型及会话参数。API Key 允许以明文保存在该本机配置文件中，但不得进入战斗存档、RunSnapshot、脱敏 AI 会话、结构化日志、公开设置快照或请求审计记录；环境变量 `DEEPSEEK_API_KEY` 可以在配置文件 Key 为空时作为运行时替代来源。

每次战斗尝试的脱敏 AI 会话默认自动保存到 `user://ai/conversations/`，内容包括公开战斗上下文、完整公开事件、压缩摘要、请求、原始回答、校验、纠错、本地接管与 Provider 分段信息。该文件只用于审计、费用检查和回放，不是存档，也不提供进程重启后的对话续接。重新进入同一战斗时必须建立新的战斗尝试 ID、AI 会话和服务端短会话，不能覆盖或续写旧尝试。

通用战斗提示词保持稳定、短小并适合服务端前缀缓存。系统提示只声明以下职责：把自己视为共享规则核下的敌方玩家；目标是提高整场战斗的最终胜率而不是每次选择即时最大伤害；只能使用请求中提供的公开信息与自身信息；只能从 `candidates` 选择；必须考虑必杀与存活、后续手牌、功法序列、连击／协同、状态、历史行为和信息不确定性；不得猜测玩家隐藏手牌、抽牌顺序或隐藏随机结果；不得请求执行候选之外的动作。返回只允许一个 JSON 对象，固定包含 `schema_version`、`decision_id`、`state_hash`、`candidate_id`，并可包含短 `reason_code` 与 `confidence`，不能输出 Markdown、解释文本、思维过程或额外字段。具体战斗上下文、历史摘要、历史增量和候选继续放在结构化用户消息中，不复制进系统提示。
