### 2.4 功法

功法是绑定牌型的战斗效果。牌型提供结构、参与牌、功法池与出招频率；参与牌的属性集中数提供基础功法倍率。功法把这些输入转换为伤害、防御、牌区变化、异状、连击、协同或其他结果。牌型本身不自动造成伤害。

每个牌型组按下列顺序处理：

```text
识别最高精确牌型
→ 结算参与真气的贡献与功法倍率，得到初始功法值 P₀
→ 结算直接功法值固定／百分比修正，并按连势规则得到最终功法值 P
→ 检查当前序列功法的牌型、属性与其他条件
→ 将成功功法与同一时点的已装备内功加入可见触发队列
→ 结算伤害、防御、异状、牌区变化与延迟效果
→ 将打出的牌置入弃牌堆或按效果移出
→ 结算出牌结束与留手效果
→ 成功功法推进该精确牌型序列；失败功法停留
```

`P₀`、`P`、连势快照与同组重触规则分别以[牌型、真气值与倍率](../combat/10-hand-ranking-and-values.md#22-真气值与数值计算)和[行动结算](../combat/12-action-resolution.md#同一时点的触发队列)为准。功法若根据自身规模产生连势，必须读取 `P₀`，不能读取已经加入连势的 `P`。

若主牌型功法建立协同，在主牌型开始结算前先锁定全部协同组；主组与协同组依次独立完成完整流程。全部组结算结束后，才结算整次行动的同气槽收益或其他额外行动。

### 五个基础功法池

功法按牌型的底层结构归入五个基础池：

| 基础功法池 | 可以读取该池的精确牌型 |
| --- | --- |
| 高牌池 | 高牌 |
| 对子池 | 一对、两对；葫芦交叉读取 |
| 三条池 | 三条；葫芦交叉读取 |
| 顺子池 | 顺子 |
| 炸弹池 | 四条、五条 |

当前运行时五个正式功法池已经开放，共 234 门非内建功法：高牌 60 门、对子 54 门、三条 37 门、顺子 39 门、炸弹 44 门。高牌池由[首批 25 门高牌功法](./24-gongfa-high-card-pool.md)与扩展索引中的 35 门组成；其余池及扩展高牌的稳定 ID 见[扩展功法正式索引](./28-gongfa-expanded-formal-pool-index.md)。详细效果正文由[蛊毒](./25-gongfa-poison-candidate-pool.md)、[成长](./26-gongfa-growth-candidate-pool.md)、[跨系统桥接](./27-gongfa-bridge-candidate-pool.md)、[山·阵势与壁垒流](./29-gongfa-mountain-candidate-pool.md)、[风·运转与扰乱流](./33-gongfa-wind-pool.md)、[火·连击与燃尽流](./34-gongfa-fire-pool.md)和[复杂机制功法](./35-gongfa-special-candidate-pool.md)文档唯一维护。

[山·阵势与壁垒流正式目录](./29-gongfa-mountain-candidate-pool.md)与[复杂机制功法正文](./35-gongfa-special-candidate-pool.md)都只按主题分卷维护正文。全部内容均进入上述234门非内建正式数量、心得随机池、奖励池与装配统计。加上散招、守招两门基础通用功法，当前正式资源总数为236。

当前扩展索引记录209门，另加首批25门高牌；再加两门基础通用功法，运行时正式资源总数为236。35号文档维护的25门复杂机制功法均已完成独立资源、正式资格、AI语义、公开预览、战斗历史／存档投影与专项测试接入；`production_sequences.json`保持不变。

**基础通用功法（2 门）**

- **散招**：ID `basic_scatter`；造成 `floor(P/4)` 点普通伤害。
- **守招**：ID `basic_guard`；获得 `floor(P/4)` 点防御。

二者均使用最终功法值 `P`，`P<4` 时结果可以为 0；永久可用、适用于八种精确牌型、基础装配上限各为 99。它们不属于五个普通功法池，不进入购买、奖励、心得随机池或已习得功法统计，但在战斗中仍是真实功法，读取连势、受功法权限影响并正常推进序列。

高牌可以由任意手牌主动打出，承担启动、保底、过渡和低成本铺垫作用；它也可以在获得足够系统支持后成为独立主牌型。高牌表示没有形成更高结构时的散手，不是其他牌型自动包含的公共结构，因此其他牌型默认不能读取高牌池。高牌功法可以在效果正文中读取本次打出的全部散牌，但默认只有最高的一张参与数值计算。

五条与四条共同读取炸弹池，但各自拥有独立槽位、序列和进度。五条心得正常进入普通心得池，不以当前牌组能否立即组成五条为生成条件。

葫芦从对子池与三条池的去重并集中获得候选：

- 对子池功法默认按一对分支结算；
- 三条池功法默认按三条分支结算；
- 功法显式提供葫芦分支时，葫芦精确分支优先；
- 同一门功法若未来同时归入两个池，在葫芦候选中只出现一次，不增加权重；
- 当前一门功法仍只拥有一个正式池归属。多池单功法在葫芦下应继承哪个默认分支尚未确认，因此暂不开放多池数据结构。

基础池只决定一条精确牌型序列可以配置哪些功法，不合并不同牌型的参与牌、固定倍率、槽位或序列进度。

### 功法槽位、心得与循环序列

每个精确牌型拥有独立的功法槽位容量、循环功法序列和序列指针。槽位容量表示该牌型至多可以同时装入多少门永久或战斗临时功法；循环序列只保存当前实际装备或成功生成的功法，不保存空值。每个精确牌型初始拥有 1 个功法槽位，容量最高为 9，并且始终至少装备一门功法。使用对应心得时：

1. 该精确牌型槽位基础 +1；物品可以通过统一心得槽位增量查询改写本次增量，超过上限 9 的部分忽略；
2. 从它可读取的正式功法池并集中，随机获得一门尚未加入该精确牌型当前序列的功法，加入本局功法库但不自动装备。

若没有符合资格且仍有有效装配次数的普通功法，本次心得仍正常增加槽位容量，但不获得功法；不跨池抽取，也不使用散招或守招强制补满新增槽位。

玩家八种永久配装必须全部满足 `slot_count>=1` 且 `1<=sequence.size()<=slot_count`，序列中不得保存空值。空余功法槽只是尚未使用的容量，不作为空节点进入循环。玩家不能卸下某个精确牌型的最后一门功法。普通功法在八种序列中合计默认最多装配 1 次；基础通用功法各最多 99 次。有效次数由纯查询 `technique_loadout_copy_limit_query` 统一修改，查询失败时提交失败关闭。配装提交以候选牌型和其他七种当前序列组成完整快照，原子校验后才替换状态。

每条序列遵守：

- 战斗开始时指向第一门；战斗结束后重置，除非内容明确改写；
- 每次打出该精确牌型，只尝试当前指向的一门功法；
- 功法满足全部条件并完整成功结算后，序列前进一格，末尾回到第一门；
- 功法失败时不产生效果、不推进序列，也不使用或清空连势；
- 同组重触复用该组原功法与冻结的 `P₀`、`P`，无论重触多少次都只推进一格；
- 协同后续组不是重触，会读取当时的序列位置并独立计算；
- 玩家永久配装不存在空序列，但可以有未被序列使用的空余槽位容量；调试夹具或敌人显式空序列仍不产生功法效果；
- 战斗开始后序列内容与顺序锁定，普通装备操作不能临时重排。

#### 战斗槽位容量、临时功法与稳定身份

永久配装仍以每个精确牌型的槽位容量与功法 ID 序列保存。进入战斗时，每门实际装备的功法必须实例化为具有稳定身份的战斗功法实例；战斗内移动、推进、临时插入、自动触发与调用都以稳定功法实例身份为事实源，不能以易漂移的数组下标或功法 ID 代替。每个实例至少保存 `slot_instance_id`、`technique_id`、`hand_id`、`temporary`、`origin_technique_id`／`origin_slot_instance_id` 与 `insertion_serial`。这里的 `slot_instance_id` 是功法本次占用槽位形成的稳定执行身份，不代表额外增加槽位容量。行动确认时冻结当前实例身份；即使后续嵌套调用改变可见顺序，原行动仍结算并推进该冻结实例。通用战斗进度统一存入来源标识，不在功法实例上保存 `battle_state`。

战斗临时功法必须占用目标精确牌型的空余功法槽。任意时点均须满足`永久已装备功法数+当前战斗临时功法数<=slot_count`；没有空余槽位时不生成。一次效果尝试生成多门时，按声明顺序和稳定 Invocation 顺序逐门检查剩余容量，已经成功生成的部分不会因为后续容量不足而回滚，除非正文明确要求整批原子成功。

成功生成的临时功法按照正文指定的位置加入当前战斗序列，拥有独立稳定执行身份、battle 来源标识与插入顺序，并按普通功法规则移动、触发、调用、自动触发和推进。跨牌型生成时，临时功法以宿主序列的精确牌型取得牌型池资格。战斗结束删除全部临时功法并释放其占用的槽位，不写回永久配装或本局功法库。临时副本不会因为复制了本局永久来源而重复提供永久装备收益。

#### 自动功法与主动触发

自动功法仍是普通牌型功法序列中的正常功法，不建立序列外的第二套实体。默认情况下，它既可以随当前序列主动触发，也额外监听定义中的自动条件：

- 主动触发按普通牌型正常计算初始功法值 `P₀`；
- 自动触发按该自动条件显式声明的特殊 `P₀` 来源计算；
- `special`是旧资源兼容字段，不形成内容分类，也没有玩法语义；不能用它推断自动触发、主动效果抑制或强度档位；
- 新字段 `manual_effect_mode` 只允许 `normal` 与 `advance_only`，默认 `normal`；
- 只有 `manual_effect_mode="advance_only"` 时，主动触发才跳过功法 `effects`。该次仍是成功功法：正常计算 `P`、读取和结算连势、结算同气、发送行动与功法事件并推进冻结槽位；自动触发不因该字段跳过效果。

manual、automatic、invoked、echo和retrigger的每次实际执行都通过同一个
`TechniqueResolutionService`边界建立稳定execution token，并在自身效果与连势/同气收尾完成后、回响
和序列推进前提交`technique_execution_resolved`。汇总只累计相同token、`source_kind=technique`且来源
ID/实例完全匹配的既有committed伤害、防御与恢复事实，不能以整次行动角色净变化代替。每次回响是
独立执行，嵌套子功法、内功、物品与异状响应不计入父汇总。continuation复用原token；预览、启动拒绝
和执行失败不发送；汇总Handler失败必须阻止当前槽位推进。

自动条件由功法定义的 `automatic_triggers` 描述，可以直接响应公共已提交事件，或把事件值累加到该槽位的来源标识并在跨过阈值时触发。没有进度配置时，每个合格事件直接触发一次；单个事件跨过多个完整阈值时可以触发多次，是否消费阈值和保留溢出由定义决定，不设置隐藏的默认次数上限。自动触发移动并结算声明该条件的具体槽位，临时副本各自判断；多个槽位同时合格时先冻结集合，再按触发前稳定可见顺序结算，不能依赖字典遍历顺序。

自动进度需要同时保留多个事件字段时，只能使用同一通用有序聚合：按事件提交顺序把声明字段追加到该具体槽位的来源标识，跨阈值时从队首冻结并消费完整组，溢出记录继续保持原顺序。消费组作为普通捕获集合传入自动结算，可以统一读取数值和、平均值与字段去重数；不得为单门功法新增平行队列、角色级计数器或按功法ID保存集合。

自动事件对双方全部已装备槽位判断，而不是只检查事件 actor 一方。统一事件上下文至少提供
`event_actor_is_owner`、`event_actor_is_opponent`、`event_target_is_owner`、`source_kind`、
`draw_reason`、`damage_type`、`hand_id`、`technique_power` 与事件公开数值字段。功法抽牌来源
只以结构化 `source_kind=technique` 判断；内功、物品、正常补牌与真气自身抽牌即使同样产生
`card_drawn` 也不能被误计。

自动检查发生在细粒度公共事件成功提交之后。默认 `timing="immediate"`，因此自动功法在产生该事件的效果与调用者的下一个效果之间完整结算；只有定义显式写出 `after_caller_advance`、`action_end`、`round_end` 等时点时才延后。具体移动、推进顺序与递归安全由[行动结算、触发队列与连击](../combat/12-action-resolution.md#功法调用自动调用与序列推进)唯一维护。

#### 调用功法的公共语义

调用不是协同、功法回响、同组重触或额外出牌：它不建立新牌型，不重新打出真气，也不再次执行真气的打出异状、毒、自身重塑响应或牌区移动。调用发生在同一次行动和同一功法链中，把指定的既有槽位移动到当前结算位置并触发；默认采用即时嵌套时点。

被调用功法默认执行普通成功功法的完整规则：检查功法条件与 `technique_activation_permission_query`，读取直接功法值修正与当前连势，结算连势保留／清空，再次结算当前行动冻结真气组的同气，发送结构化功法事件，并按稳定槽位身份推进。若调用效果要求不推进、不读取连势、不获得同气或忽略功法条件，必须分别通过明确字段关闭，不能由调用身份暗中省略。

调用的 `P₀` 默认复用调用者冻结的 `P₀`，也可以显式使用固定值、`ValueSpec` 或重新计算。固定“初始功法值 30”表示先令 `P₀=30`，随后仍加入直接修正与当前连势得到 `P`；只有明确固定“最终功法值 30”才直接覆盖 `P`。调用顺序、延后队列、事件元数据与恢复幂等由[行动结算、触发队列与连击](../combat/12-action-resolution.md#功法调用自动调用与序列推进)定义。

### 功法条件

功法的真气条件分为：

```text
通用功法：只限制牌型
属性功法：限制牌型，并要求参与最高牌型的真气中至少有指定数量属于某属性
纯属性功法：限制牌型，并要求全部参与最高牌型的真气都可以视为指定属性
```

属性功法必须同时写明属性与数量。默认只检查参与最高牌型的真气，不检查额外打出的真气或仍在手中的真气；正文可以明确例外。混元与临时属性重塑参与属性识别，明确读取基础属性时仍读取真气本体。

功法只能读取已经识别完成的本次牌型，不能追溯把本次最高牌型改成另一牌型。改变顺子长度、牌阶关系、默认参与范围等识别前规则，应由内功、物品或其他在识别前生效的内容承担。

功法条件、自动事件条件、效果 `when` 与格挡条件共用唯一 `ConditionSpec` 注册表；
“条件不同”只能体现在配置和条件规格中，不得复制伤害、牌区、功法结算、标识或事件系统。

### 通用操作码收敛

正式内容只使用 `write_momentum(operation)` 表达连势增加、设置和消费；只使用
`write_same_qi(operation="add")` 表达同气增加。清空同气并转防御时，先由
`write_same_qi` 捕获实际清空值，再由普通 `defense` 读取捕获结果。反震比例统一使用
`grant_reflection_source`；防御移除统一由 `DefenseEffectHandler` 的
`remove_defense(amount/all/cause)` 表达。

蓄力功法不建立角色级统一“蓄力”资源。底层协议已完成：`TechniqueDefinition.charging`只声明
`primary_marker_id`、显示名、battle/public属性、允许的`add/subtract/set/clear`操作及最小／可选最大值；
倒计时、观察次数、完成条件和具体公式不能写进该声明。主要marker必须引用本功法已声明的公开battle
marker。

“正在蓄力”的唯一判定是：实际功法定义声明了charging，且该`slot_instance_id`对应的主要marker条目
真实存在。marker存在且值为0仍在蓄力；`set 0`不结束，`clear`移除条目才结束。通用只读查询按精确牌型
及当前槽位顺序枚举实际实例，通用端口负责begin/write/end和冻结目标后的原子批量写。主要marker始终以
实际slot为`source_instance_key`；同ID永久槽、临时副本以及`share_origin`临时副本各自独立，普通marker
的share-origin语义不变。查询、预览、UI和AI不能推进倒计时、写值、发送事件、移动序列或推进RNG。

蓄力功法首次`trigger_mode=manual`触发和蓄力期间再次manual触发都仍是正常成功功法：照常识别牌型、
计算P₀/P、读取连势、结算同气并推进序列；效果用`charging_active`与`trigger_mode=manual`组合选择正文
分支。再次触发不默认引爆、清空累计值、建立第二份延迟/观察或改变倒计时。automatic、invoked、echo、
retrigger不能误入manual分支。完成后仍由既有自动功法流程移动该slot、以正文特殊P₀结算和推进，正文再
明确clear marker。

风·长风蓄海的蓄风值、火·三劫悬炉的生命损失累计值`L`、山·悬岳待敌两次观察记录的当前总和`Z`
均已按该协议接入。倒计时和观察继续由`StatusDelayService/StatusResponseService`及自动功法体系负责。

`dissipate_captured`、`atomic_exchange_captured`、`synchronous_discard_queries`、
`generate_temporary_techniques` 与 `invoke_sequence_technique` 因表达槽位容量检查、同步冻结或特殊结算时序
可以保留。仅被单门内容使用且名称带具体玩法含义的操作码，若能由
capture／query／when／move／anomaly／repeat 组合表达，必须迁移内容并删除；只有确实需要
原子性、同步性或冻结语义的通用原语可以保留。

### 功法的即时落点

功法默认应满足：

- 至少立即造成伤害或立即获得防御；
- 至少有一项实际结果有意义地读取 `P`；
- 随机目标或合格目标不足时，仍结算即时伤害或防御；
- 延迟效果建立时冻结需要的 `P₀`、`P` 与派生值，之后不因其他行动变化，除非正文明确重新读取。

标准模板优先使用“即时伤害或防御 + 一个主要机制 + 可选条件强化”。建立连击或协同、大规模转换牌区、大量创建／复制／移除临时真气、终结性爆发或带显著代价的规则改写，可以由正文明确省略即时落点，但仍必须有清楚的成功条件、失败边界与数值输入；这种例外是具体效果结构，不是功法内容等级。

功法效果不应只为单门内容新增封闭资源。优先读取现有牌区、真气异状、重塑、牌型结构、功法序列、生命、防御、连势、反震、额外行动与延迟事件；只有多个效果能够生产、读取或消耗，且现有状态无法表达时，才新增公共状态。

### 牌型定位与效果权限尺度

八种精确牌型的功法定位必须从牌型自身的成型难度、出牌投入、出现频率、可保留性、可拆分性和升级路径中推导，不能先预设流派，再把与底层战斗规则无关的效果硬套给某个牌型。

牌型强弱不是无条件的线性升级关系。不同牌型应提供不同的战术用途；功法之间可以存在局部替代，但不能让高级牌型的全部功法都只是低级牌型功法的数值上位替代。低级牌型通常以稳定、灵活、低投入或高频率形成价值；越难形成、投入越大或越少见的高级牌型，通常越有资格获得更具威胁性、影响范围更大或更独特的效果权限，而不只是更高倍率。

这一梯度是评审功法时使用的软性设计尺度，不是硬性的牌型禁用表。具体效果仍需结合触发条件、即时收益、战内后续收益、序列位置、重复装配、重触、协同、额外行动与敌方反制综合判断。系统支持也可以令低级牌型成为构筑核心；高级牌型则不因难以形成而自动保证收益更高。

### 流派涌现与自然联动

流派应当是玩家利用公共规则后观察到的构筑结果，而不是内容先声明的固定套装。功法优先生产、修改或消费公共状态与公共语义，例如牌区、留手、真气属性与异状、牌型结构、功法序列、连势、协同、额外行动、防御、反震和延迟效果。两门功法只要分别对同一公共对象提供生产与消费关系，就应能自然协作，不要求彼此写明功法 ID。

联动设计不得依赖“装备甲功法时乙功法额外生效”一类封闭硬配对，也不得在中央战斗流程中按功法 ID 添加分支。需要新战斗语义时，可以新增边界清楚、可被多门内容复用的小型效果处理器；只有多个来源和多个消费者确实需要观察同一事件时，才新增通用战斗时点或权限端口。

本轮整体审计继续采用“改现有功法形成桥接”的原则，不为单次联动额外扩充功法池：林·易形扩大临时牌阶调整面，风·断页用燃尽顶牌连接火·暗薪，山·擂关把邀战达标结果转为连势，火·护势只压缩公开说明而不改运行语义。AI辅助语义标签使用[敌方AI](../ai/70-enemy-ai.md)冻结的词表；标签不参与战斗规则，也不能代替效果链。

### 四属性底层系统

风、林、火、山共享同一牌池和战斗规则，不是四个隔离角色。属性归属主要由功法读取和操作的底层对象决定，不由最终输出是伤害、防御或抽牌决定。

| 属性 | 主要底层系统 | 核心输入 | 常见操作与公共接口 |
| --- | --- | --- | --- |
| 风 | 卡牌与牌区 | 敌我手牌、占脉数量、牌库、弃牌堆、待出区的位置、顺序与可用时机 | 抽牌、寄脉、明确弃牌、控顶、定向检索、回手、洗回、夺取、交换；风引、乱流、重聚与临时属性重塑 |
| 林 | 真气实例与生命周期 | 牌阶、属性、有效真气值、重塑、异状、跨牌区保留与清理 | 回收、培育、临时牌阶、带虚无的战斗临时真气、净化、附毒、炽气／枯气、成长／衰败，以及损失与恢复的转化 |
| 火 | 功法运行 | 独立序列、成功与失败、同组重触、协同后续组、攻击段与延迟结算 | 推进、重触、串联、追击、连势、连击、燃命、燃尽、真伤与高频响应 |
| 山 | 牌型结构 | 精确牌型、参与牌、额外牌、主副结构、频率、投入和数值规模 | 稳定结构、读取结构差异、把投入转为防御、反震、破绽、延迟收益或终结效果 |

四层形成循环：

```text
风调度牌区资源
→ 林改变具体真气的生命周期与状态
→ 山读取真气形成的牌型结构
→ 火运行该精确牌型当前功法并传播效果
→ 结果再次改变牌区、真气、成型机会与后续功法运行
```

风与林都可以移动牌，但主要读取对象不同：风关心资源从哪里移动到哪里以及移动本身的收益；林关心同一张真气经过留手、消耗、入堆、回收和再利用后怎样成长、衰败、净化或转化。火可以有限改写功法运行，但仍遵守每组默认只触发当前一门、同组重触不播放后续功法、成功只推进一格和禁止自身递归。山在识别后读取结构，不能追溯改写本次结构。

生命、防御、伤害、真伤、毒、破绽、封穴、封禁、标记、触发队列、连击、协同、反震和延迟效果都是四属性之间的公共连接接口，不属于某一属性独占。

本源、强化和印记等永久重塑主要由战斗外成长内容完成。普通功法不得在战斗中永久改造基础牌组；需要临时模拟强化、属性身份或牌阶时，使用对应的临时重塑槽，并写明目标、覆盖和移除规则。功法生成的战斗临时普通真气默认获得虚无，除非正文明确豁免；净化移除虚无后，该牌仍在战斗结束时清除，不进入本局永久牌组。

第一版不普遍加入取消整门功法或中断整次行动的硬反制。反制优先使用枯气、衰败、毒、封禁、封穴、明确弃牌、消散、防御、反震和直接功法值修正等可见手段。随机只是结算方式，不单独构成流派；风险收益应来自玩家能够理解的代价与回报。
