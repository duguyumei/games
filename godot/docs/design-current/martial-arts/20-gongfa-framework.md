### 2.4 功法

功法是绑定牌型的战斗效果。牌型提供结构、参与牌、功法池与出招频率；参与牌的属性集中数提供基础功法倍率。功法把这些输入转换为伤害、防御、牌区变化、异状、连击、协同或其他结果。牌型本身不自动造成伤害。

每个牌型组按下列顺序处理：

```text
识别最高精确牌型
→ 结算参与真气的贡献与功法倍率，得到初始功法值 P₀
→ 结算直接功法值固定／百分比修正，并按连势规则得到最终功法值 P
→ 检查当前序列功法的牌型、属性与其他条件
→ 将成功功法与同一时点的已装备内功加入可见触发队列
→ 结算伤害、防御、异状、牌区变化与延迟效果
→ 将打出的牌置入弃牌堆或按效果移出
→ 结算出牌结束与留手效果
→ 成功功法推进该精确牌型序列；失败功法停留
```

`P₀`、`P`、连势快照与同组重触规则分别以[牌型、真气值与倍率](../combat/10-hand-ranking-and-values.md#22-真气值与数值计算)和[行动结算](../combat/12-action-resolution.md#同一时点的触发队列)为准。功法若根据自身规模产生连势，必须读取 `P₀`，不能读取已经加入连势的 `P`。

若主牌型功法建立协同，在主牌型开始结算前先锁定全部协同组；主组与协同组依次独立完成完整流程。全部组结算结束后，才结算整次行动的同气槽收益或其他额外行动。

### 五个基础功法池

功法按牌型的底层结构归入五个基础池：

| 基础功法池 | 可以读取该池的精确牌型 |
| --- | --- |
| 高牌池 | 高牌 |
| 对子池 | 一对、两对；葫芦交叉读取 |
| 三条池 | 三条；葫芦交叉读取 |
| 顺子池 | 顺子 |
| 炸弹池 | 四条、五条 |

当前运行时五个普通正式功法池已经开放，共 169 门：高牌 49 门、对子 38 门、三条 27 门、顺子 26 门、炸弹 29 门。高牌池由[首批 25 门高牌功法](./24-gongfa-high-card-pool.md)与扩展正式索引中的 24 门组成；其余池及扩展高牌的稳定 ID 见[扩展功法正式索引](./28-gongfa-expanded-formal-pool-index.md)，详细效果正文由[蛊毒](./25-gongfa-poison-candidate-pool.md)、[成长](./26-gongfa-growth-candidate-pool.md)、[跨系统桥接](./27-gongfa-bridge-candidate-pool.md)、[山·阵势与壁垒流](./29-gongfa-mountain-candidate-pool.md)与[风·运转与扰乱流](./33-gongfa-wind-pool.md)文档维护。此前 107 门旧流派候选已经整体归档，不属于当前活跃名单。

[山·阵势与壁垒流正式目录](./29-gongfa-mountain-candidate-pool.md)记录 56 门山系正式功法，其中本批 49 门均已完成独立资源、运行时、AI／UI／历史投影和专项测试，并进入上述 169 门普通正式数量、心得随机池、奖励池与装配统计。加上散招、守招两门基础通用功法，当前正式资源总数为 171。

本批已经删除`林·蛊壳`与`林·落叶归根`，新增4门林功法，并把风系扩展为51门。当前普通正式功法为169门：高牌49门、对子38门、三条27门、顺子26门、炸弹29门；扩展索引记录144门，另加首批25门高牌。再加两门基础通用功法，正式资源总数为171；奖励池、心得候选、修习商店和装配统计均已同步，`production_sequences.json`保持不变。

**基础通用功法（2 门）**

- **散招**：ID `basic_scatter`；造成 `floor(P/4)` 点普通伤害。
- **守招**：ID `basic_guard`；获得 `floor(P/4)` 点防御。

二者均使用最终功法值 `P`，`P<4` 时结果可以为 0；永久可用、适用于八种精确牌型、基础装配上限各为 99。它们不属于五个普通功法池，不进入购买、奖励、心得随机池或已习得功法统计，但在战斗中仍是真实功法，读取连势、受功法权限影响并正常推进序列。

高牌可以由任意手牌主动打出，承担启动、保底、过渡和低成本铺垫作用；它也可以在获得足够系统支持后成为独立主牌型。高牌表示没有形成更高结构时的散手，不是其他牌型自动包含的公共结构，因此其他牌型默认不能读取高牌池。高牌功法可以在效果正文中读取本次打出的全部散牌，但默认只有最高的一张参与数值计算。

五条与四条共同读取炸弹池，但各自拥有独立槽位、序列和进度。五条心得正常进入普通心得池，不以当前牌组能否立即组成五条为生成条件。

葫芦从对子池与三条池的去重并集中获得候选：

- 对子池功法默认按一对分支结算；
- 三条池功法默认按三条分支结算；
- 功法显式提供葫芦分支时，葫芦精确分支优先；
- 同一门功法若未来同时归入两个池，在葫芦候选中只出现一次，不增加权重；
- 当前一门功法仍只拥有一个正式池归属。多池单功法在葫芦下应继承哪个默认分支尚未确认，因此暂不开放多池数据结构。

基础池只决定一条精确牌型序列可以配置哪些功法，不合并不同牌型的参与牌、固定倍率、槽位或序列进度。

### 功法槽位、心得与循环序列

每个精确牌型拥有独立的循环功法序列和序列指针。每个精确牌型初始拥有 1 个功法槽位；使用对应心得时：

1. 该精确牌型槽位 +1；
2. 从它可读取的正式功法池并集中，随机获得一门尚未加入该精确牌型当前序列的功法，并默认填入新增槽位。

若没有符合资格且仍有有效装配次数的普通功法，新增槽位依次使用散招、守招补满；两者都达到上限时整次心得失败并完整回滚。

玩家八种永久序列必须全部满足 `slot_count>=1` 且 `sequence.size()==slot_count`，不得保存空值或未填槽。普通功法在八种序列中合计默认最多装配 1 次；基础通用功法各最多 99 次。有效次数由纯查询 `technique_loadout_copy_limit_query` 统一修改，查询失败时提交失败关闭。配装提交以候选牌型和其他七种当前序列组成完整快照，原子校验后才替换状态。

每条序列遵守：

- 战斗开始时指向第一门；战斗结束后重置，除非内容明确改写；
- 每次打出该精确牌型，只尝试当前指向的一门功法；
- 功法满足全部条件并完整成功结算后，序列前进一格，末尾回到第一门；
- 功法失败时不产生效果、不推进序列，也不使用或清空连势；
- 同组重触复用该组原功法与冻结的 `P₀`、`P`，无论重触多少次都只推进一格；
- 协同后续组不是重触，会读取当时的序列位置并独立计算；
- 玩家永久配装不存在空序列；调试夹具或敌人显式空序列仍不产生功法效果；
- 战斗开始后序列内容与顺序锁定，普通装备操作不能临时重排。

### 功法条件

功法的真气条件分为：

```text
通用功法：只限制牌型
属性功法：限制牌型，并要求参与最高牌型的真气中至少有指定数量属于某属性
纯属性功法：限制牌型，并要求全部参与最高牌型的真气都可以视为指定属性
```

属性功法必须同时写明属性与数量。默认只检查参与最高牌型的真气，不检查额外打出的真气或仍在手中的真气；正文可以明确例外。混元与临时属性重塑参与属性识别，明确读取基础属性时仍读取真气本体。

功法只能读取已经识别完成的本次牌型，不能追溯把本次最高牌型改成另一牌型。改变顺子长度、牌阶关系、默认参与范围等识别前规则，应由内功、物品或其他在识别前生效的内容承担。

### 普通功法的即时落点

除非明确标为特殊功法，否则每门普通功法必须：

- 至少立即造成伤害或立即获得防御；
- 至少有一项实际结果有意义地读取 `P`；
- 随机目标或合格目标不足时，仍结算即时伤害或防御；
- 延迟效果建立时冻结需要的 `P₀`、`P` 与派生值，之后不因其他行动变化，除非正文明确重新读取。

标准模板优先使用“即时伤害或防御 + 一个主要机制 + 可选条件强化”。建立连击或协同、大规模转换牌区、大量创建／复制／移除临时真气、终结性爆发或带显著代价的规则改写，可以作为少量特殊功法省略即时落点，但仍必须有清楚的成功条件、失败边界与数值输入。

功法效果不应只为单门内容新增封闭资源。优先读取现有牌区、真气异状、重塑、牌型结构、功法序列、生命、防御、连势、反震、额外行动与延迟事件；只有多个效果能够生产、读取或消耗，且现有状态无法表达时，才新增公共状态。

### 牌型定位与效果权限尺度

八种精确牌型的功法定位必须从牌型自身的成型难度、出牌投入、出现频率、可保留性、可拆分性和升级路径中推导，不能先预设流派，再把与底层战斗规则无关的效果硬套给某个牌型。

牌型强弱不是无条件的线性升级关系。不同牌型应提供不同的战术用途；功法之间可以存在局部替代，但不能让高级牌型的全部功法都只是低级牌型功法的数值上位替代。低级牌型通常以稳定、灵活、低投入或高频率形成价值；越难形成、投入越大或越少见的高级牌型，通常越有资格获得更具威胁性、影响范围更大或更独特的效果权限，而不只是更高倍率。

这一梯度是评审功法时使用的软性设计尺度，不是硬性的牌型禁用表。具体效果仍需结合触发条件、即时收益、战内后续收益、序列位置、重复装配、重触、协同、额外行动与敌方反制综合判断。系统支持也可以令低级牌型成为构筑核心；高级牌型则不因难以形成而自动保证收益更高。

### 流派涌现与自然联动

流派应当是玩家利用公共规则后观察到的构筑结果，而不是内容先声明的固定套装。功法优先生产、修改或消费公共状态与公共语义，例如牌区、留手、真气属性与异状、牌型结构、功法序列、连势、协同、额外行动、防御、反震和延迟效果。两门功法只要分别对同一公共对象提供生产与消费关系，就应能自然协作，不要求彼此写明功法 ID。

联动设计不得依赖“装备甲功法时乙功法额外生效”一类封闭硬配对，也不得在中央战斗流程中按功法 ID 添加分支。需要新战斗语义时，可以新增边界清楚、可被多门内容复用的小型效果处理器；只有多个来源和多个消费者确实需要观察同一事件时，才新增通用战斗时点或权限端口。

### 四属性底层系统

风、林、火、山共享同一牌池和战斗规则，不是四个隔离角色。属性归属主要由功法读取和操作的底层对象决定，不由最终输出是伤害、防御或抽牌决定。

| 属性 | 主要底层系统 | 核心输入 | 常见操作与公共接口 |
| --- | --- | --- | --- |
| 风 | 卡牌与牌区 | 敌我手牌、占脉数量、牌库、弃牌堆、待出区的位置、顺序与可用时机 | 抽牌、寄脉、明确弃牌、控顶、定向检索、回手、洗回、夺取、交换；风引、乱流、重聚与临时属性重塑 |
| 林 | 真气实例与生命周期 | 牌阶、属性、有效真气值、重塑、异状、跨牌区保留与清理 | 回收、培育、临时牌阶、带虚无的战斗临时真气、净化、附毒、炽气／枯气、成长／衰败，以及损失与恢复的转化 |
| 火 | 功法运行 | 独立序列、成功与失败、同组重触、协同后续组、攻击段与延迟结算 | 推进、重触、串联、追击、连势、连击、燃命、燃尽、真伤与高频响应 |
| 山 | 牌型结构 | 精确牌型、参与牌、额外牌、主副结构、频率、投入和数值规模 | 稳定结构、读取结构差异、把投入转为防御、反震、破绽、延迟收益或终结效果 |

四层形成循环：

```text
风调度牌区资源
→ 林改变具体真气的生命周期与状态
→ 山读取真气形成的牌型结构
→ 火运行该精确牌型当前功法并传播效果
→ 结果再次改变牌区、真气、成型机会与后续功法运行
```

风与林都可以移动牌，但主要读取对象不同：风关心资源从哪里移动到哪里以及移动本身的收益；林关心同一张真气经过留手、消耗、入堆、回收和再利用后怎样成长、衰败、净化或转化。火可以有限改写功法运行，但仍遵守每组默认只触发当前一门、同组重触不播放后续功法、成功只推进一格和禁止自身递归。山在识别后读取结构，不能追溯改写本次结构。

生命、防御、伤害、真伤、毒、破绽、封穴、封禁、标记、触发队列、连击、协同、反震和延迟效果都是四属性之间的公共连接接口，不属于某一属性独占。

本源、强化和印记等永久重塑主要由战斗外成长内容完成。普通功法不得在战斗中永久改造基础牌组；需要临时模拟强化、属性身份或牌阶时，使用对应的临时重塑槽，并写明目标、覆盖和移除规则。功法生成的战斗临时普通真气默认获得虚无，除非正文明确豁免；净化移除虚无后，该牌仍在战斗结束时清除，不进入本局永久牌组。

第一版不普遍加入取消整门功法或中断整次行动的硬反制。反制优先使用枯气、衰败、毒、封禁、封穴、明确弃牌、消散、防御、反震和直接功法值修正等可见手段。随机只是结算方式，不单独构成流派；风险收益应来自玩家能够理解的代价与回报。
