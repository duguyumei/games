### 2.5 内功

内功承担类似《小丑牌》的常驻规则改写：

- 可以改变抽牌、弃牌、倍率、牌型识别或功法触发条件；
- 暂设四个档位，档位主要用于出现概率与内容组织，不决定固定价格；
- 每门已装备内功占用一个栏位；基础容量为 6，物品、内功或其他明确效果可以修改有效容量；
- 不绑定某一个普通牌型，除非内功文本明确这样写。

获得的内功进入本局内功库，不会因为六个装备栏位已满而自动替换、遗忘或出售已有内功；未装备内功保留但不生效。每个内功必须在文本中明确自己的触发时间，例如玩家回合开始、出牌、玩家回合结束、战斗胜利、完成节点或进入修习。内功不能在同一次出牌中无限生成牌型或递归触发功法。

功法是“某个牌型出现时做什么”，内功是“整套牌组和战斗规则如何被改写”，两者不能混成同一类效果。

功法可以建立立即效果、有限回合效果、敌方标记，或者具有明确层数／次数且耗尽后移除的延迟效果。原则上，持续整场反复读取状态、使用“每当”“每第几次”“实时读取”等文本且没有耗尽时点的我方永久功法增益，应设计为内功，而不是功法。

已装备内功可以被明确效果临时压制。压制期间它仍占据原栏位并保留装备顺序，只是不为被禁止的触发建立新结算；压制不等于卸下或遗忘，也不撤销已经建立的延迟效果，结束后自然恢复。

同 ID 多副本、一次合格触发的额外执行，以及复制另一来源的规则正文是三种独立规则。多副本会建立多个装备来源；额外执行由同一来源连续建立多个 invocation，后一遍读取前一遍结算后的最新状态，且额外执行本身不递归产生更多额外执行；复制能力另行定义，不能用含义不明的统一“重复”布尔代替。

需要跨战斗或跨节点保留进度的内功，必须通过 Handler 显式声明本局整数计数器；不得在成长库存中为每门内功增加专用字段，也不得保存任意 Dictionary、对象或脚本状态。纯查询只能读取已声明计数器，只有已提交事件可以修改；查询、预览和失败结算均不能推进进度。计数器可以选择保留到本局结束，或在内容最后一个已获副本永久失去时清除；卸下、调整装备顺序和临时压制都不清除。

当前没有持久副本 ID，因此计数器身份由来源类型、内容 ID、behavior 的稳定 `state_key` 与 `counter_id` 共同组成。同 ID 多副本共享内容级进度，不是每个装备栏独立进度；多个副本若分别成功触发，可以依次增加同一个计数器。未来若确认需要逐副本成长，必须先建立持久副本 ID，不能用装备槽位、来源顺序或数组下标伪造实例身份。本协议只建立平台能力，不使任何候选内功成为正式内容。
