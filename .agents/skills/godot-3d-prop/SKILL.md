# Godot 3D 道具程序化制作

全部几何/贴图/文字由 @tool 脚本实时生成（BoxMesh 拼块＋运行时贴图画线＋Label3D），零外部模型文件；好处＝全参数化、语义件可挂状态与动画。上手先读项目 `AGENTS.md` 工作约定与工程教训速查，本 skill 是其道具分支的展开。

## 铁律（违反＝返工）

1. **独立 demo 交付**：新道具一律 `previews/mN_<物>_demo.tscn`（N＝道具族序号），绝不直接挂 studio / 对局场景——上桌是另一次拍板。用户令「做个模型给我看看」＝给他编辑器过目，不是进游戏。
2. **@tool 必挂**：组件脚本 `@tool class_name MN<Xxx> extends Node3D`——编辑器只执行 @tool，不挂＝编辑器里隐形（历史上两次翻车）。demo 场景根协调器不挂 tool。
3. **用户可调项一律检查器导出**（`@export` + setter→`_rebuild()`）：尺寸/颜色/位置/开关；写死脚本常量＝没收用户调参权。
4. **一次只交一个可裁决单元**：先单件过目，形定了再组装（多本/叠放/摆位）——用户评审节奏如此，一次塞多个新参数必被逐个推翻。
5. 源文件手术只用 Edit/Write 工具；改脚本/tscn 后运行中实例不热重载，重启再验。
6. **观感裁决归用户**：agent 不截图自验、不对自家渲染跑图像分析、不出口观感结论（「成色好」禁语）；agent 只做 validate＋几何探针＋run_checks。用户点名的外部参考图调研除外。

## 七步工作流

1. **定语义**：道具承载什么游戏语义（亮/暗态、点击发动、发光…）？哪个部件是「核心像素」（如武学名＝必须最可读，一切版式让它）？
2. **量参考**：有参考图＝像素实测（见下节），禁止拿训练印象/书本知识直接上参数。
3. **参数化**：比例/颜色/布局全变 @export；参考图内有分歧的项（如签位左右）参数化留给用户拧。
4. **程序化建模**：介质选择见「细节选介质」。
5. **独立 demo**：`previews/mN_xxx_demo.tscn` ＋ 参照物（`scenes/mahjong3d/mj3d_blank_tile.tscn` 一张牌定尺度）＋同款 Environment/Sun/机位（抄上一个 demo 的 tscn）。
6. **数字验证三件套**：validate → 运行时探针 → run_checks。
7. **交用户过目**→按否决点迭代，每轮只修被点名的项。

## 参考图实测法（引用纪律）

- **数字必须实测**：图落本地 → PIL 连通域取**单件** bbox（多件并排图必须取最大连通域，整图框必错）＋视觉模型报数交叉。纯像素阈值测浅色区域易吃整面底色——比例以连通域框＋视觉报数互核为准。
- 色值结论必须程序采样，不信图像分析器报色。
- 训练印象（「XX 通常是什么比例」）只能标「假设」；不实测不上参数。（教训：拿古籍开本 1.7–1.9 顶替，用户参考图实测 1.25–1.40，两版白做。）
- 用户贴参考图＝参考截图挖掘模式：量化提取（比例/构造/位置）逐项落进实现，输出对照表（参考值/实现值/是否已合）。

## 构造语汇与解剖自洽

- 观众**先读构造语汇再读细节**：硬壳 vs 软面、西式书背 vs 订线、白页 vs 纸黄、方形 vs 修长——语汇错了细节全白搭。建完自查一句：「哪个体裁信号在骗人？」
- **解剖要整组同推**：单部件位置对≠整体对（书脊在左、书口在右、签贴右、首字在远端——一个方向量定全组）。建完自查部件相对关系。
- 用户审美可推翻语汇纯度（非严格古籍的色脊/订绳，参考图如此就照做）——照办并记档。

## 细节选介质

| 细节类型 | 介质 | 要点 |
|---|---|---|
| 线/纹/符（装订线、边饰、纹样） | **运行时贴图画**（`Image.create`＋`fill_rect`→`ImageTexture`） | 绝不拿小方块拼线（必被读作断线）；透明底只含线，贴 ArrayMesh 覆膜（TRANSPARENCY_ALPHA＋UNSHADED＋双面） |
| 块状结构 | BoxMesh | 圆角/曲率面数只花在屏幕可见处 |
| 文字 | Label3D | **每字一节点**精确控距（多行行高不均）；**栅格 font_size ≥256px**（64px 在 2× 窗口被放大＝糊）；`pixel_size = 世界字高 / font_size`；平面躺字 `rotation_degrees.x = -90` 首字在远端 |
| 连续闭环件（绕多面走线） | 多面覆膜共享坐标 | 见下 |

**连续件端点审计**：所有面共享同一套世界坐标（主干位置、站点公式同源，各膜按自身世界跨度换算像素）；每段线的两端必须**落面棱或落交点**——「看起来连」不算。探针做：贴图逐行/逐列连续断言＋面间世界坐标对齐（站点 z 互差 ≤2mm、角点 y 同高）。**多层件先查层间遮挡**：实体唇沿（如书脊包边顶面）高过覆膜平面 0.5mm 就会遮断贴图线——先保证层序/高度再谈贴图对齐。

## 验证三件套（每版必跑）

1. **validate**：godot-play `validate`（targets 批量：scriptPath/scenePath）。
2. **运行时探针**：`run_project(background=true, scene=demo)` → `run_script` 数值断言 → `stop_project`：
   - 正向：部件齐全、位置/朝向/AABB、投影在屏（unproject）、色值实采（albedo 对比）。
   - **负向**：被否旧件不复活（`get_node_or_null("旧件名") != null` 即败）。
   - 连续件：像素级连续＋面间对齐（见上）。
   - 面朝向存疑：MeshDataTool 读面法线，不靠手推。
3. **run_checks**：先确认无残留 godot 会话（占 McpBridge 端口＝全系假红）；新增 class_name/资产用全量、纯改用 quick。

## Godot 专属坑（道具相关速查）

- **前面＝顺时针绕序**：按 OpenGL 逆时针手推 cross 必翻；自建面片绕序存疑一律探针读面法线。
- **PlaneMesh UV 朝向不确定**：要锚定 u=0 在某侧时自建 SurfaceTool quad 自定 UV。
- 重建型组件清理＝`remove_child`＋`queue_free`；@tool setter 链 guard `is_inside_tree`；子件 owner 留空不入档（位置拖根节点）。
- 探针 GDScript：无列表推导（用 `.map(func(...))`）；Array 取出的 Variant 显式转型（`float()`/`int()`）再声明类型。
- 压暗/亮暗态实现＝`_tone(c)` 全件 albedo 乘系数，暗态色探针可断言。

## 评审循环经验

- 用户给方向＋纠错、不定需求：agent 独立完整推演，但**未确认的参数不自作主张**——字体/比例/颜色/布局每个都是独立裁决点。
- 用户指令可能带降级路径（「做不好就画线」）——照路径执行，别硬撑原方案。
- 被否后一次一个做透；每版改动小（一个否决点一轮），探针断言随版本累积成防回归资产。
- 每版收尾同步：AGENTS.md 活事项＋复盘归档（只记用户原话与对原话分析）＋记忆，挂账写明。
