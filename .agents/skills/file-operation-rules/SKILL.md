# 文件操作规则

## 修改闸门

1. 默认只读。分析、审计、讨论和回答不写入文件。
2. 用户首次提出实现、修改、记录、写入、创建、删除、重命名或格式化时，先检查现状并报告准确路径、拟执行操作、改动范围，以及是否新增、删除或重命名文件。
3. 收到用户下一条明确的二次确认前，不得写入文件。
4. 二次确认只覆盖已报告的路径、操作和范围；任一项改变时，重新报告并重新取得确认。
5. 会产生文件变化的命令同样属于修改，包括生成、格式化、代码生成、迁移和安装仓库内依赖。

## 范围与保留

- 只操作已确认的目标，不顺手修复无关问题。
- 不自行新增文件；确需新增时，先说明原因、路径和必要性，并取得针对该文件的明确授权。
- 不删除、覆盖或重命名已有文件，除非操作已经包含在确认范围内。
- 保留工作区已有改动，不使用破坏性命令清理或回滚。
- 修改使用 `apply_patch`，避免不可逆的批量覆盖。

## 权威记录

- 权威记录文件只保存当前有效规则、当前术语和当前实现边界。
- 不写入讨论过程、错误假设、失败方案、弯路、比较过程、变更历史、迁移说明或重复解释。
- 机制替代时直接重写为新规则，并删除旧定义、旧示例、旧术语、旧交叉引用和基于旧规则的审计结论。
- 删除机制时完整清理其定义、触发条件、数值、示例、界面说明、测试条目和索引，不保留“曾经、原来、改为、已废弃”等历史叙述。
- 每条规则只保留一个权威定义；其他章节使用交叉引用，避免复制同一机制。
- 写入前确认记录对象和边界，避免把未确认的暂名、推测或讨论意见固化为规则。

## 写入后检查

- 写入完成后检查目标文件差异、文件列表和关键结果，确认没有超出批准范围。
- 搜索已删除机制的关键词、冲突术语和重复定义，确认权威文件只剩当前规则。
- 运行与目标文件直接相关的校验；发现范围外变化、冲突或验证失败时停止扩展修改，只报告问题。
