## 4. 模块设计

### 4.1 `core/run/run_state.gd` —— 组状态机

唯一事实源；场景只读、按钮调方法；不做 IO。

```gdscript
func start(deck_id, seed) / func opponent_id() -> String
func build_match_cfg() -> Dictionary    # deck 基础数值＋neili＋loadout＋pailing＋hp 带入；seed＝battle_seed()
func apply_result(winner: String, player_hp_fp: int, beats: int) -> String
    # 返回 "settlement"（胜且还有下一战：wins+1、index+1、hp 带入、内力+1、解锁洗点）
    #      "victory"（胜且组终：D14——不加内力不发历练不三选一，phase=victory）
    #      "defeat"（负：phase=over）
func grant_lianli() -> int              # 仅 battle_index 0/1 有值；敌③返回 0
func alloc_neili(...) / acquire_wuxue(...) / acquire_pailing(...) / unlock_slot(kind)
func heal(amount_fp) / func is_group_clear() -> bool
```

⚠ 架构盯防（沿用）：RunState 上帝对象候选——多组化时先拆 cfg 装配器。

### 4.2 `core/run/shop.gd` —— 修习（货架/重掷/开槽/疗伤丹）

`roll_shelf`（武学×2＋牌灵×1，去重）｜`reroll_cost`｜`buy`｜`buy_heal`（限购 1/次修习，即买即用）｜`slot_unlock_cost`｜`roll_wuxue_pick3`（只刷有空位类型）。
确定性：全部由 `run_seed + battle_index + reroll_count` 派生，档里不存货架。
修习屏四区：抽选货架｜疗伤丹固定格｜开槽区（三轨按钮达顶置灰）｜洗点（锁死态禁用）。

### 4.3 `core/run/run_session.gd` —— 场景交接

DojoConfig 同模式。`mahjong_battle` `_ready` 按 active 分叉注入；`_show_result` 按 apply_result 返回值分三路（settlement/victory 屏/hub 失败态）；顶栏返回在挑战模式指 hub（弃战回锚重打）。

### 4.4 `core/run/run_saver.gd` —— Saver 主档（D9/D16）

```gdscript
class_name RunSaver
const SAVE_VERSION := 3
const SAVE_PATH := "user://mj_run_save.json"
static func save(state) / load() -> RunState / clear() / has_save() -> bool
```

- 档内容＝to_dict 全字段＋version；**写穿式（D16）**：`save` 在每次状态变更后被场景调用（购买/开槽/洗点/绑牌灵/入账/phase 变更），同步写小文件（KB 级，成本可忽略）。
- 检查点表（phase 变更＋变更即写的合流表述）：begin→hub｜迎战→battle｜胜(非组终)→settlement｜结算确认→xiuxi｜修习继续→hub｜胜(组终)/败→**clear**。
- 恢复：load() → 按 phase 路由（battle→hub 重打该战同墙；settlement/xiuxi 重进原屏，货架种子重摇还原）。
- 坏档：解析失败/版本不符→改名 `mj_run_save.bad.json` 留证、按无档开局，绝不静默覆盖。
- ⚠ 对照我地麻：其 GameSaverUtil 队列＋防抖＋超时强存为大档＋Steam 云异步而生；我们 v1 写穿同步写，升格条件＝多组化/云存档（与备份档同批）。

### 4.6 牌灵 `core/mahjong/pai_ling/`（一类一文件）

`MJPaiLing { id, tile, register(hooks, side) }`＋`summary()`（图鉴/绑定 UI 用）。首发四枚：灵罡（TILE_DRAWN→罡气+1）｜灵重（TECH_FIRE 标记→TECH_RESOLVE pct_bonus+30）｜灵变（POSTURE batch 含绑定牌→变招充能+1；反击批次 kind=counter 同计）｜灵甲（TILE_DRAWN→下次护体免伤+10）。

### 4.9 图鉴重构（D15，`scenes/codex/` ＋ `core/codex_state.gd`）

**先说我方现状的问题（用户直觉确认）**：现行图鉴是"退役内容的博物馆"——真气页展示 v2.2 的风火山丹珠（v3 真气已是万/筒/条）、功法/内功页全是 v2.2 旧数据（点星式/崩山式等已随 v3.5 退役的件）、新内容一件不在——它既不反映现行战斗，也没有任何收藏目标感。

**我地麻的做法（其档 §9，证据摘要）**：图鉴（Illustration）＝发现制收藏闭环——主面板 Tabs＋子页（灵俑/遗物/祭品/番种/成就＋Boss 详情）＋全局搜索；条目默认「未发现」剪影，对局中获得/遇到才点亮（发现）；未解锁条目可花"修为"购买解锁（图鉴兼解锁商店），成就/兑换码也发解锁；稀有度分组、"总表(含未解锁/已解锁)"双视图、收藏完成度百分比；收藏持久化在主档（HadXiaoChouList 等）。

**我们的重构（按池子规模裁剪，分层采纳）**：

| 收藏完成度百分比 | 采纳：图鉴头部「收藏 x/y（z%）」 | — |
| 收藏持久化 | **账号级新档** `user://mj_meta.json`（`core/codex_state.gd`，写穿；与 run 档分离——收藏跨局存活，正是我地麻 HadXiaoChouList 的位置） | — |

## 8. 实现级默认（agent 钉死，逐条可翻案）

4. 货架配比武学×2＋牌灵×1；疗伤丹固定第四格、不参与重掷、每修习限购 1、即买即用。

7. 洗点校验总量守恒；首战锁死＝UI 禁用。
8. 组内三战重掷/疗伤限购独立计数（每次修习重置）。
9. 敌方牌灵只留数据位不实配。
10. 胜负沿用引擎 winner；无平局分支。
11. 坏档＝改名 .bad＋按无档开局；备份档/存档队列为升格路径（多组化/云）。
12. 池尽明码「宝山已空」。
