# 战斗系统 v1：设计与 Godot 实现规格

版本：v1.0  
状态：第一版战斗原型基线  
用途：统一战斗设计、规则边界和 Godot 战斗沙盒实现范围

## 1. 设计目标

战斗的核心不是等待随机抽到某张牌，而是：

1. 玩家提前准备真气牌库、心法、功法和兵器。
2. 每回合从自己的真气牌库中获得一组有限输入。
3. 玩家根据当前手牌，主动选择要追求的牌型和要施展的功法。
4. 敌人的手牌隐藏，但下一步功法意图公开，玩家可以据此安排应对。
5. 战斗中的真气使用有明确消耗，使玩家在本回合和后续回合之间做取舍。

第一版优先验证“构筑目标是否能被主动追求”和“战斗决策是否清楚”，不加入未经验证的状态大系统。

## 2. 战斗单位

玩家和敌人使用同一套战斗底层。每个战斗单位包含：

- 气血。
- 护境。
- 真气牌库、抽牌堆、手牌和弃牌堆。
- 已装备的心法。
- 已装备的功法。
- 当前兵器。
- 当前回合的临时效果。

第一版不设置独立的“角色总内力”数值。内力只通过真气牌的基础内力和本次传输计算体现。

## 3. 真气卡牌

### 3.1 卡牌本体

玩家可见的设计字段只有两个：

```text
属性：风、林、火、山之一
基础内力：正整数
```

程序内部可以有 `card_id` 用于识别卡牌，但它不是玩家需要理解的战斗属性。

第一版不在真气卡牌上设置“状态”字段，不实现冻结、封存等卡牌状态。

### 3.2 属性

本项目固定使用四种属性：

```text
风、林、火、山
```

属性默认只参与：

- 功法的属性条件。
- 真气牌库构筑和流派倾向。
- 未来可能的心法或功法特殊效果。

属性本身不自动提供数值加成。除非某个具体效果明确写出，否则风不会自动加内力，火也不会自动加伤害。

### 3.3 基础内力范围

基础内力是可扩展的正整数，不在系统层固定为1—6。纸面和 Godot 第一版可以暂时使用1—6作为易于测试的样例，但这不是正式上限。

正式牌库的总张数、同属性同数值的复制数量和成长方式属于后续牌库设计，不写死在战斗引擎中。

## 4. 牌型判断

牌型只判断玩家本次明确选择的真气，不自动把整手牌判成最高牌型。

| 牌型 | 严格条件 |
|---|---|
| 高牌 | 选择1张真气 |
| 对子 | 选择2张基础内力相同的真气 |
| 三连 | 选择3张基础内力相同的真气 |
| 四连 | 选择4张基础内力相同的真气 |
| 五连 | 选择5张基础内力相同的真气 |
| 顺子 | 选择5张，基础内力为5个不同且连续的整数 |

补充规则：

- 牌型数量是“恰好选择的牌数”，不是至少选择这么多张。
- 四连、五连指相同基础内力，不是连续点数。
- 顺子不要求属性相同，属性不参与顺子判断。
- 当前没有同花牌型。
- 当前不额外加入两对、葫芦、同花顺等牌型。
- 牌型之间不设强制等级覆盖；玩家选择的具体牌组满足哪一项，就由对应功法决定能否发动。

例如五张基础内力都是5的手牌：

- 选择5张，是五连。
- 选择4张，是四连。
- 选择3张，是三连。
- 选择2张，是对子。
- 选择1张，是高牌。

程序内部使用明确枚举名，不用“连”字推断规则：

```text
HIGH_CARD
PAIR
THREE_OF_KIND
FOUR_OF_KIND
FIVE_OF_KIND
STRAIGHT
```

## 5. 内力计算

### 5.1 三个概念

```text
基础内力：卡牌印刷的固定数值
有效内力：本次输入时，该张牌实际能提供的数值
传输内力：选中的全部真气交给功法后的最终总值
```

有效内力和传输内力不是卡牌本体字段，而是结算时计算出来的临时值。

### 5.2 第一版计算公式

当前第一版没有冻结、削弱等卡牌状态，因此默认：

```text
每张真气的有效内力 = 基础内力
```

一般公式保留未来扩展位置：

```text
有效内力_i = 基础内力_i + 明确作用于该张真气的修正
传输内力 = Σ(有效内力_i) + 明确作用于本次传输总值的修正
```

所有修正都必须由具体心法、功法或战斗效果明确写出，不存在系统自动推断的“其他功法影响”。

属性默认不参与数值加法；属性相关加成必须在效果文字中指定作用层级。

### 5.3 结算顺序

```text
玩家选择真气
  → 判断牌型
  → 计算每张真气的有效内力
  → 汇总传输内力
  → 应用本次功法明确写出的传输修正
  → 结算功法效果
  → 按功法规则处理已使用真气
```

传输内力只在当前功法结算期间存在，不是永久角色属性。

## 6. 真气牌区和使用后处理

第一版只使用三个牌区：

```text
抽牌堆、手牌、弃牌堆
```

### 6.1 默认处理

功法成功结算后，参与本次功法的真气默认进入弃牌堆。

大回合结束时，手牌中没有被使用的真气随机洗回抽牌堆（不放回顶部；C-015 修订 D-021）。

第一版不设置通用的消耗区或蓄势区。以后若某门具体功法需要回流、永久消耗或特殊保留，作为那门功法的明确例外，不扩展为全局默认规则。

### 6.2 牌库循环

- 大回合结束时不洗牌。
- 下一回合从抽牌堆继续抽牌。
- 抽牌堆不足以补满手牌时，先抽完剩余牌，再将弃牌堆洗入抽牌堆。
- 一场战斗结束后，真气牌库恢复为玩家配置的牌库；战斗内进入弃牌堆不等于永久失去真气。

## 7. 功法

每门功法只声明它实际需要的条件，不默认堆叠所有限制。

功法数据至少包含：

- 名称。
- 兵器要求，可为空。
- 牌型要求，可为空。
- 属性要求，可为空。
- 内力门槛，可为空。
- 战斗时机。
- 效果。
- 真气处理方式；默认是弃牌。
- 是否有本回合或整场次数限制；默认无限制。

### 7.1 第一版示例功法

#### 回身卸力

- 牌型：对子。
- 兵器：无。
- 效果：护境覆盖为本次传输内力。
- 真气处理：弃牌。

#### 穿云式

- 牌型：四连。
- 兵器：剑。
- 效果：伤害为 `floor(传输内力 / 2)`。
- 当传输内力达到20时，攻击前额外移除目标2点护境。
- 真气处理：弃牌。

#### 五岳归元

- 牌型：五连。
- 兵器：无。
- 效果：护境覆盖为8，并使下一门功法的传输内力+1。
- 真气处理：弃牌。

“下一门功法传输内力+1”是角色当前回合的临时功法效果，不是卡牌状态，也不产生蓄势牌区。

#### 推掌

- 牌型：高牌。
- 兵器：徒手。
- 效果：造成2点伤害。
- 真气处理：弃牌。

#### 三叠劲

- 牌型：三连。
- 兵器：徒手。
- 效果：造成6点伤害。
- 真气处理：弃牌。

#### 劈山式

- 牌型：高牌或对子。
- 兵器：刀。
- 条件：传输内力至少8。
- 效果：造成7点伤害。
- 真气处理：弃牌。

《借力反打》不作为第一版底层必需机制。以后若保留，作为一门具体的受击时机功法设计，不建立通用“反击架势”系统。

## 8. 心法

心法属于角色的持续能力，不占用战斗行动权。（**已实现**，D-060：小丑牌式被动规则修改器，
5 平权槽，效果词表与数据结构见《27》；运行时＝core/battle/xinfa_runtime.gd，敌我同规则。
原"内功"术语已于 C-031 全局改为"心法"。）

第一版心法只允许两类行为：

- 被动效果：满足触发条件时自动结算。
- 时机效果：在指定的系统窗口自动检查并结算；如果效果需要玩家在窗口内做选择，该选择不等于发动一门功法，也不占用行动权。

第一版不实现冻结、护脉功等状态交互。心法能否修改单张有效内力或本次传输总值，必须在具体心法文字中明确
（落地口径：培元词条走 technique_prepare 点位改写本次传输总值，如 transfer_bonus；选择型效果 v1 一律自动化，
如调息诀换"内力最低那口"）。

## 9. 行动权模型（D-063 换轴，2026-09-10 落地；原"大回合与收势"章节废止）

**行动权是唯一时序令牌**——无先手/后手、无大回合、无收势，只有"现在谁持有行动权"。原设计讨论见《26》§11（定稿块），本节为其战斗权威落点。

### 9.1 战斗开始与第一次行动权

1. 双方起手各纳 HAND_SIZE 口（暂定 6，§9 拍板 #7；调息口径的免费首纳，不占行动）。
2. 第一次行动权：默认玩家；被袭击＝敌方（C-028"敌方先手"的语义改述），只定这一次。
3. battle_start 与 initiative_gain 两个时点依次结算（心法 battle_start 词条在此生效）。
4. 敌方意图在战斗开始即锁定（§9.5）。

### 9.2 原子行动（全部默认结束即转让行动权）

- **发动功法**：选择真气和功法后确认发动；确认前可取消重选，确认后不可取消。
- **调息（吐故纳新）**：弃置全部手牌入气海，从丹田纳 HAND_SIZE 口。气持有即保留——
  不再自动回收，换手唯一途径就是调息（C-015 口径承接）。调息永远是链条终点：**调息
  后行动权必转让，不可连动保留**。世界钟（D-058 未实现）将来挂 breath 点位，每次调息 −1。
- **暂让（过牌）**：这一拍不动、交权，顺从丹田纳 1 口（不弃手牌、不扣行动力、不触发毒发）。
- **用道具**：占一次行动（C-022 维持），例外走道具"即时"词条。
- 截劲：随拆招系统后置。

例外（连动）只能来自词条：**取消 initiative_transfer 动作**（通用 cancel 词条，D-064）＝行动权保留再动一拍，
仅功法/道具类行动有效（调息/暂让后的取消被引擎铁律驳回并强制移交），且必须随意图公开标记（宪法第 6 条）。

### 9.3 僵局保险

连续无功法动作（暂让＋调息，双方合计）达到上限（暂定 12，占位进《10》）→ 平局，视同败北。任何功法发动重置计数。

### 9.4 状态与心法的时点换锚

毒等 battle 域状态随**本人的调息**发作（毒随血行，喘一口气发作一次；别人的喘气不催你的毒）；心法回合类词条同步换锚为 breath 时点（once_per_breath＝每口气一次，以该单位调息计数换界）。

### 9.5 意图系统

- 锁定时机：战斗开始＋敌方每次行动结算后刷新；玩家行动不影响已锁意图（D-025）。
- 显示内容：功法／目标／预计数值＋行动权流向；行动权模型下意图可以是"调息"（敌方换气的公开暴露）。
- 敌方无合法功法时选择调息（换一手）；牌尽气绝才暂让。敌方调息无行动力成本，代价＝交权＋意图暴露。

## 10. 护境和伤害

- 基础规则下每个角色只有一个护境值。
- 新护境直接覆盖旧护境，不叠加，即使新值更低也覆盖。
- 护境跨行动持续（无回合概念，直到被覆盖或消耗）。
- 受到伤害时先扣护境，剩余部分再扣气血。
- 护境不会低于0。
- 强化护境、保留旧护境或制造额外护境，必须由具体功法明确写出。

标准伤害顺序：

```text
功法前置效果
  → 移除或改变护境
  → 伤害先扣护境
  → 剩余伤害扣气血
  → 功法后置效果
  → 处理真气
```

## 11. 兵器

兵器是正式系统的一部分，但第一版先验证兼容性：

- 剑类功法要求装备剑。
- 刀类功法要求装备刀。
- 徒手功法要求徒手。
- 无兵器要求的功法不受兵器类型限制。
- 兵器损坏后，不能满足对应兵器要求；徒手和无兵器要求的功法仍可使用。

兵器耐久字段保留在数据结构中，磨损扣除时机和远征资源压力在战斗规则通过后单独设计，不阻塞第一版战斗状态机。

## 12. 敌人和信息公开

敌人拥有自己的牌库、手牌、功法、心法和兵器，使用与玩家相同的规则底层。

玩家可以看到：

- 敌人下一门已锁定功法。
- 行动类型。
- 目标。
- 预计原始伤害或护境值。
- 明确写出的附加效果。

玩家看不到：

- 敌人当前手牌。
- 敌人抽牌堆顺序。
- 敌人实际使用的真气牌面。
- 敌人没有选中的其他合法功法。

敌人意图锁定后，不因玩家随后选择而临时换招。玩家的护境等公开状态可以按正常结算规则影响最终承伤，但不会改变敌人的已锁定功法。

敌人具体行动优先级属于《敌人行为与 AI 规则》和各个敌人策划，不写入本文件的通用底层。

## 13. Godot 第一版战斗沙盒范围

### 必须实现

- 玩家和敌人的战斗状态。
- 抽牌、手牌、弃牌和牌库不足时重洗。
- 牌型判定。
- 有效内力和传输内力计算。
- 功法合法性检查。
- 玩家选择、取消、确认和行动权切换。
- 敌人隐藏手牌与公开意图。
- 伤害、护境、胜负。
- 兵器兼容性。
- 可复现的调试日志。

### 暂不实现

- 地图移动。
- 搜索点和撤离点。
- NPC、剧情和任务。
- 冻结、封存、气滞等状态系统。
- 通用蓄势区、通用消耗区。
- 正式美术和复杂动画。
- 联网和手机适配。
- 兵器磨损的完整远征经济。

## 14. Godot 模块

```text
CombatState       # 双方战斗状态、牌区和临时效果
FighterState      # 气血、护境、兵器、心法和功法
QiCard            # 属性、基础内力、card_id
PatternEvaluator  # 牌型判断
ForceCalculator   # 有效内力和传输内力
TechniqueResolver # 合法性检查和功法结算
TurnManager       # 行动权、暂让、收势和回合结束
EnemyPolicy       # 隐藏手牌下的确定性策略
CombatLog         # 可复现的规则事件日志
CombatUI          # 显示状态并发送玩家操作
```

规则模块不得依赖 UI；UI 不直接修改气血、牌区或伤害，只发送玩家操作请求。

## 15. 第一版验收标准

战斗沙盒达到以下条件才进入地图原型：

1. 六种牌型判定结果与纸面规则一致。
2. 选牌确认前可以取消，确认后不能取消。
3. 任意一方没有合法功法时不会卡死。
4. 护境覆盖、扣除和跨回合保留结果一致。
5. 抽牌堆不足时才洗弃牌堆。
6. 敌人手牌对玩家隐藏，意图信息完整且不会临时变招。
7. 同一随机种子和相同操作可以重放出相同结果。
8. 可以正常获得胜利、失败和战斗结束状态。
