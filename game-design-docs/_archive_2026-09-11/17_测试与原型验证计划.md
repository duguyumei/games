# 测试与原型验证计划

版本：v1.0  
状态：战斗规则已整理，Godot 战斗沙盒准备开始

## 阶段一：战斗纸面测试

材料：少量真气牌、3–5 个招式、1–2 个敌人。

验证：

- 每回合抽 5 张真气是否有决策。
- 高牌、对子、三连、四连、五连、顺子是否有明显差异。
- 目标流派能否主动构筑出来。
- 牌型不理想时是否仍有可玩选择。
- 敌人行动是否可预测但不无聊。
- 一场战斗是否接近目标时长。

## 阶段二：牌阵探索测试

材料：一副地点牌堆（入口 + 普通地点 + 2 张撤离牌）、容器表、行动力表。

验证：

- 牌叠顺序是否带来"白捡还是血战"的真实方差。
- 处理或无视、翻一半留着是否成为有意义的决策。
- 追兵阈值与力竭是否构成"再贪一件"的真实算术。
- 撤离牌随机位置是否公平。
- 目标流派是否能获得足够明确的追求方向。

## 阶段三：完整远征测试

流程：

```text
据点准备 → 进入地点 → 搜索 → 战斗 → 消耗 → 警觉上升 → 撤离或死亡
```

验证：

- 气血、伤势、药物和兵器磨损是否形成真实压力。
- 玩家是否会主动选择继续深入。
- 撤离是否有足够价值。
- 死亡损失是否有风险但不挫败。
- 重复物是否有清晰用途。

## 阶段四：Godot 战斗沙盒

纸面规则已完成初步审计，开始实现。第一版实现规则正确性和可复现性，不追求正式美术。具体范围以《23_战斗系统v1》为准。

## 阶段五：Godot 牌阵原型

已实现（见《05》与《16》）：地点牌堆生长、牌叠/遗留区、容器统一、行动力经济、追兵拦截、力竭判负、撤离结算；62 项 GUT 测试全绿，含同种子布局一致与整局重放一致。待验证：数值手感（起始行动力、追兵阈值、容器定价）、开包演出、拖拽手感。

## GUT 测试隔离策略（autoload 会话）

C-028 容器返工时暴露的隐患及根治（2026-09-07）：

- **隐患**：`ExpeditionSession` 是 autoload，board 场景测试隐式共享它；board `_ready` 在不在局中时会去续磁盘存档——上一轮 GUT/试玩留在 `user://expedition_save.json` 的局面会被续进来（AP 见底/背包带脏数据/英雄移位），用例结果取决于测试执行历史；测试动作还会覆写真档。
- **根治**（`expedition_session.gd`，仅 autoload 本尊生效、测试自管的裸实例不受影响）：
  - **测试态探测**：命令行带 GUT 运行器（`-s addons/gut/gut_cmdln.gd`）即测试态；编辑器内跑 GUT 不在此列。
  - **存档重定向**：测试态存档指向 `user://test_expedition_save.json`，每轮 GUT 启动清一次残留——真档永不被 GUT 读写。
  - **读档扑空**：测试态 `_read_save` 恒返回空字典——续档/开机补结算是玩家侧行为，board 场景在测试里只会 `start_run` 新开，续不到任何磁盘局面（含本轮 GUT 中途写下的）。
  - **`reset_for_tests()`**：清会话＋测试档。场景类测试（实例化 board.tscn 的）before_each 调用；要确定局面再自行 `start_run(固定种子)`。GUT 不调用被子类覆盖的继承 `before_each`，所以不设测试基类、靠显式调用。
- **钉住**：`tests/test_session_isolation.gd`（重定向/读档扑空含裸实例反向验证/真档零改动/复位清空）；`run_checks` 连跑两轮全绿即跨轮隔离的实证。
