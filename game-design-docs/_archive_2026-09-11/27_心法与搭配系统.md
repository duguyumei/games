## 1. 心法是什么

心法是武者持续运转的心法底子，**不是一次性消耗品，不因远征失败而消失**。战斗中它不占行动权、不主动发动——它改变规则本身：

- 你抽到的真气怎么换（行气）；
- 你这口气催出去有多沉（培元）；
- 你挨打时有多硬（护体）；
- 你的招里藏着什么劲（发劲联动）。

参照系：Balatro 的小丑牌、杀戮尖塔的奇物。**每门心法幅度必须小**（平衡预算：5 门合计 ≈ 1.5 门功法的强度），质变来自组合，不来自单门数值。

### 1.1 三段身份（26 号 §2 拆出定案）

- **系为纲**：风/林/火/山（+通用）——D-046"心法是系的入口"演化为"**心法组合是系的入口**"：5 个槽的系别分布就是流派声明（3 火 2 山＝离火配山镇；5 纯系＝纯系大成）。
- **刚柔为性**：留牌面当构筑方向提示，不上升为系统字段。
- **代价为词条**：负面效果（走火、自损、依赖条件、同修排他）写在具体心法上，不做全局"真气相冲"。

## 2. 数据结构（XinfaData）

`data/xinfa.json`，键=心法名（与 techniques.json 同规）：

```json
"调息诀": {
  "tier": 1,
  "school": "通用",
  "desc": "每回合一次，回合开始后自动将手牌中基础内力最低的真气放回牌库底，再抽一张。",
  "effects": [
    {
      "on": "round_start",
      "phase": "post",
      "when": { "once_per_round": true },
      "do": { "type": "put_bottom_draw" }
    }
  ]
}
```

字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tier` | int 1~5 | 品阶，对齐功法 level |
| `school` | 枚举 | 风/林/火/山/通用 |
| `desc` | string | 面向玩家的完整描述（图鉴/悬浮用） |
| `effects` | array | 效果词条列表，每条 = 时机 × 条件 × 动作 |

16 号的 `InternalSkillData` 占位 schema（passive_effects/qi_modifiers/status_modifiers）由本表取代：passive/timing 两类行为统一为 effects 词条，qi_modifiers 并入动作词表（`transfer_bonus` 等结算时修正）。

## 3. 效果词表（数据与代码的共同契约）

每条 effect：`{ on, phase?, when?, do }`。**白名单受控**——DataRepo 加载期校验，词表外数据 push_error。

### 3.1 时机（on＝管线动作类型）

| on | 相位默认 | 语义 |
|---|---|---|
| `battle_start` | post | 战斗开始（TurnManager.start_battle） |
| `breath` | post | 调息时点（D-063：该单位弃旧纳新之际；PRE 可改纳气量；毒发同锚） |
| `technique_prepare` | **pre** | 功法结算前（新点位，见 §6.1）——改本次传输内力的唯一窗口 |
| `technique_use` | post | 功法结算后（含本次真气/牌型/传输） |
| `damage` | pre | 伤害动作（PRE 可改 amount——加伤/减伤窗口） |
| `damage` | post | 伤害动作后（反震类） |
| `initiative_gain` | post | 获得行动权（移交/夺取结算后发给最终持有方） |
| `initiative_transfer` | **pre** | 行动权移交前（D-064 实际动作：取消＝连动保留、改写 target＝改道；调息/暂让后的取消被引擎铁律驳回） |
| `initiative_seize` | **pre** | 有人夺取行动权时（D-064 实际动作：取消＝免疫夺取） |

v1.1（D-063）：round_start 时点随大回合制废止退役，原回合类词条换锚 breath；round_gte→breath_gte、once_per_round→once_per_breath（以该单位调息计数换界，"每口气一次"）。

### 3.2 条件（when，全满足才触发）

| 键 | 语义 |
|---|---|
| `attribute_gte: {attribute, count}` | 动作关联真气中某系张数 ≥ count（technique 类/damage 带出招真气时可用） |
| `xinfa_school_gte: {school, count}` | 自身装备心法中某系门数 ≥ count（含本门——类断点效果的单门表达） |
| `pattern: "PAIR"` | 本次出招牌型含该牌型 |
| `transfer_gte: N` | 本次传输内力 ≥ N |
| `breath_gte: N` | 该单位调息次数 ≥ N |
| `as_attacker: true` | 动作来源是自己（damage 类） |
| `as_target: true` | 动作目标是自己（damage 类） |
| `once_per_breath: true` | 每口气限一次（该单位调息计数换界，运行时记账） |
| `once_per_battle: true` | 每场限一次（运行时记账） |

### 3.3 动作（do）

| type | 参数 | 语义 |
|---|---|---|
| `transfer_bonus` | `value` 或 `per_attribute`+`value` | 本次传输内力 +value；带 per_attribute 时按出招中该系真气张数 ×value（培元词条） |
| `damage_bonus` | `value` | 伤害动作 +value（需 as_attacker） |
| `damage_resist` | `value` | 伤害动作 −value（需 as_target；护境吸收前） |
| `reflect` | `value` | 受伤后对攻击者反震 value 点伤害（as_target，走 damage 点位） |
| `guard_bonus` | `value` | 护境 +value |
| `heal` | `value` | 气血回复 value（不超上限） |
| `draw` | `value` | 额外抽 value 张（超抽=真资源增益，定价从严） |
| `put_bottom_draw` | — | 换气：手牌中基础内力最低一张放回牌库底，再抽一张（调息词条；**v1 自动化**，纸面版自选口径见 C-031） |
| `apply_status` | `status, value, to` | 施加状态；to=opponent（出招目标）/self |
| `self_hp_loss` | `value` | 代价词条：失去 value 点气血（走 hp_loss 点位，护境不挡） |
| `seize_initiative` | — | 夺取行动权（D-064）：执行器**方法内**先判断对方是否同修本门心法（互抵写进方法，不立通用条件），通过才提交 initiative_seize 动作——该动作可被 PRE 取消（免疫夺取） |
| `cancel` | — | **通用取消本动作**（仅 pre 相位合法，DataRepo 校验）：免疫伤害/免疫夺取/保留行动权（取消移交）一词通吃 |
| `amount_bonus` | `value` | 通用数值改写（仅 pre 相位）：本动作 amount±value，如调息纳气 +1 |
| （留位）`slot_rule` | — | **心法发槽词条位**（太吾式"装备时功法槽±N/限系"）：v1 词表占位不出内容，D-061 后续版本可开 |

### 3.4 上下文契约

心法条件可依赖的动作上下文（管线保证写入）：

- `technique_prepare` / `technique_use`：`technique`（功法名）、`cards`（本次真气数组）、`transfer`（传输内力，prepare 后回写）；
- 功法产生的 `damage` 动作：`technique` + `cards`（TechniqueResolver 传入）；
- `battle_start` / `round_start`：`rng`。

## 4. 搭配系统（涌现层）

**不建独立子系统**。搭配 = 三个既有轴上的词条互指：

1. **真气属性轴**（本系统激活——此前属性字段不参与任何结算）：心法条件数出招真气的系别张数，牌库构筑产生"纯系稳 vs 混系活"的取舍；
2. **心法系别轴**：`xinfa_school_gte` 让 5 槽组合互认（凑三门火，第四门自己亮）；
3. **既有兵器轴**（C-026 不动）：功法 school × 兵器增幅照旧，与心法系正交。

据点构筑面板 = 搭配试验场：换装即见全部生效规则汇总。类断点、配方、发槽的**显式表一律不做**——它们要么以单门心法词条表达，要么不做（D-061）。

## 6. 实现规格（Godot）

### 6.1 战斗内核

- 新增 `core/battle/xinfa_runtime.gd`：战斗装配时把双方装备心法的 effects 注册成管线钩子（模板=StatusRuntime；载体="xinfa:名:fighter_id"）；`once_per_round/once_per_battle` 运行时记账，回合数取 CombatState。
- **新抽象点位 `technique_prepare`**：TechniqueResolver.resolve 在计算传输内力前提交；PRE 钩子可改 `context.transfer_modifier`，resolve 读回后结算——心法培元词条影响本次出招的唯一窗口（否则 technique_use 已是事后）。
- `FighterState.xinfa: Array[String]`；`EncounterLoader._build_fighter` 读取 def 的 `xinfa` 字段；`CombatState` 装配 XinfaRuntime（**敌我同规则**，D-055 敌人搭配由 enemies.json 可选 xinfa 字段落地）。
- 战报克制：心法触发不逐条弹行，合并为简短后缀（如"（疾风步）"）；构筑面板承担完整规则披露（01 号规则透明）。

### 6.2 局外与 UI

- `MetaArchive` v5：`learned_techniques/learned_xinfa`（已学清单）+ `loadout.techniques(≤4)/loadout.xinfa(≤5)`（构筑配置）；旧档免迁移直读默认（player.json）。
- 据点**构筑面板**（README 待做#2）：心法 5 槽 + 功法 4 位调整 + 真气牌库查看 + 生效规则汇总。
- 据点**参悟面板**：研读仓库 manual 类物品（心法篇/功法卷）→ 学会入清单，秘籍销毁（参悟即蚀）；已在学清单上的秘籍不可重复研读（白卷）。
- 备战页心法区落位（原"心法占位（未立项）"）；战斗内心法胶囊（24 号既有设计：小丑牌式竖排胶囊挂立绘外侧）。

### 6.3 校验（DataRepo）

xinfa.json 进 pack：tier 1~5、school 枚举、effects 的 on/phase/when/do 全在白名单、apply_status 引用存在、每门至少一条 effect、desc 非空；enemies/player 的 xinfa 引用存在；`xinfa_school_gte` 的 school 不校验"是否存在其他心法"（运行时读装备表）。

## 8. 开放问题（进《10》或后续版本）

- 心法品阶与获取节奏（掉落权重、研读成本）；
- `slot_rule`（发槽词条）开放时机；
- 选择型效果（纸面版调息诀自选换哪张）是否给玩家手动口径；
- 心法稀有度是否复用物品四档（common~legend）还是用品阶 1~5 单轨。
