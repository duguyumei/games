## 技术方向

## 核心模块

```text

BoardState             # 牌阵规则核心：地块大陆、双摞（牌堆/散落区）、容器、地点卡、行动力、警戒、力竭、to_dict/from_dict 序列化（已实现）
CombatState            # 双方气血、真气、招式和状态（已实现）

EffectPipeline         # 动作管线：PRE 拦截可改可挡 → RESOLVE 默认结算 → POST 触发入队（已实现）
StatusRuntime          # 状态载体运行时：按 statuses.json 把状态注册成管线钩子（已实现）
TechniqueResolver      # 功法合法性（含子集搜索）与效果结算（已实现，效果经管线流转）；功法 level 等级字段已定（D-044：按转化率/强度/代表性人工定级，UI 边框色，随 M7 落地）

容器掉落表              # 地点配置内：weights 稀有度权重或 table 物品池（已实现）
Persistence            # 仓库已落地（meta 存档 user://meta_save.json，撤离入库）；解锁和 NPC 状态（未实现）
UI                     # 只显示状态并发送操作请求（board.gd / battle.gd 薄 UI；探索场景组件在 ui/ 目录的场景文件，board.gd 只做编排与信号接线；战斗 UI 已定稿为 ui/ 设计画布：qi_orb 丹珠/qi_slot 镶孔/qi_slot_group 孔组/technique_card 功法卡/technique_bar 功法层/hand_bar 经脉手牌层/fighter_panel 战斗者面板/battle_stage 对战区，D-044+C-011，M7 实现）
```

## 关键解耦原则

- 卡牌、招式和兵器数据与显示节点分离。
- 战斗规则与动画表现分离。
- 牌阵与战斗均使用随机种子，支持整局复盘。
- 敌人行为策略不直接修改 UI。
- UI 不直接决定伤害、掉落或资源扣除。

## 被动存档（已实现）

- 无手动存档 UI，存档时机全部自动：探索开始、牌阵每个动作结算后、进入战斗前（检查点）、战斗结算后。
- 存档文件 `user://expedition_save.json`：`{version, player_hp, player_max_hp, board, terminal}`；`board` 为 `BoardState.to_dict` 的全部牌阵状态（seed、ap/ap_spent、alert_level、pursuers_spawned、qixi、hunt_count、hunt_queue、guardians_off、hunter、outcome、hero_site、site_deck、inventory、pouch、sites）。当前 version=7：v3 加物品 type/use 结构；v4 加镇物追杀状态（hunter 的 site 经 Vector2i 编解码）；v5 加贴身锦囊（pouch 与背包同构，格数 pouch_slots 在 meta 档）；v6（M4/C-026）加穿戴栏 equipped{weapon,armor,bag}——值为装备实例 {id,uid,dur}（行囊无 dur）或空字典；v7（C-028 明牌网格）site.stack/ground 合并为 **site.grid**（3 列卡牌网格，空字典＝洞、拿走留洞不回填），敌牌带 **alert/primed** 警戒字段，顶层加 **sneak_ap**（迷踪香静音窗）/ **battle_cell**＋**battle_enemy_first**（强退续战与偷袭先手）/ **chain_queue**（连坐待战网格位），hunter 加 **prox/cell/primed**（迫近与占格）。散落区/探查概念删除；容器内容物留在牌上（contents 条目带 **flipped**，容器弹窗逐张翻牌恢复 D-028 口径），ap 表配 **flip**（容器内翻牌 1/张）。旧版本档作废重开。
- 序列化纪律：逻辑在 `BoardState.to_dict/from_dict` 与 `RunState`（save_game / has_save / resume_from_save），`board.gd` 只在存档时机调用。
- Vector2i 无法直接进 JSON：sites 字典键编码 `"x,y"`，pos/links 编码 `[x, y]`；rng.state（uint64）按字符串存（JSON 数字是 double，会丢精度）。
- 终态规则：死亡/力竭/撤离时 `terminal: true`，不续玩、开新局覆盖；中途退出（未结算）启动时读最近非终态存档续玩；战斗中强退回到战前检查点（PvE 合法 SL）。
- rng.state 入档只作测试辅助，正常游玩不保证世界线一致；事件日志与稀有度缓存是瞬态，不入档。
- 据点 meta 存档 `user://meta_save.json`（`{version, warehouse, pouch_slots, uid_next, equipped, prep_cart, learned, loadout, silver, experience}`，与远征档分离，C-027 起 version=3、购物车修复起 version=4、心法系统起 version=5、账面资产起 version=6）：撤离成功背包＋锦囊入库（可叠物同 id 叠数量；装备实例带 uid 永不叠堆，无 uid 装备按参数包判别同样不并堆——老档防线），死亡/力竭只入锦囊（M3/C-024）；pouch_slots＝锦囊格数（局外升级制，初始 1 封顶 3，旧档带值直接沿用）；uid_next＝装备实例 uid 发号器（MetaArchive.next_uid，跨局唯一，BoardState.issue_uid 回调接线）；equipped＝**穿戴栏（C-027 跨局角色状态）**——撤离 set_equipped 原样带回（耐久照旧）、死亡/力竭 clear_equipped 散失，编解码复用 BoardCodec.read_equipped（int 归一）；prep_cart＝**备战购物车（v4 跨局角色状态，搜打撤档案逻辑）**——出发装配的背包/锦囊两列数组，ExpeditionPrep.setup 直接绑档案数组（增删即改档案、save_meta 即落盘），退出备战页/退出游戏/崩溃都不丢、重进原样恢复，出发 consume_cart 才清车（物资转入远征档，生死由结算决定；v1~v3 旧档免迁移直读，车为空）；
learned＝**已学清单（v5，D-060）**——{techniques[], xinfa[]}，研读秘籍习得（参悟即蚀，D-047；
重复研读＝白卷拒绝，参悟点系统后置）、learn_technique/learn_xinfa 直接入册；loadout＝**构筑配置（v5）**
——{techniques[]≤4, xinfa[]≤5}，据点「搭配·构筑」面板读写（set_loadout 校验：已学子集/去重/槽位上限），
ExpeditionSession.take_battle_context 随开战上下文下发、battle 场景压过 player.json 默认构筑；
旧档免迁移直读，缺省取 player.json 初始清单；
silver/experience＝**账面资产（v6，D-062）**——银两钱包（获取渠道随折银/商店后置，v1 恒 0，gain_silver 预留）
与历练积累（胜仗+2/撤离+3/研读+1，败北不计；只展示不消费，作用后置）。
- 开局流程（C-027）：据点「出发」→ 备战页（scenes/prep；核心逻辑 ExpeditionPrep——仓库⇄穿戴手动换装（即时提交 meta）、仓库整堆装载背包/锦囊购物车（**购物车与穿戴同为持续保存的角色档案**）、payload() 生成 {equipped,inventory,pouch} 深拷贝载荷、远征档落盘后 consume_cart 清车）→ start_run(seed, prep) 应用载荷；空 prep＝空手开局（**保底配发与仓库自动换穿已废除**）。弃局统一 abandon_run（全丢＋清穿戴＋弃档）；死亡/撤离后直接退出游戏由**终态开机补结算**兜底（autoload _ready 检测终态档→from_dict→settle→清档，防丢账与重复入库）。

## 数据对象占位

### TechniqueData

- id
- name
- weapon_type
- qi_pattern
- effects
- tags
- restrictions
- durability_cost

### XinfaData（已落地为 data/xinfa.json，D-060）

键=心法名（与 techniques.json 同规）。字段：

- tier（品阶 1~5，对齐功法 level）
- school（系别：风/林/火/山/通用）
- desc（玩家可读完整描述）
- effects[]（效果词条，每条 = 时机 × 条件 × 动作，白名单受控——DataRepo 加载期校验）
  - on：battle_start / round_start / technique_prepare / technique_use / damage
  - phase：pre / post（technique_prepare 默认 pre，其余默认 post）
  - when：attribute_gte / xinfa_school_gte / pattern / transfer_gte / round_gte / as_attacker / as_target / once_per_round / once_per_battle
  - do：transfer_bonus / damage_bonus / damage_resist / reflect / guard_bonus / heal / draw / put_bottom_draw / apply_status / self_hp_loss（"slot_rule" 槽位规则词条留位，v1 不出内容）

词表契约与语义详见《27》§3。运行时载体＝core/battle/xinfa_runtime.gd（XinfaRuntime：
装配时把双方装备心法注册成管线钩子，once 记账与内部回合钟在运行时）。

### StatusData（已落地为 data/statuses.json）

- name（显示名）
- scope（"battle" = 战斗结束按自身逻辑清除的临时标注；未标注的效果一律延续）
- on / phase / priority（挂点：动作类型、pre/post、触发顺序）
- action（发作时发出的动作类型：damage 可被护境挡 / hp_loss 失去气血绕开护境）
- amount（"stacks" = 按层数结算数值）
- decay（每次触发后递减层数）

载体不局限于状态：心法、装备、功法附加效果、场地等未来都以同一数据形态注册进管线。

## 动作点位目录

一切皆动作，每个动作都是一个点位。实际动作有默认结算（基本法），抽象动作是纯时点（无默认结算，供钩子使用）。已埋点位：

| 点位 | 类型 | 默认结算 |
|---|---|---|
| damage（受到伤害） | 实际 | 护境先挡、剩余扣气血 |
| hp_loss（失去气血） | 实际 | 绕开护境直接扣气血（毒发走这里） |
| heal（回气） | 实际 | 气血回复，不超上限 |
| status_apply | 实际 | 加状态层数并注册该状态钩子 |
| draw（抽牌） | 实际 | 抽 N 张，牌尽洗弃牌堆 |
| breath（调息） | 实际 | 弃全部手牌入气海，再从丹田纳 N 口（PRE 可改纳气量——心法调息词条挂点；世界钟 D-058 未来挂此，每次调息 −1 行动力；毒发与心法回合类词条在 POST 随本人调息结算） |
| pass（暂让） | 实际 | 不动手，顺从丹田纳 N 口（默认 1） |
| technique_prepare（功法凝招前） | 抽象 | 无（传输内力计算前发出；PRE 钩子可改 transfer_modifier——心法培元词条的唯一改写窗口，D-060） |
| technique_use（发动功法） | 抽象 | 无（resolve 结算成功后发出，带功法名/本次真气/传输内力/rng；功法生命周期 prepare→效果→use 统一在 TechniqueResolver.resolve 收口） |
| battle_start（战斗开始） | 抽象 | 无 |
| initiative_transfer（行动权移交） | 实际 | D-064：RESOLVE 按 action.target 指派 active_side 并向最终持有方发 initiative_gain；PRE 可取消＝连动保留（仅功法类动作后有效，调息/暂让后引擎强制移交）、可改写 target＝改道 |
| initiative_seize（夺取行动权） | 实际 | D-064：翻持有方＋发 gain＋战报（"获得行动权的特殊情况"）；PRE 可取消＝免疫夺取 |
| guard_set / guard_remove / guard_gain（护境覆盖/移除/增减） | 实际 | D-064：功法 guard_cover/remove_guard 与心法 guard_bonus 的管线化落点，PRE 可拦截（"护境被拦/未被撼动"） |
| initiative_gain（获得行动权） | 抽象 | 无（移交/夺取结算后发给最终持有方；战斗开始发给第一次行动权持有者——被开战夺取抢走时只发夺取方） |

round_start 点位已随大回合制废止退役（D-063）；毒发等原挂 round_start 的状态一律换锚 breath（只随本人调息发作）。initiative_release 点位与 retain 标记机制已随 D-064 纯化删除（保留行动权＝取消 initiative_transfer）。**钩子排序（§11.5）**：EffectPipeline.acting_side 标记当前持有方，双方钩子持有方先结算（同方内 priority 升序、注册稳定序），无 side 标记的钩子（状态等）排第二梯队。

新增点位 = 起名字 → 注册默认结算（实际动作）→ 在发生处 submit，钩子载体零改动。待扩：round_end、行动开始/结束、使用道具、气血归 0 前、战斗结束。

### ItemData（已落地为 data/items.json；结构与枚举详见《25》）

- id / name / type / rarity / value（value=售价，无买价）
- type：consumable / material / valuable / manual / weapon / armor / container / readable（DataRepo 校验按 type 分支；container＝行囊，M4）
- 消耗品专属：subtype（medicine / hidden_weapon / tool / provision / credential）＋ use{scopes, target, effects}
- 可选件：icon（缺省文字回退）/ max_stack（缺省 99）/ charges（出现即"耐久道具"，实例不叠堆——装备用）/ desc
- use.effects 的 kind 为受控枚举＝已实现执行器清单（heal / restore_ap / damage / apply_status / open_all_chests / evade_top_enemy）；探索域执行器在 BoardState.use_item（heal 经 heal_player 回调落 ExpeditionSession），战斗域执行器在 ItemEffects（直伤绕 guard、按减免打折）

### EnemyData（已落地为 data/enemies.json）

- max_hp / school / weapon_level（M4：敌我兵器系别与增幅等级；玩家侧由开战载荷 take_battle_context 的 weapon_school/weapon_level/armor_defend 覆盖，来自穿戴栏）
- techniques / ai_priority / deck
- tier（normal / veteran / elite / master，决定战斗行动力价格与道具直伤减免缺省表）
- item_damage_reduction（可选 0~1，覆写按档次的缺省减免：0% / 20% / 35% / 50%）
- loot_chest（遗体行囊档次，指向地点配置的容器表）

### LocationData（已落地为 data/location_qingfeng.json）

- name / entrance_type
- ap（行动力表：起始、移动、flip＝容器内翻牌；战斗 0、探查已删）
- pursuer_thresholds / pursuer_table（追兵阈值与敌人表）
- scatter_table（零散物品池）
- chests（容器表：ap_cost、draws、weights 稀有度权重或 table 物品池）
- continent（地块大陆：常规地点数量与类型池，预置生成）
- location_cards（地点卡表：effect 长新节点/捷径、site_type、require_item/consume、撤离卡数量与藏法）
- site_types（地点类型模板：cards 洗牌区 + bottom 沉底牌、extract 标记）

## 第一版禁止的技术复杂度

- 不先做联网同步。
- 不先做通用脚本语言让玩家无限组合效果。
- 不先做实时自由移动和复杂寻路。
- 不把每个招式写成互相复制的独立逻辑。
