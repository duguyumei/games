# 协作分工与审核流程

版本：v0.1  
状态：已确认流程

## 用户负责的事项

- 最终游戏愿景和审美方向。
- 选择纯武侠的题材边界。
- 判断核心体验是否符合预期。
- 决定哪些方案进入正式制作。
- 审核关键节点的冻结和变更。
- 试玩后的主观体验判断。
- 最终决定开发范围、平台和发布目标。

## AI负责的事项

- 将口头想法整理成结构化文档。
- 提供互斥方案、风险和返工影响。
- 设计规则初稿、数据结构和测试用例。
- 批量生成招式、敌人、地图和事件的初稿。
- 进行纸面模拟、数值检查和矛盾检查。
- 编写 Godot 原型代码和工具脚本。
- 根据反馈同步关联文档。
- 维护设计决策日志和版本变更记录。

## 共同审核的事项

- 核心循环是否好玩。
- 真气牌型与招式的关系。
- 敌人行为是否公平、确定和可读。
- 搜索、战斗、资源损耗和撤离是否形成闭环。
- 玩家是否能够主动追求目标流派。
- 失败损失是否有风险但不挫败。

## 文档审核流程

```text
AI 提交设计初稿
  → 标记已确认、待验证、待决策
  → 用户审阅并指出修改
  → AI 更新文档和关联影响
  → 纸面或 Godot 原型验证
  → 用户确认是否冻结
  → 写入设计决策日志
```

## 冻结规则

- “已确认”表示当前基线可以据此继续设计，不代表永远不能修改。
- “已冻结”只在原型验证通过后使用。
- 修改已冻结内容时，必须说明原因、证据、影响文档和预计返工范围。
- 没有测试证据时，AI不能把自己的假设写成最终规则。
